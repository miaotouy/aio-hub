# 容器元素语义与装饰样式对应规范 (Semantic Decoration Style Mapping)

本文档定义了项目中容器、卡片、列表项和信息块的视觉装饰规范，旨在统一治理“容器左侧单边粗描边高亮”在不同语义中的使用方式，降低高密度页面中的视觉噪音。

## 1. 核心原则

### 1.1 结构与状态分离

普通容器只表达结构，选中、告警、失败等状态通过独立的状态装饰表达。

- **结构**：1px 中性边框、背景层级、间距和分组标题；
- **交互**：2px 主色边线、背景变化或 focus outline；
- **内容语义**：3px 左侧线，仅用于引用和强语义内容；
- **分类**：Badge、图标、色点或标签；
- **严重度**：图标、状态文案、语义背景，必要时才增加色条。

### 1.2 一个视觉手段只承担一个主语义

左侧粗描边不应同时表示：当前选中、角色类型、错误等级、内容引用、普通信息块。
如果一个组件同时拥有多个状态，应优先使用组合方式表达，例如“选中背景 + 角色 Badge”，而不是继续叠加多条边线。

### 1.3 高密度列表优先使用低面积装饰

在日志、事件、消息和监控列表中，优先使用：

- 6px 左右的状态点；
- 图标；
- 小型 Badge / Tag；
- 标题颜色；
- 行背景的轻微色阶。
  **不建议**让列表中的每一行都拥有 3px 或 4px 的整高色条。

### 1.4 不能只依赖颜色

颜色应与图标、文字标签、形状或位置组合使用。角色、事件类型和严重度尤其不能仅通过红、黄、绿、蓝等颜色区分。

## 2. 语义与装饰样式映射表

| 语义              | 首选装饰                       | 次选装饰           | 左侧粗描边规则             |
| ----------------- | ------------------------------ | ------------------ | -------------------------- |
| 普通容器 / 分组   | 1px 全边框 + 背景层级          | 标题、分隔线、间距 | **禁止**                   |
| Hover             | 背景变化 + 边框颜色变化        | 轻微阴影           | **禁止新增**               |
| Selected / Active | 浅色背景 + 2px 主色左线        | 主色 outline       | 允许，仅交互态             |
| Focus             | `outline` / focus ring         | 外部阴影           | 不用左线                   |
| Info              | 信息图标 + 淡色背景            | 1px 语义边框       | 默认不用，必要时 2px       |
| Warning           | 警告图标 + 标签 + 淡色背景     | 语义边框           | 持久性告警才允许 2–3px     |
| Error             | 错误图标 + 操作建议 + 淡色背景 | 语义边框           | 阻断性错误允许 3px         |
| Success           | 成功图标 + 状态点 + 淡色背景   | 成功 Badge         | 不用粗左线                 |
| 消息角色          | 图标 + Role Badge              | 标题色 + 状态点    | **禁止**默认粗左线         |
| 事件 / 数据类型   | 状态点 + Type Badge            | 类型图标           | **禁止**默认粗左线         |
| 日志等级          | 图标 + 等级标签                | 行首状态点         | **禁止**每行使用粗左线     |
| 引用 / Blockquote | 低饱和 3px 左线 + 背景         | 引号图标           | 允许，专属语义             |
| Tool Call / Code  | 1px 边框 + 标题栏 + 折叠       | 状态点             | 仅运行中或失败时允许 2–3px |
| Drag / Resize     | 可视化手柄 + 光标              | active focus ring  | 容器最多 2px               |
| Disabled          | 降低对比度 + 虚线边框          | 禁用图标           | **禁止**彩色粗线           |

## 3. 宽度与颜色 Token 约束

### 3.1 宽度约束

|       宽度 | 允许用途                                         |
| ---------: | ------------------------------------------------ |
|        1px | 普通结构边框                                     |
|        2px | 选中、激活、拖拽、局部交互反馈                   |
|        3px | 引用、持久性告警、强语义内容                     |
|        4px | 仅兼容已有 Markdown / 富文本特殊样式，不建议新增 |
| 5px 及以上 | 不用于容器；仅允许 CSS 三角形等绘制技巧          |

### 3.2 颜色与主题自适应

- 优先使用项目主题变量，严禁在组件中直接写硬编码 Hex 颜色。
- 装饰线和背景色必须响应 [`theme-appearance.md`](./theme-appearance.md) 中的“界面质感（透明度/模糊）”设置。
- 在半透明/毛玻璃背景下，应使用 `color-mix` 或 `rgba` 配合全局透明度变量（如 `calc(var(--card-opacity) * 0.1)`）以保持通透感，避免使用实色。

---

## 4. 移动端极简主义约束 (Mobile Constraints)

由于移动端（[`mobile-protocols.md`](./mobile-protocols.md)）屏幕宽度极其珍贵：

- **容器左侧粗线一律禁止**，仅保留 Markdown 的 `blockquote` 和全局阻断性 `Error` 弹窗。
- 移动端的所有分类和状态一律改用**行首 6px 状态点**、**轻量级文字后缀**或**小 Badge**，以换取更多正文宽度，避免因左侧线和内边距叠加而挤压内容。

## 5. 工程落地避坑指南

### 5.1 性能优化：避免高频更新页面的重排 (Reflow)

在高频接收广播、动态插入卡片的监控页面（如 VCP Monitor）中，如果频繁通过类名切换 `border-left-width`（例如从 `0px` 变到 `2px`），会触发浏览器的布局重排。

- **解决方案**：容器的 `border-left` 宽度应保持固定（例如默认就是 `2px solid transparent`），激活时只改变 `border-left-color`。
- **高级方案**：使用 `::before` 绝对定位伪元素来绘制左侧线，并开启 `transform: scaleY()` 动画，这样可以完全避开布局计算，直接交由 GPU 渲染。

### 5.2 拖拽手柄 (Drag / Resize) 的易用性

在拖拽和调整尺寸时，如果物理交互热区过窄，在高分辨率屏幕下鼠标极难精准悬停。

- **解决方案**：采用“视觉与交互热区分离”技术。手柄的物理交互热区（`width`）设为 `8px` 或 `10px`（方便鼠标悬停），但内部的视觉高亮线（通过 `::after` 绘制）保持 `2px` 或 `4px`。

## 6. 新增样式的决策树

新增容器装饰前按以下顺序判断：

```text
这是普通分组吗？
├─ 是 → 1px 全边框 + 背景层级
└─ 否
   这是选中或激活态吗？
   ├─ 是 → 2px 主色左线 + 浅色背景
   └─ 否
      这是引用或正文语义块吗？
      ├─ 是 → 3px 低饱和左线
      └─ 否
         这是告警或错误吗？
         ├─ 是 → 图标 + 语义背景 + 1px 边框
         │        阻断性或持久性告警才增加 2–3px 左线
         └─ 否
            这是角色、类型或日志分类吗？
            ├─ 是 → Badge + 图标 + 状态点
            └─ 否 → 不使用左侧粗描边
```
