# 桌面应用内存用量测试：真实会话与外观配置

## 目标与当前入口

定位首页、空聊天、复杂聊天在不同主题和材质配置下的进程内存、页面堆与 GPU 内存开销，并观察进入、滚动、展开内容、返回首页后的保留量。

现有 `scripts/perf/run.ts` 继续承担玻璃材质滚动对比；新增入口负责整应用内存：

```powershell
bun run perf:memory:corpus -- --source <应用数据根目录>\llm-chat --out .tmp/app-memory/corpus.json
bun run perf:memory -- --corpus .tmp/app-memory/corpus.json --list
bun run perf:memory -- --help
```

当前自动化覆盖：独立进程启动、首页基线、指定会话载入、静置、当前已挂载推理/工具面板展开、往返滚动、返回首页冷却、同一会话重复进入、末次页面 GC 诊断。运行时使用真实 Tauri 窗口与独立 WebView2 profile。

树视图、分支切换、图片查看器、主题热切换和流式生成属于下文的专项交互设计，后续按问题选择实施。

### 样本处理边界

- 新提取默认 `--text-mode readable`：保留可读正文、推理、译文和常规代码标识符，定向处理常见凭据、联系方式、本机路径；资源地址另行重建。可读正文仍可能有私人语境，仅限本机，分享前需人工审阅。
- 可读模式支持 `--replacements .tmp/app-memory/entity-replacements.local.json`，使用人工抽查后的字面替换表统一处理网名、同一人的多种账号写法、角色名和特定设定名。替换表与语料一起留在本机忽略目录，日志只记录规则数量。优先使用等长、同字种的自然化名，保留代码标识符、VCP 标记和 Markdown 结构。
- 旧版 `masked` 使用独立密钥按词替换，保留用于原结构负载复查；随机替换破坏部分 VCP 识别、改变实际 DOM。旧结果继续保留，与可读模式分开比较，语料模式写入 manifest。
- 重建会话、节点、工具请求和资产身份，保留父子关系、活动叶节点、工具请求关联、启用状态和压缩关联。
- 元数据按展示字段白名单重建。供应商请求快照、连接配置、撤销历史、身份数据与执行状态留在原目录。
- 处理脚本、样式、iframe 等活动 HTML，只保留常见静态结构。复杂 HTML 卡片的 CSS、脚本和交互成本需要专项受控样本补充；本次回放统计会显示处理前后的体积差异。
- 同源图片引用复用同一匿名资源身份。内嵌 PNG 读取头部尺寸；HTML 中声明的宽高记为尺寸提示；其余图片使用 640×480 的本地测试图。原附件图片按已有尺寸元数据重建，尺寸限制在 4,096 像素内。
- 图片重建保留资源引用关系，图像压缩率和原始像素内容发生变化。`imageDimensions` 明确记录已知尺寸、HTML 提示和回退资源数量；媒体组结果用于重建负载对照，原会话的绝对图片内存需后续补齐原始尺寸。
- 音视频当前使用文档卡代替。播放器解码、波形、视频缩略图和原始二进制体积另设专项。
- 回放保留原始会话索引数量，以匿名轻量条目填充。归档正文只物化当前案例目标，首页与空会话同样承载这个规模的索引。

提取器只读取指定索引与索引中的会话 JSON，跳过超过默认 64 MiB 的单文件并计入 `skipped`。所有 corpus、图片、隔离数据和运行产物写入 Git 已忽略的 `.tmp/` 或 `.dev-data/`，报告只展示结构和测量数据。

```json
  "pine7": "reed8",

```

```powershell
bun run perf:memory:corpus -- --source <应用数据根目录>\llm-chat --text-mode readable --replacements .tmp/app-memory/entity-replacements.local.json --out .tmp/app-memory/corpus-readable-entities.json
```

按最长原词优先、单次字面匹配执行；同一人的中文名与账号需分别列入替换表。正文、推理、译文和工具展示参数共用这张表，大小写变体显式列出。单字称呼使用带上下文的规则（如发言人标签、@ 提及），减少对普通句子的影响。替换后的语料另存，已测文件继续保留；后续对比固定使用同一份新语料。人工抽查只能覆盖已识别的指代，可读语料仍限本机使用。

### 完整 UI 材质矩阵：38 个配置

以下四个维度笛卡尔积共 36 个配置，另加浅色和深色的特效关闭基线：

| 维度            | 取值                                                    |
| --------------- | ------------------------------------------------------- |

### Windows 窗口材质：独立 12 个配置

`--suite native`：2 种主题 × `none / mica / acrylic` × 窗口不透明度 `1.0 / 0.7`。UI 层固定壁纸开启、基础不透明度 0.75、模糊 15 px。

OS 合成器效果受 Windows 版本、驱动与桌面状态影响。当前 runner 保存请求配置、系统版本、实际 CSS 状态及可选截图；Mica/Acrylic 的原生生效状态需真实窗口走查确认。GPU 进程计数覆盖应用侧资源，桌面合成器的共享成本单独分析。

### 案例总量与执行顺序

当前 8 份真实样本加首页、空会话，共 10 类页面：

- 默认 quick 页集：`home,empty,rich-text,tools`，8 配置，共 32 个独立进程案例。
- quick 全页集：80 个案例。
- full 全页集：380 个案例；3 个独立重复轮次共 1,140 次启动。

## 3. 每个案例的采样流程

每个“页面 × 配置 × 独立轮次”使用新的应用数据目录和 WebView2 profile。基线与回放都在同一进程树内采样；案例之间重启，避免前一个配置的 GPU/会话缓存混入。

| 阶段          | 默认时长             | 动作与记录                                                 |
| ------------- | -------------------- | ---------------------------------------------------------- |
| 启动          | 等待页面就绪         | 启动后立即开始 OS 采样；首页就绪前的样本保存在原始时间序列 |
| `home`        | 预热 8 s + 测量 12 s | 首页基线，含同规模匿名会话索引                             |
| `enter`       | 至少 12 s            | 通过页面链接进入 Chat、点击目标会话，覆盖载入峰值          |
| `idle`        | 稳定 8 s + 测量 12 s | 当前活动路径自然静置                                       |
| `expanded`    | 12 s，存在面板时执行 | 展开当前已挂载的推理与工具结果；保留折叠态与展开态测量     |
| `scroll`      | 12 s，可滚动时执行   | CDP 滚轮驱动列表往返滚动，不操作系统鼠标                   |
| `return-home` | 15 s                 | 通过真实导航返回首页，记录冷却后的保留量                   |
| 重复往返      | 默认 3 次            | 对同一会话重复载入、浏览、返回，观察首次缓存后是否趋于平台 |
| `after-gc`    | GC 后测量 12 s       | 仅在案例结束时执行页面 GC，辅助分析页面堆保留              |

整个自然使用序列采用浏览器正常 GC。末次强制 GC 只针对页面，Worker 与 GPU 的回收时机仍由运行时决定。首页独立案例直接测基线与末次 GC。

### 指标口径

1. **进程树私有提交量**：应用根进程与 WebView2 全部子孙进程的 Private Bytes 之和，记录峰值和阶段最后 5 秒中位数。
2. **进程树工作集**：同一进程集合的 WS 合计。共享页可能被重复统计，不能将它直接解释为独占物理内存。
3. **按进程类别拆分**：Rust/native、WebView browser、renderer、GPU、utility 的阶段尾值。结果只保存类别、PID 和内存，省略命令行。
4. **GPU 专用/共享用量**：按这棵进程树的 PID 汇总 Windows GPU Process Memory 计数。查询不可用时显示 `—`。
5. **页面 JS Heap / embedder / backing storage**：页面 CDP 数据，帮助区分 JS 与外部存储；报告明确标为页面数据。
6. **DOM、document、事件监听器数量**：配合页面往返观察保留增长。
7. **实际运行状态**：视口、DPR、可见性、实际 CSS 模糊/壁纸值、消息/工具/推理面板数量、图片数量、已解码图片数量，以及图表和图片错误数量。

OS 采样目标间隔为 1 秒，CIM 查询耗时可能导致间隔拉长。每个阶段至少 3 个样本、最后 5 秒至少 2 个样本，且观察到 WebView2，才标记为有效；不足时保留结果并标为稀疏。采样峰值是观测下界，短暂峰值可使用专项追踪工具补充。

原始采样贯穿整个案例。JSON 保存样本和阶段时间边界，Markdown 汇总每阶段值、独立轮次的中位数/范围，以及每次返回首页相对首次首页的 Private/Heap 增量。单轮增量与缓存增长结合观察，持续增长的对象再定位到 Worker、资产缓存、渲染器或 GPU 路径。

## 5. 运行与产物

release 采样使用 `perf-instrumentation` 构建：

```powershell
bun run build:perf

# 先做一个首页/空会话的最小试跑，确认构建和窗口控制可用。
bun run perf:memory -- --corpus .tmp/app-memory/corpus.json --binary src-tauri/target/release/aiohub.exe --pages home,empty --configs light-effects-off --cycles 1

# 看同一复杂样本在全部 quick 配置下的差异。
bun run perf:memory -- --corpus .tmp/app-memory/corpus.json --binary src-tauri/target/release/aiohub.exe --pages branches --rounds 3 --screenshots

# 完整矩阵先预览，再挑具体配置执行。
bun run perf:memory -- --corpus .tmp/app-memory/corpus.json --suite full --pages all --list
```

`--binary` 需指向本次构建实际生成的文件。普通 release 通常关闭 CDP，无法用于这个 runner。debug 适合检查驱动流程，正式比较使用同一编译通道、前端资源和 WebView2 版本。

产物默认写入新建的 `.tmp/app-memory/run-<时间>/`：

- `manifest.json`：主机、运行时输入、可复现的 corpus / binary 身份、案例矩阵和参数。
- `<case>.json`：已完成阶段、原始 OS 样本、页面检查点、重建资源统计和失败操作。
- `report.md`：可读汇总与返回首页保留量。
- `<case>.png`：显式传入 `--screenshots` 时保存真实 WebView 视口。

每个案例完成或失败都会保存已有结果。测后清理本案例的隔离数据，`--keep-data` 可保留复查；清理前校验实际路径位于本次结果目录内。Ctrl+C/SIGTERM 只结束本次创建的应用进程树。已有用户窗口、真实会话目录保持原样。

### 本次验证状态

已完成真实数据结构盘点、8 组本地处理样本、380 案例矩阵预览、脚本类型检查、相关单元测试和性能构建（含前端类型检查、Vite 生产构建、Rust release）。
