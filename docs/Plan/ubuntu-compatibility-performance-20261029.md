# Ubuntu / WebKitGTK 兼容性与性能初测

日期：2026-10-29。环境为本机 Ubuntu 24.04.4 VM（4 vCPU、16 GB RAM、Wayland、WebKitGTK 2.52.3），源码基于 `a74aa3ae1`，另含 CSP 修复与本轮控制 / 测量脚手架。环境准备见 [Ubuntu 虚拟机兼容性验证](../guide/ubuntu-vm-compatibility.md)。

## 1. 测量入口与范围

`rich-text:performance:tauri` 已按实例传输复用页内渲染探针：Windows 保留 CDP，Linux 使用嵌入式 WebDriver。输入投递、组件提交、rAF、最终 AST 校验沿用同一代码。Linux 通过已有生产资源 Debug 实例运行：

```bash
bun run rich-text:performance:tauri -- --instance ubuntu-probe --cycles 2 --sizes 10 --filter '^(prose|code):' --out-dir .tmp/ubuntu-performance/current-10k
```

本轮 WebKit 缺少 Long Tasks 与 CDP 指标。报告显式保存能力信息，长任务汇总为 `null` / “—”，CDP 指标为空；帧和提交时序继续采集。Debug、VM 与引擎差异均会影响绝对耗时，结果用于本环境内对照。

## 2. 当前版本的真实 Renderer

10 KiB 生成文本与代码各运行 2 轮，每轮含 static / stream，共 8 次；最终 AST 均匹配，探针采集的运行异常为空。流式输入为 256 字符一块、20 ms 计划间隔，页内按绝对时间投递。

| 输入与模式  | 首个内容帧 ms（两轮） | 完成信号到校验后绘制机会的上界 ms | 帧间隔 P95 ms |
| ----------- | --------------------- | --------------------------------- | ------------- |
| 文本 static | 96 / 89               | 静态总耗时 145 / 138              | 71 / 71       |
| 文本 stream | 45 / 36               | 114 / 103                         | 17 / 18       |
| 代码 static | 446 / 505             | 静态总耗时 488 / 553              | 410 / 429     |
| 代码 stream | 125 / 105             | 234 / 103                         | 40 / 51       |

代码样本结束时可见编辑器计数为 5。时序包含渲染与校验边界，完整定义沿用脚本的报告说明。这里仅测了当前版本，界面收益还需前后版本的同口径回放。

产物：Ubuntu 原生检出的 `.tmp/ubuntu-performance/current-10k/report.json`、`summary.md` 与各次截图。

## 3. 最近一次 VCP 预检优化的同引擎对照

比较 `9549deee8` 与 `a74aa3ae1` 的 Tokenizer：从 Git 归档历史源码，分别打成浏览器模块，放入同一真实 WebKitGTK 页面。该对照未替换工作区业务源码。语料全部生成，覆盖缺失字段标记、完整标准字段、pending 字段和普通文本。

每 512 字符取一个前缀，四组共 131 个前缀；完整 token 的 JSON 表达前后一致。每组热身后按交替顺序采样 7 轮，每次批处理至少约 30 ms，再按实际批次数归一为一遍全部前缀的累计时间，以降低 WebKit 时钟粒度影响。

| 合成输入                             | 旧版中位数 ms | 当前中位数 ms | 观察                                                   |
| ------------------------------------ | ------------: | ------------: | ------------------------------------------------------ |
| 缺少字段标记的 VCP 正文，17,046 字符 |        40.000 |         0.090 | 失败扫描压力场景显著降低；该构造偏向优化命中的极端路径 |
| 完整标准字段与长值，18,279 字符      |        15.500 |         6.600 | 累计时间约降低 57%                                     |
| pending 字段，16,829 字符            |        13.333 |         0.612 | 合成输入累计时间显著降低                               |
| 普通文本控制组，14,000 字符          |         6.400 |         9.250 | 首轮出现反向变化，追加一次独立复核                     |

控制组在新文档、20 遍热身、15 轮交替采样后为 4.375 → 4.000 ms，方向发生变化，当前证据未显示稳定的控制组回归或收益。保留两次原始数据，后续长会话测量继续检查 JIT、GC 与调度影响。

这组结果支持 VCP 必要标记预检在 WebKit 中也能减少对应失败扫描。它只覆盖分词计算；Worker 往返、传输、DOM 更新、内存驻留和完整聊天体验需要各自测量。

产物：`.tmp/ubuntu-performance/tokenizer-compare.json`、`tokenizer-control-repeat.json`。临时复现脚本在 `.tmp/ubuntu-compat/`，归档源码位于既有 bench 的临时目录。

## 4. 控制脚手架的真实窗口验证

- 独立实例启动、状态、停止、重启与原生身份核验通过，开发桥已连接。
- 宿主机通过 SSH 执行批处理，跳转设置、读取结构与回传 PNG 通过。
- 临时按钮被覆盖时返回 `TARGET_OBSCURED`，移除覆盖层后只触发一次点击。
- 320 × 160 局部截图尺寸正确；Pillow 核对敏感区域中心为黑色，旁边的青色控制区域保持原色。
- 960 × 720 窗口请求仍未改变 1280 × 768 视口，返回 `WINDOW_RESIZE_UNCONFIRMED`。

相关类型检查、Dev Control 回归用例、性能计时契约、前端类型检查、Vite 与原生 Debug 构建均已执行；具体命令入口见开发控制指南。当前正式运行通道已能支持下一轮主线性能探查。
