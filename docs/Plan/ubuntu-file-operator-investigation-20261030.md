# Ubuntu Agent 文件操作器专项调查（2026-10-30）

## 验证入口

在 Ubuntu VM 的普通用户会话中，使用生产前端资源的 Debug Tauri 实例执行测试。通过 Dev Control 进入本地文件操作器，加载应用已经注册的工具实例，将合成 `ParsedToolRequest` 交给真实 `executeToolRequests()`；随后由工具动作层调用真实 Rust IPC，并从磁盘回读结果。

审批确认与取消由执行器的 `onBeforeExecute` 回调驱动，验证强制审批是否触发及拒绝后的磁盘状态。聊天界面的审批条交互和在线模型请求属于后续端到端范围。

所有文件样例位于 `/tmp/aio-agent-files-*`，包含独立的白名单、外部目录、死区和审批区。测试结束恢复工具配置与主题。VM 原有源码改动通过显式文件清单和摘要保护保留。

## 发现与处理

| 问题                       | 修复前证据                                                         | 处理                                                                                 |
| -------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 符号链接后接父路径越界     | `safe/jump/../secret.txt` 被判定在白名单内，实际读取到外部样例内容 | Rust 逐段解析路径，先跟随链接，再处理后续 `..`；新建文件也沿用真实祖先               |
| Unix 字面反斜杠混淆目录    | 白名单 `alias\safe` 错误允许读取另一个目录 `alias/safe`            | 仅 Windows 路径转换反斜杠；Unix 保留字面文件名与大小写                               |
| 双路径审批过早返回         | 源在审批区、目标在死区时先请求审批，随后动作层才报拒绝             | 汇总全部路径判定，死区优先；该例修复前已有动作层拦截，磁盘未发生越界修改             |
| 递归复制跟随外部链接       | 复制允许的源目录，将内部链接指向的外部文件内容复制进结果           | 目录流转前检查整棵源树、映射目标及待覆盖目标树；复制/移动遇到链接返回明确错误        |
| 目录枚举遗漏子规则         | 搜索白名单根目录时返回死区内文件名、路径和大小                     | Rust 在枚举和递归进入子目录前应用规则，跳过死区、白名单外路径及待审批子目录          |
| 外部传输规则优先级分叉     | Rust 原逻辑按最深规则判定，子审批区可覆盖父死区                    | 外部原始文件传输采用死区优先，覆盖规则两种排列顺序的回归用例                         |
| 精确 Diff 删除邻接行       | 对 CRLF 文本搜索 `beta\n` 时，下一行 `gamma` 消失                  | 精确命中按字符偏移替换，保留匹配范围外的行与行内前后缀                               |
| 自动重命名与覆盖别名边界   | 原实现只验证最初写入路径，流转的同源判断使用路径拼写               | 自动重命名后重新检查最终路径；流转按真实路径拒绝同源别名、自身后代及包含源的覆盖目标 |
| 原生权限错误被概括文案替代 | Rust 返回字符串错误时，操作结果仅显示“写入文件失败”                | 保留并截断原生字符串错误，真实只读目录返回 `os error 13`                             |

安全规则目录解析失败时改为阻断操作，便于发现无效路径、断链或系统访问权限问题。

## 最终验证

### Agent 方法与真实磁盘

全部 12 个方法均经过执行器和原生 IPC：

- `read_file`、`write_file`、`append_file`、`apply_diff`
- `create_directory`、`list_directory`、`search_files`、`path_exists`
- `copy_file`、`move_file`、`delete_file`、`get_file_info`

20 组实机场景通过，检查包含：

- 中文、空格、引号、特殊符号、隐藏目录、Unix 字面反斜杠；写入、追加、Diff 和回读内容一致。
- 普通审批确认与拒绝；目录内审批规则要求整次复制/删除确认，拒绝时保留原样。
- 白名单外路径、同名前缀目录、大小写不同目录、符号链接及链接后接 `..` 均受限。
- 双路径死区优先、嵌套死区、待覆盖目标中的死区，在创建或删除目标之前拦截。
- 列表和递归搜索过滤受保护子目录；普通用户只读目录继续受系统权限约束。
- 自动重命名保留原文件，候选路径中的悬空外部链接被拒绝；外部目标保持未创建。
- 外部传输的父死区/子审批区两种排列均拒绝；原生流转直接调用也拒绝同源链接别名覆盖。

操作审计区域可以看到动作结果和安全配置变更。浅色、深色界面均保留完整配置与日志工作区，1440×900 视口无页面横向溢出。Dev Control 页面诊断为空。

## 运行边界与继续跟踪

- 文件操作器通过受信任前端执行器落实审批；配置快照用于目录命令的二次检查。通用 IPC 的其他调用方仍拥有原有能力，OS 沙箱需单独设计。
- 文件系统路径检查与实际操作间存在并发替换竞态；当前实现面向本机受信任工作区，进一步对抗恶意本地进程需要句柄相对操作等机制。
- 复制/移动包含符号链接的目录时要求单独处理链接；未来可按明确的保留链接语义扩展。
- 写入和追加继续遵循底层命令现有的扩展名限制；Office/PDF 解析和 VCP 远端协议会话分别按各自测试范围跟踪。

实机脚本、断言结果、构建日志和浅深色截图保存在已忽略的 `.tmp/ubuntu-file-operator/`。实现入口与调用约束同步到[文件操作器架构](../../src/tools/aio-file-operator/ARCHITECTURE.md)。
