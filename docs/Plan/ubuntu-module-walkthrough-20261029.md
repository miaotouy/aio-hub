# Ubuntu 各模块界面与交互走查

日期：2026-10-29

## 环境与范围

基于 `b098de634`，使用 Ubuntu 24.04 / Wayland / WebKitGTK 2.52.3 的生产资源 Debug 构建，通过项目 Dev Control 的 embedded WebDriver 操作。`ubuntu-matrix` 使用独立数据目录，沿用脱敏会话与合成图片；本轮本地文件样例位于 `.tmp/ubuntu-modules/`。

首轮遍历 46 个已注册工具、主页、扩展管理和 11 个设置页，共 59 个页面状态。检查真实截图、主要工具栏、空数据状态和可见反馈，随后补充页签、表单与本地功能操作。默认视口 1440×900；数据筛选页另以实际 1100×760 窗口检查布局。深色补查包含编辑器、画板、系统监控、Git、FFmpeg、媒体生成、思绪、知识库与设置。

首轮页面均能打开，未出现白屏和页面级横向溢出。系统脉搏初访先等待采样，随后显示 CPU、内存、磁盘与网络数据。进一步操作发现下述功能问题。

## 已修复：差异编辑后的页面文本未更新

打开文本差异对比并分别编辑左右文本后，点击“交换”没有效果。实际 Monaco 模型已经更新，页面的 `original` / `modified` props 仍为空。

当前 `@guolao/vue-monaco-editor` Diff 包装层接收文本 props，但没有转发组件所监听的 Vue 更新事件。页面持有的文本落后于编辑器画面，交换失效；复制、保存和补丁生成也使用这份旧状态，存在读取空内容或旧文本的风险。

本轮让 `RichCodeEditor` 直接订阅左右 Monaco 编辑器的内容变更，分别发出 `update:original` / `update:modified`。父级替换文本时按当前 props 避免重复回写，替换实例和卸载前清理订阅。

新增两个组件契约测试，保护编辑回写、父级替换，以及旧实例和卸载后的事件隔离。两项在旧组件上均失败，修复后通过。重建 Ubuntu 原生应用后，在浅色与深色下分别修改真实 Monaco 模型，再经界面切换内联/并排、交换两侧；交换后的文本和一处差异均符合预期。

## 发现与后续处理结果

### 已修复 P1：Web Canvas 新建项目失败

在独立数据目录中，新建“空白 HTML”画布，填写项目名称并点击“创建”，弹窗保持打开，列表仍为空。页面反馈：

```text
[Canvas/GitService] 初始化版本控制失败
Attempted to assign to readonly property.
[Canvas/Store] 创建画布失败
Git 初始化失败
```

两次实际创建均复现。后续探针在 Git 添加 `caller` 的位置保留了原始字符串：Tauri 拒绝 `stat` 画布内的 `.git/config`。当前独立数据根目录依赖运行时动态 scope，该 scope 在 Unix 默认要求显式匹配隐藏路径；已有配置中的 `requireLiteralLeadingDot: false` 作用于 capability scope，未能让这条动态授权覆盖嵌套的 `.git`。

为 `**/canvases/projects/**` 补充 capability scope，覆盖项目隐藏文件，沿用原有 deny。Git 适配层统一把 Tauri 字符串拒绝值转换成可写的标准 Error，保留原因与 ENOENT；`lstat` 改用真实文件自身的信息。

重新构建后，新建空白 HTML、编辑 Monaco 内容、点击 Commit All、打开独立预览均通过。磁盘 Git 日志确认初始提交与编辑提交，已跟踪文件状态干净；预览截图实际显示修改后的 HTML。

### 已修复 P2：图片色彩分析产出非法 HEX

上传 64×64 PNG，左半纯红、右半纯蓝，默认主色调数量为 8。图片加载与分析完成后，`currentAnalysisResult.quantize.colors` 包含：

```text
#0404fc  #fc0404  #3c04100  #bc0484  #1000404
```

其中两项有七位十六进制数字，无法作为合法 CSS 颜色显示或复制使用。依赖在稀疏图像的空量化桶中可能返回通道值 256，直接拼接 HEX 形成非法结果。

已显式请求 RGB 数组，过滤非有限值与越界通道，经统一 RGB 转换输出六位 HEX，并保留有效黑色。RGB 转换补充小数取整。项目声明与依赖当前的 options、默认 HEX、空主色返回值同步；依赖 exports 尚未正确暴露自带声明，继续保留本地类型桥接。

原生窗口重传同一双色图，输出 `#0404FC #FC0404 #BC0484`，三个色块均可显示。**剩余质量问题**：库仍返回一项原图中没有的合法近似色；本次解决非法色值，量化色板的代表性留待专项改进。

### 已修复 P2：Windows 专属原生能力缺少 Linux 状态说明

- **窗口自动化**：可以创建方案并进入编辑页，目标窗口刷新失败，列表为空。实际 IPC 返回 `Command wa_get_windows not found`；Rust 命令仅在 Windows 注册。页面反馈停留在获取窗口失败。
- **实时字幕 OCR**：屏幕工作区展示监控入口和默认 Windows Native OCR。实际 IPC 返回 `Command capture_screen_rect not found`，截屏命令同样仅在 Windows 注册。本地视频页可以打开，识别链路待准备引擎与素材。

已通过统一平台能力查询显示支持范围。Linux/macOS 禁用窗口选择、刷新及屏幕采集入口，绑定查询、方案执行、打开监控框与启动采集也在业务入口阻止无效原生调用。屏幕工作区跳过 OCR 预热。原生复测可新建并进入方案编辑，窗口选择/刷新均禁用；屏幕三个采集按钮禁用，本地视频工作区仍可切换。Windows 路径的原生查询契约由相关单测保护，真实 Windows 窗口执行仍待专项复测。

### 体验问题与环境因素

- **壁纸探测**：GNOME 返回 `/usr/share/backgrounds/gnome/adwaita-l.jpg`，本机文件缺失，原生资产协议确认 `File does not exist`。原提示“此格式暂不支持预览”已改为加载失败反馈，并在图片失败时检查文件存在性。本机复测显示“壁纸文件已不存在，请在系统设置中重新选择壁纸”。系统壁纸配置与实际文件脱节属于本机环境因素。
- **FFmpeg**：Ubuntu 工作台与序列帧合成的命令复制入口固定为 PowerShell。依赖检测成功；转码执行与各 shell 转义待专门验证。
