# Ubuntu 权限专项调查（2026-10-29）

## 范围与方法

在普通用户 `mty` 的真实 Tauri / WebKitGTK 实例中，用本次生成的临时文件、隐藏目录、符号链接和最小 Sidecar ZIP 对照验证。测试保持普通用户权限，操作范围限于新建的测试数据。

权限按层定位：操作系统文件权限、Tauri FS command 与路径 scope、asset scope、页面 CSP、子进程执行位、桌面会话能力。各层返回的拒绝分别保留，避免用一个“权限不足”掩盖原因。

## 已确认问题与修复

### 1. 应用数据根目录的动态授权漏掉隐藏后代

修复前，隔离数据目录中的普通文件可以 `stat/lstat/rename`；同级 `.hidden/fixture.txt` 的 `stat/lstat/remove` 被 FS 插件拒绝。读取同一文件却成功。这会影响 Git 之外的隐藏缓存、临时目录与迁移清理。

当前锁定的 `tauri-plugin-fs 2.5.1` 在构造动态 scope 时使用 `FsScope::default()`；Unix 默认要求显式匹配点目录。`plugins.fs.requireLiteralLeadingDot: false` 参与 capability scope 的构造，未改变该动态 scope 的匹配选项。此前给 `**/canvases/projects/**` 加全局 scope 只覆盖画布路径，并且会同时授权磁盘上其他同名目录。

启动时新增仅针对**实际应用数据根目录及其后代**的运行时 capability，复用当前所有本地窗口的权限模式。Unix 后端根目录与前端缓存的 `getAppConfigDir()` 统一返回真实路径，确保已有文件和未创建目标采用一致的根目录。Capability 对 glob 元字符转义，移除按目录名称全盘匹配的画布特例，保留既有 deny 与 asset scope。动态 FS 授权失败会返回启动错误，替代忽略错误后记录成功。

特殊路径探针还查明：直接把符号链接别名加入 capability，Tauri 会自动添加 canonicalize 后的 pattern，并把目标目录中的 `[ ] * ?` 重新当作 glob 解释，导致同级目录误获授权。因此 capability 只写入转义后的真实根目录；应用路径接口负责先消除目录别名。

### 2. 外部文件能读内容，却不能获取元数据

修复前，普通外部文件、隐藏文件与符号链接均可读取内容和查询 exists，`stat/lstat` 却返回 command scope 拒绝。当前 capability 原本已允许全路径读写和枚举；本次为 `stat/lstat` 添加相同的只读元数据范围，保持行为一致。

删除、移动与复制的外部授权策略保持原样。本次验证中，未通过对话框授权的 `/tmp` 文件，其 FS 插件删除和重命名继续被拒绝。该结果只描述 FS 插件边界；应用的自定义 Rust 文件命令需要按各自的安全契约评估。

### 3. ZIP 安装丢失 Unix 执行位

真实 ZIP 条目包含 `0755`，安装后的 Sidecar 文件却为 `0664`，启动返回 `os error 13`。Windows 上创建的 ZIP 也可能缺少 Unix mode 字段。

安装器现在流式解压文件：普通数据设为 `0644`；ZIP 声明可执行的文件及 manifest 当前平台的 Sidecar 入口设为 `0755`。只恢复执行意图，清除 setuid、setgid、sticky 与组/其他用户写入位。权限修复限定在安装目标，开发源码和其他运行路径维持原权限。

### 4. 插件安装与卸载的目录边界

原卸载入口接受空 ID 与 `.`，可将目标解析为整个插件根目录；该风险由源码确认，未在旧版本执行破坏性调用。本次统一安装、预检与卸载的 ID 校验，拒绝空值、路径分隔符、盘符、控制字符及 Windows 尾部点/空格别名。

原解压逻辑的 `starts_with(install_dir)` 采用词法路径比较，无法防住 ZIP 的 `..` 穿越。本次在创建安装目录前检查所有成员，拒绝绝对路径、目录穿越、Windows 路径别名与 NTFS ADS，以及符号链接条目。实际提取沿用同一归档句柄并再次解析相对路径，统一两端分隔符语义。

## 授权范围与后续问题

### 插件运行信任边界

现有默认 capability 应用于所有本地应用窗口，包含全路径文件读写和广泛 HTTP 请求范围；asset scope 也保留了既有的 `**`。本轮只补齐元数据读取、收窄画布目录特例，没有进行全应用最小权限迁移。

JS 插件通过动态 import 加载到宿主前端，Native 插件在宿主进程加载，Sidecar 由普通子进程启动。已检查的加载与执行链路没有将 manifest 的 `permissions` 字段转换为 OS 级权限隔离。插件应按可信本地代码管理；子进程隔离提供独立运行与生命周期，并未自动建立沙箱。后续若支持低信任插件，需要单独设计权限代理与进程沙箱，并覆盖现有 SDK / 原生命令入口。

### Wayland 会话

`rdev` 全局输入监听仍记录 `KeyboardError`。文件 scope 的修复覆盖不到桌面合成器的输入能力边界。保持普通用户运行；全局鼠标、物理跨窗口拖动、屏幕捕获需要按 X11 / Wayland 和 portal 能力分别继续验证。

### 提示与安装可靠性

颜色批量归档的符号链接提示仍写“需要管理员权限”，而当前后端实际使用目标目录创建探针，Unix 普通用户可在可写目录建立链接。文案应改为目标目录权限与平台能力提示，避免用户因一般目录权限问题以高权限运行应用。

插件安装的失败回滚、压缩包资源上限与已有损坏安装的修复入口仍可继续加强；本次验证使用小型本地归档。既有安装会保留原权限，新安装与重新安装采用本次规则。
