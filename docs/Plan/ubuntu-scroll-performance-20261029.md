# Ubuntu 历史消息滚动性能调查

日期：2026-10-29

## 范围与基线

基于 `f9fc143a8`，沿用上游复测的脱敏语料、Ubuntu 原生检出、WebKitGTK 和 `ubuntu-matrix` 独立数据目录。保持 1440×900 视口、浅色关闭特效，仅检查 branches / media；前后各三轮，每轮重新加载文档，再按相同顺序向下、向上回放。

探针使用合成 wheel 表达阅读方向，通过 1500ms rAF 时间进度设置 scrollTop，同时记录帧间隔、观察器回调及几何访问耗时。由列表当前高度计算滚动目标，异步展开会改变所经内容。该探针用于找出主线程连续占用与布局热点，结果不能等同原生滚轮延迟。重载清理页面实例和高度缓存；系统文件缓存保持原状。

## 已定位的成本

### 多媒体首次展开

`memory-real-7-n13` 的脱敏正文长 40,822 字符，本地生产解析器得到 178 个顶层块、547 个图片节点。首次访问必须构造大量组件、解析资源并加载图片；显示后整行实测高度约 211,321px，列表曾由约 27,282px 扩展至 238,102px。

这解释了前轮的巨大高度变化。通用 500px 行占位无法表达这类超长图片消息；块级回收当前需要先创建并测量正文，也会承担首次完整挂载成本。本轮保留已加载图片语料，后续若采用提前分批挂载，需同时维护图片纵横比、块级占位与阅读锚点。

### 分支会话恢复图表

同条件三轮探针中，首次向上回放的最大帧间隔为 8,305 / 9,345 / 10,285ms，比前轮短探针暴露了更长的连续阻塞。

慢调用堆栈指向 `MermaidNode.rememberHeight()`：SVG 插入和缩放后，在 nextTick 微任务中同步读取 `.mermaid-container` 的 border box。单次读取约 150–300ms；向上回放期间这些读取的累计记录约 4.3–5.4 秒。它包含浏览器为满足几何查询执行的布局工作，不能把全部时间归为 JS 计算。

共享 Mermaid 运行时通过 Promise 链串行配置主题与排版。连续恢复多张图表时，单纯串行会让下一项继续进入微任务队列；本轮在保留主题互斥的前提下增加批次让出。单图 Mermaid 内部布局仍可能很重。

### 休眠正文的块级检查

`useRendererBlockMounting` 原先跟随宿主页面 active，整消息展示树已回收时仍接收页面滚动调度。新实现改为跟随 `displayActive`，并取消休眠时待执行的帧任务。活动长消息内的块级几何扫描仍保留，后续可结合原生时间线检查其成本。

## 本轮调整

- Mermaid 同一批排版累计超出 8ms 后，使用定时任务让出主线程；恢复时再次检查请求有效性，过期任务跳过。
- SVG 插入、缩放与展开后的补充高度读取合并至下一帧；卸载清理待执行帧，保留 ResizeObserver 尺寸更新。
- 整消息休眠时停止块级帧检查与回收定时任务，重新进入阅读区后恢复。
- 增加共享队列行为测试：昂贵任务之间待处理输入获得执行机会，等待期间取消的图表跳过，后续主题配置保持正确。现有生命周期测试继续保护图表高度、主题与展示状态恢复。

## 复测结果

最长单次 rAF 间隔（ms），各列依次为三轮结果：

| 场景          | 调整前                 | 调整后                |
| ------------- | ---------------------- | --------------------- |
| branches 下滚 | 342 / 513 / 579        | 421 / 510 / 290       |
| branches 上滚 | 8,305 / 9,345 / 10,285 | 826 / 550 / 381       |
| media 下滚    | 2,275 / 2,078 / 1,198  | 1,964 / 2,084 / 2,085 |
| media 上滚    | 495 / 447 / 474        | 492 / 1,044 / 250     |

分支会话连续图表恢复时的多秒阻塞明显缓解。调整后上滚期间，超过 4ms 的 Mermaid 容器几何读取累计为约 49–81ms，仍有单图排版与其他布局成本。多媒体首次下滚依然接近两秒，当前修改未解决它的首次挂载问题；上滚样本的波动也需要保留。

这些是插桩诊断回放，前后三轮分组执行，动态高度变化会使同一时间进度经过不同内容。各轮末尾列表高度也有差异，未进行随机交错或相同像素轨迹的基准采样；表格用于确认连续阻塞是否存在，不计算整体性能提升百分比。

验证结果：

- Mermaid 运行时、图表生命周期、Renderer 生命周期和块级回收共 41 项测试通过。新增队列测试替换回原实现后按预期失败：输入任务未获得执行机会，已排队图表在取消前继续渲染；恢复当前实现后通过。
- Ubuntu `bun run build:tsc`、`AIO_DEV_CONTROL=1 bun run build:vite` 和生产前端资源的原生 Debug 构建通过。
- 真实 WebKitGTK 内嵌预览契约 8/8 通过，诊断列表为空。
- 查看复杂预设浅色 / 深色截图：图表、公式和交互画布可见，图表及公式错误节点为 0，布局待完成节点为 0，页面横向溢出为 false。截图位于 `complex-light.png` / `complex-dark.png`。

本轮没有重跑全部主题矩阵，Windows 原生运行态与原生滚轮输入仍待后续专项验证。

## 复现与证据

产物位于 `.tmp/ubuntu-scroll/`，包括 `before-{1,2,3}-{branches,media}.json`、`after-*`、单元测试与构建日志。`paired.ts` 沿用上一轮探针，仅收窄会话范围并在每轮重载；性能插桩只存在于测试页面与临时脚本。

```bash
cd /home/mty/aio-hub-Ubuntu
export PATH="$HOME/.local/bin:$HOME/.bun/bin:$HOME/.cargo/bin:$PATH"
bun .tmp/ubuntu-scroll/paired.ts branches repeat
bun .tmp/ubuntu-scroll/paired.ts media repeat
```

下一步优先处理多图片长消息的首次挂载预算与可靠高度占位，使用同一已加载图片语料检查阅读位置。无需继续扩大主题矩阵。
