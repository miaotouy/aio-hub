# Ubuntu 工作区关闭与归档权限补查（2026-10-30）

## 范围与发现

继续处理兼容性专项中已复现的两项待办：关闭工具标签后的组件回收，以及颜色批量归档的符号链接权限提示。使用 Ubuntu 普通用户、独立生产资源 Debug Tauri 实例，沿用复杂消息样本；实验文件位于独立临时目录。

旧版本实机复现：FFmpeg 加载本地视频后，切换设置并返回仍持有同一媒体地址；点击工具标签的关闭处理器后，该地址依然返回 HTTP 200。主布局的 KeepAlive 缓存与已打开工具列表脱节，关闭仅移除了标签，组件的卸载清理没有执行。

## 实现

### 工作区生命周期

- 主布局按路由路径维护独立缓存边界。主页、扩展页及已打开工具参与缓存；设置页随离开卸载。
- 从工具列表移除路径时，KeepAlive 回收对应缓存项。关闭当前标签先导航回主页；清空标签、分离工具和移除工具也通过同一份打开列表驱动回收。
- 普通页面切换保留工具实例及编辑状态，媒体租约也保持有效；关闭后触发工具既有的卸载清理，重新打开得到新工作区。
- 每个缓存项通过自己的 VNode 属性持有页面，避免停用项的默认插槽继续读取当前页面并被动替换内容。不同工具共用组件、组件名与路由名不同，均可按路径单独回收。
- 路由 query 的变化更新当前页面属性；缓存边界按路径保持稳定。

相关入口：

- `src/components/WorkspaceRouteCache.vue`
- `src/views/MainLayout.vue`
- `src/components/__tests__/WorkspaceRouteCache.test.ts`

### 符号链接归档提示

归档弹窗改为说明目标目录写入权限与文件系统链接能力；Windows 提供系统开发者模式这一可行动入口。预检继续在实际目标目录创建并清理探针，保留底层权限错误。普通用户在可写目录即可完成本机 Unix 链接归档。

## 验证

- Windows 宿主与 Ubuntu 各 17 条相关前端测试通过，其中新增生命周期用例 6 条；沿用工具 store 和媒体源的已有用例。
- Ubuntu 全量类型检查、带 Dev Control 的 Vite 构建、生产资源 Debug Tauri 构建通过（`--debug --no-bundle`）。本轮没有修改依赖与锁文件。
- 最终独立实例的 6 组原生场景全部通过：设置切换后媒体地址保持一致且 HTTP 200；关闭当前标签后旧地址变为 404；重新打开无旧预览且新租约不同；后台标签关闭后旧地址也变为 404。
- 同一原生探针以 UID 1000 在可写目录完成符号链接预检和真实链接归档，检查链接类型、实际目标及探针清理；只读目录返回系统 EACCES（`os error 13`），目录保持空。
- 另外通过真实界面输入目录、扫描一张 PNG、分析、打开归档弹窗、选择符号链接并执行归档，最终文件为指向原图的有效链接。
- 1440×900 下查看浅色、深色归档弹窗。弹窗为 682×704，说明与预检结果可见，页面及弹窗均无横向溢出；归档结果页也已采集截图。
- 最终 Dev Control diagnostics 的异常与 CSP 摘要为空，主题、已打开标签和归档配置已恢复。

6 个新增生命周期用例保护工作区状态与资源释放契约，涵盖异构页面切换、共用组件的路径隔离、关闭后重新打开、当前工具关闭、清空标签保留主页、设置离开卸载，以及异步初始化未完成时关闭。断言观察实例状态、实际卸载/作用域清理和页面输出；重构缓存内部实现后仍可复用。既有工具 store 与媒体源清理用例继续复用。

实机探针通过 Dev Control 调用标签现有 DOM 关闭处理器，检查真实媒体 HTTP 地址；该部分没有验证物理鼠标悬停关闭图标。权限部分调用真实 IPC 并检查最终磁盘链接，界面走查另外记录操作与截图。
