## 1. 目标与边界

本分支用于制作桌面端 `0.6.6-r.2` 修复版。此前已经推送到 `origin/main` 但未进入发布标签的提交，不自动视为本修复版基线，也不要求全部进入修复版。

本轮只选择满足以下条件的改动：

1. 问题已经存在于 `v0.6.6-r.1`，或由该版本包含的数据/模块重构直接引入；
2. 对数据完整性、凭据安全、启动可用性、资源占用或高频主路径有明确影响；
3. 能在旧版本基线上独立验证，不依赖 0.7 的 Recall、Knowledge、Guided Flow、插件 API v3 等新架构；
4. 回移范围和风险可解释，可用自动化测试及真实 Tauri 运行证据支撑；
5. 每项修复独立提交，未经确认不合并到 `main`，不提前修改版本号或创建发布 tag。

## 5. 已知迁移缺口与高风险实机验收项

### 5.1 Agent 跨模块目录迁移不具备可靠恢复语义

位置：`src/tools/agent-manager/composables/storage/useAgentStorage.ts`

当前已知问题：

- 新目录只要存在任意实际条目就跳过迁移，部分复制或新旧目录并存时可能永久漏迁 Agent；
- `.migration_in_progress` 只被排除计数，没有恢复、继续或回滚状态机；
- 完整性验证只比较顶层条目数量，不比较名称、嵌套文件、文件大小、关键 JSON 可解析性或内容；
- 迁移失败后清理新目录但继续应用启动，用户可能只看到空 Agent 列表；
- 没有跨 WebView / 进程互斥，两个迁移调用可能互相复制、重命名或回滚；
- 备份目录没有 manifest、迁移 ID、校验结果和自动恢复入口。

实施结果：保留模块内迁移语义，未引入整模块 Rust staging/rollback 子系统。新增的轻量协调器只负责版本完成标记和跨 WebView 锁；Agent 迁移以当前目标文件为准，从旧目录及 r.1 归档目录递归补齐缺失文件，损坏的 `agent.json` 会先固定路径备份再修复。迁移不覆盖有效目标、不删除旧目录，失败不写完成标记，后续启动原地重试；所有索引、实体读取、保存和删除均在首次文件操作前等待迁移。此次确有历史文件被补齐时，会在完成标记成功落盘后发送可跳转到智能体管理的成功通知；通知发送失败不影响迁移结果。

最低验收场景：成功迁移、重复启动、目标目录部分存在、新旧及归档目录并存、旧 marker 残留、嵌套资产缺失、复制/校验/完成标记写入失败、并发调用、失效锁恢复和旧目录只读恢复。

### 5.2 User Profile 首次升级存在竞态和永久跳过风险

位置：`src/tools/user-profile-manager/composables/storage/useUserProfileStorage.ts`、`src/tools/user-profile-manager/stores/userProfileStore.ts`

当前已知问题：

- 只有“新索引不存在且旧索引存在”才迁移，新索引一旦被创建为空文件就永久跳过旧数据；
- `loadProfiles()` 与 `loadSettings()` 并行，后者可能先由 `ConfigManager.load()` 创建默认新索引，从而使前者跳过迁移；
- 头像资产复制失败只记录 warning，之后仍提交新索引，下一次启动不再重试；
- 单个 Profile 加载失败后可能根据成功加载集合重写索引，进一步固化漏迁状态；
- 没有部分迁移状态、冲突处理、恢复入口和真实旧版本升级测试。

实施结果：User Profile 复用轻量协调器，但索引合并与 `globalProfileId` 规则保留在模块内。默认空索引或有旧索引可恢复的损坏目标会按“目标条目优先、旧条目补缺”合并；配置和头像只补缺失文件，复制或索引提交失败不写完成标记。Store 从一次迁移后的索引快照同时加载档案与全局选择，详情暂时不可读时不再收缩索引或清空已有内存状态。此次确有历史文件或索引被补齐时，会在完成标记成功落盘后发送可跳转到用户档案管理的成功通知；通知发送失败不影响迁移结果。

自动化证据：Agent / User Profile 模块及迁移协调器共 7 个测试文件、24 项通过；迁移完成通知接入后已复验前端类型检查、Oxlint 和 Vite 生产构建，`git diff --check` 通过。真实旧数据与 Tauri 故障注入仍保留为发布门禁，不以合成测试替代。

最低验收场景：并行首载、默认空新索引、部分目标目录、头像复制失败、索引写入失败、重复启动、`globalProfileId` 一致性和旧头像协议解析。

### 5.3 LLM Chat 会话持久化（已回移，待故障与并发验收）

已知证据：

- `writeTextFile()` 截断正式文件后直接写入，进程退出可能留下空文件、部分内容或 NUL 填充；
- 流式保存周期短于单次持久化耗时，同一会话存在重叠写；
- 分离窗口可能参与加载、索引同步和修复，形成多写者；
- 删除与待写队列没有协调，迟到保存可复活已删除会话；
- 索引损坏会触发大量会话文件全量解析，造成明显启动阻塞。

当前工作区已将前端单写者/合并队列、Rust 原子替换、索引备份、恢复语义和删除墓碑作为一个一致性边界回移；上述证据转为发布前故障样本与并发验收清单。

### 5.4 目录搜索资源安全（已回移，待真实大目录与 VCP 联调）

已知问题：

- 超时不等于取消底层 walker；
- 新旧搜索可能重叠；
- 缺少统一深度、文件数、读取字节、deadline 和全局并发预算；
- Tool Calling 和 VCP 的 AbortSignal / cancel frame 没有完整传到节点执行；
- 替换类操作可能在截断或不完整搜索结果上继续写盘。

当前工作区已按调查结论回移完整取消边界：本地搜索可取消、单活动搜索、有限 worker、组合资源预算、Tool Calling 超时下推和 VCP 分布式 cancel frame 保持同一生命周期；上述问题转为真实 Tauri 与远端节点验收清单。
