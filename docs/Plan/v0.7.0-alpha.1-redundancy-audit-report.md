## 6. 结论与建议顺序

- **总计**：高 6、中约 25、低约 20（含复查升级的 2 个行为 bug 和 1 个新发现 bug）。
- **最优先（桌面 Alpha 门禁）**：高优先级中的五项桌面端条目（H1-H4、H6）合计可直接删约 220 行桌面生产代码（H5 是移动端，不纳入本次门禁）。
- **行为 bug 同步修复**：`agentActions.ts` priority/enabled 覆盖 bug、smart-ocr 三份不一致实现、`vcpLogWs.onclose` 缺少取消调用，建议与高优先级清理同批次处理。
- 建议同步恢复 `retrieval_pipeline.rs` 等模块的编译器死代码检测（删除模块级 `#![allow(dead_code)]`）作为长期防线。
- **测试方面**：复查发现原报告的 5 个冗余测试条目中有 2 个是误报（recall-runtime-fixture spec 和 recall-curated-corpus test 应保留），有 2 个 wire contract 测试被错误标记为可删（应保留）。实际可安全清理的仅：`retrieval_pipeline.rs:1406` 的单臂 key 测试、`:2426` 中 3 条 ID 复述断言、`sidecar_plugin_manager.rs` 的 3 个恒真单函数测试（:697-703, :718-730），以及 `runner-options.test.ts` 中 5 个纯配置复述 case。

> **注**：原报告"Rust 侧 `#[allow(dead_code)]` 集群可删约 800+ 行"中约 80% 来自 707 行的 `migration_baseline.rs` 测试文件，生产侧实际约 180 行；原"高优先级六项可直接删约 400 行"含 178 行移动端文件，桌面口径约 220 行。
