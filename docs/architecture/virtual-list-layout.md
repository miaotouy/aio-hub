# 虚拟列表布局约定

## 动态高度列表

统一通过 [`useMeasuredVirtualizer`](../../src/composables/useMeasuredVirtualizer.ts) 创建纵向动态列表。

- 调用方提供条目身份键。筛选、排序和同数量数据替换后，缓存继续跟随原条目。
- 键映射由响应式数据快照生成，覆盖数组原地排序和跨集合切换。
- 行节点声明 `data-index` 并绑定 `measureElement`，同步读取布局高度；摘要变化、详情展开和重新挂载时采用当前尺寸。
- 被测节点包含卡片和行间距。外层 margin 不计入自身 `offsetHeight`，可将间距放进被测包装层。
- 宽度、内容或分组结构变化会改变屏外条目的高度时，调用方重置对应缓存。Token 分组跟踪完整分组结果，覆盖等数量文本替换。

## 当前接入点

| 区域                                   | 身份与布局处理                         |
| -------------------------------------- | -------------------------------------- |
| 聊天会话侧栏、智能体侧栏、批量会话管理 | 会话或智能体 ID，实测搜索摘要高度      |
| 输入区迷你会话列表、迷你智能体列表     | 实测卡片与间距，按测量位置定位当前会话 |
| 思绪集条目                             | 数据库与条目 ID，实测卡片              |
| 思绪集监控日志                         | 日志 ID，实测可展开详情                |
| VCP 消息监控                           | 同一消息对象的稳定键，实测消息内容     |
| 批量颜色结果                           | 分组行键，分组变化时重测               |
| Token 计算结果                         | 分组起止位置，分组变化时重测           |

媒体任务网格继续使用固定行高。每行的 CSS 高度与虚拟列表 `itemHeight` 保持 370px，内部卡片为 350px。修改卡片或行间距时同步检查这两个尺寸。

聊天消息正文使用 `content-visibility` 与专用的 `MessageHeightCache`。该缓存以会话、消息 ID 和内容、宽度、外观签名区分测量，保留其消息级实现。

移动端当前源码未使用上述虚拟列表接口；后续引入动态虚拟列表时沿用身份键与实测高度约定。
