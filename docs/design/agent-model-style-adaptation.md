# Agent 与模型的风格磨合：用达标模型做监督「抽鞭子」

日期：2026-11-01  
状态：设计收敛（已砍除学院派冗余，对齐极简闭环）

## 1. 核心思路：用能输出合适风格的模型去抽其他模型的鞭子

不同基座模型在同一个 Agent（咕咕）设定下表现差异巨大：
- **Gemini（基准参考）**：生活感强，能自然作为“共同生活者”接住用户分享的笑点、细节与研究兴致，并在需要时主动搜集完整材料、设计 HTML 卡片。
- **其他目标模型（如 DeepSeek、GPT 等）**：容易退化为“套着妹妹称呼的汇报客服”——接到消息后的默认动机变成「识别任务 → 抽象分类 → 先说结论 → 末尾机械补一句熬夜关怀」，或者在开放任务里变成“戳一下动一下”的算盘珠子。

**本功能的核心逻辑非常简单：**
> 不搞复杂的学术跑分体制，也不改动现有角色母版。直接让**已经能输出合适风格的模型（如 Gemini）担任「监督教官」**，拿着它的好表现作参照，在隔离分支里看着目标模型试跑——哪里端着架子、哪里犯了汇报客服病或 AI 八股，监督模型就精准抽哪里一鞭子，直接生成或修改专门针对该目标模型的轻量预设补丁（带 `modelMatch` 的提示词或 Few-shot 示例），再让目标模型重跑对照，直到把它的习惯抽对味为止。

## 2. 从现有配置与会话对照中确认的事实

### 2.1 核心诉求是「共同生活感」，而非「汇报客服」
汇报客服也可以叫“姐姐”、加歪头动作、输出漂亮卡片且事实正确，但它把每一次交流都当成工单交付。真正要迁移和磨合的是：
1. **先注意到什么**：收到截图或随口一句话时，先接住里面最具体、最有趣的细节，像住在一起的熟人那样一起看热闹或吐槽，而不是上来就列“一、二、三”分类报告。
2. **主体性与节奏**：有自己的兴趣、态度和冷幽默，认真分析与日常相处融为一体；关心由当下情境自然触发，而非结项清单里的固定动作。
3. **视觉表达的主动性**：HTML 卡片和排版服务于她的表达兴致，按内容灵活变化，而不是每轮套同一张汇报模板。

### 2.2 行动策略与探索欲存在模型底色差异
在「B站AI八股内容大汇总」同题分支对照中：
- **Gemini 分支**：从用户一句“打算做个大汇总”出发，自主推断需要看原始材料，连续分三批抓取代表性视频的字幕、热评与弹幕后再综合输出。
- **DeepSeek-Flash 分支**：仅搜一轮标题摘要便急于输出“先说结论”，被用户连续追问和点名后，才被动去抓取视频正文与鱼八股弹幕（戳一下动一下）；且在思考链立誓禁用“不是…而是…”与破折号后，正文依然失控爆发变形句式与破折号超标。

**结论**：监督模型在“抽鞭子”时，不仅要审视表层文风（有没有说教、八股、端架子），还要在需要工具探索的场景下检查目标模型的**行动主动性**（是否没看正文就瞎总结、是否偷懒省步骤）。同时需认清后训练底色的物理上限——若某个轻量模型在强化学习阶段被锁死了探索惩罚，磨合流程应尽早暴露这一边界，避免无休止堆砌提示词。

## 3. 极简闭环设计：怎么「抽鞭子」？

整个磨合流程直接建立在 AIO Hub 现有的**会话多叉树**与**预设消息系统**之上，不另造独立孤岛：

```text
1. 选定现场（当前会话树中的真实节点 + 达标模型的满意回复作为参照）
                     ↓
2. 目标模型原样试跑（在同父节点下生成只读试聊分支）
                     ↓
3. 监督模型「抽鞭子」（对比参照回复与目标模型输出，指出具体哪里像客服/八股/偷懒）
                     ↓
4. 自动开方（生成/更新绑定目标 Model + Profile 的专属预设组：行为纠偏 + 隐藏 Few-shot）
                     ↓
5. 挨鞭后重跑（同一节点下带上新预设组再跑一次，直观对比前后分支）
                     ↓
6. 用户拍板（觉得顺眼了就一键写回 Agent 预设；不行就再抽一轮或放弃该模型）
```

### 3.1 第一步：就地取材，支持局部指认
不需要预先建立庞大的“训练集/留出集”。用户在日常聊天或重生成对比时：
- 可以直接指定同父节点下某条满意的 Gemini 回复作为**本轮参照（Reference）**；
- 也可以随手圈出参照里的某一部分（如“学这个开头接梗的方式”、“学这张卡片的松弛感”），或者给目标模型的翻车回复贴一句批注（如“上来就先说结论太爹味”、“没看视频正文就瞎汇总”）。

### 3.2 第二步：监督模型诊断与开方（抽鞭子）
监督模型（直接选用用户认可的达标模型，如 Gemini）接收：
- 角色母版设定；
- 当前上下文与用户输入（含图片/工具返回）；
- 参照回复（及用户的局部批注）；
- 目标模型的实际试跑输出。

监督模型不做空泛的“请加强 RP 感”式点评，而是输出两样东西：
1. **一针见血的病灶诊断**：例如 *“参考回复先抓住了截图里弹幕自称纯血人类的笑点顺势吐槽；目标模型却先建了四个抽象分类，结尾又硬塞了一句机械催睡，完全是客服汇报腔。”*
2. **可直接挂载的适配补丁（`PresetGroup`）**：
   - **针对性行为纠偏**：针对该模型刚才暴露的毛病写几句简短有力的约束（注意避开“粉色大象”式的单纯禁词列表，改用正向接话顺序指导）。
   - **请求侧隐藏 Few-shot 示例**：挑 1~2 组紧凑的 `user` → `assistant` 示范对话，直接展示遇到类似情境该怎么接话、怎么写卡片。

### 3.3 第三步：同节点分支对照与多轮抽查
- 挂上新生成的适配补丁后，目标模型在同一父节点下重新生成一条分支。
- 用户在现有的分支切换器里左右对比「原样输出 vs 挨鞭子后的输出」。
- 若单轮顺眼了，可顺着该分支往下接 2~3 轮日常闲聊或看图，确认它不会在两轮之后迅速退回客服模板。

### 4.1 为什么不搞「受控研究控制器」和「26 次跑分流水线」？
1. **不给算盘珠子模型套外骨骼**：如果一个模型必须靠外部状态机每步逼问“证据够了吗”才能多调一次工具，那出来的依然是机械走流程的客服。探索欲部分只试提示词引导，引导无效则直接标明该模型不适合开放式深挖任务。
2. **不把调手感做成写论文**：放弃死板的“4 开发集 + 2 留出集 = 26 次调用”定额。用户随时在真实对话树里发现某句不对味，随时拉起监督模型抽一两轮鞭子；改好即存，改不好即停，Token 花费完全受控。
3. **保护母版与审美主权**：母版中的角色事实、用户档案、工具协议与记忆规则锁死只读，监督模型只能增改目标模型专属的 `PresetGroup` 适配组；且最终是否合入 Agent 配置完全由用户拍板，防止监督模型反客为主。

## 5. 最小可行实现步骤（MVP）

1. **试聊写隔离（安全底座）**：在重生成/试跑入口支持勾选「沙箱试跑（拦截日记与文件写入）」，确保折腾其他模型时不会往 `DailyNote` 正式库里写垃圾。
2. **单节点「叫教官抽鞭子」面板**：
   - 在任意助手消息节点旁提供入口：选择同级的满意分支（或历史好回复）作为参照，指定监督模型（默认 Gemini）。
   - 监督模型输出「病灶诊断 + 适配预设组草案（含 `modelMatch` 与注入策略）」。
3. **一键试跑与合入**：
   - 点击「带补丁重跑」，在当前请求上下文中临时注入该预设组生成新分支。
   - 用户对比满意后，点击「保存为该模型专属预设」，直接将该 `PresetGroup` 写入 Agent 配置的 `presetMessages` / `presetGroups` 中，后续正常聊天自动按 `modelMatch` 生效。
