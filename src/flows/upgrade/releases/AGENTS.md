# 用户更新说明编写约定

本目录的 Markdown 正文，以及 manifest 中的 `title`、`summary`、`highlights` 会直接展示给用户。读者需要快速找到关心的模块，了解功能变化和升级注意事项。

## 取材与核实

- 重要功能先查对应的历史聊天，读原始需求和后续反馈，了解使用困扰及方案取舍；聊天标题和摘要用于定位。
- 结合 plan、design、architecture 与直接相关实现，核对当期已交付的能力。区分讨论提案、最终实现和后续版本变化。
- Commit 与 diff 用于定位和核实改动。功能收益应有需求记录、设计说明或可观察行为支撑；背景缺失时按已确认行为写，保持表述克制。
- 研究过程与工程依据留在开发记录。私人提示词、角色名、路径和个人配置改用通用案例，凭据及敏感内容遵循仓库访问边界。
- 对外部评审和改写样稿同样核实事实，尤其是性能数字、兼容版本、平台范围、默认值及操作名称。

## 正文结构：方便扫读

- 默认按界面中的模块名分节，如「智能体预设消息」「LLM 对话」「Git 分析与提交」「媒体生成」。标题可补充本次重点，保留模块名作为查找锚点。
- 以 `- **功能点**：变化与用途。` 为主要条目形式，一条只讲一件事，或同一使用任务中紧密相关的一组变化。用途各异的功能、不同界面中的独立操作和不同工具分别成条，条目数量服从内容，避免为压缩行数用分号或逗号拼接。
- 加粗标题是扫读索引，冒号后应有完整的动作和对象，单独读正文也能理解。例：「新增统一操作弹窗，创建 Git 标签后可直接推送到远端」，避免只写「可在同一弹窗中完成」。
- 新概念或关键需求可在列表前用短段说明背景，随后列出具体能力；背景服务于理解功能，按内容需要取舍。
- 修复写清对象与可观察的问题。内部禁用条件、状态机和防御逻辑归入开发文档，影响使用决策的数据风险与限制单独提醒。
- 长版本可以提供「更新重点」，让读者先看主要变化；模块列表展开细节，控制重复和篇幅。
- 升级、迁移、格式兼容及模型限制集中列出，写清需要采取的行动。

## 标题与摘要

- `title` 使用明确的功能或模块名称，如「预设消息组合、聊天分支保存与 GitHub 仓库分析」，避免口号、顺口溜和含义模糊的生活化替代。
- `summary` 简述主要变化与用途，保留可搜索的功能名称。
- `highlights` 提炼主要功能，每条独立可读。正文补充操作与限制，保持脱离应用页面后仍能读懂。
- 文字调整保留版本号、日期、发布通道、贡献关联和注册契约。

## 用词与事实边界

- 用清晰、干练的书面中文。保留用户需要识别的模块名、协议名、文件格式和高级设置名称，实现术语仅在有助于使用时出现。
- 工具与功能名称沿用真实界面中的完整名称，例如「符号链接搬家工具」。避免生造「符号搬家」等含义含混的简称。
- 专业配置先说明解决什么麻烦、在什么条件下有效，再补必要的配置名称。例：确认同款嵌入模型和向量配置一致后，可手动换渠道并保留已有向量，省去重复计算。单写「增加模型身份和向量空间设置」不足以交代用途。
- 写明实际收益，省去「落地、收敛、产品化」等过程总结，以及寒暄、夸张赞叹和口号式比喻。
- 性能数字需有测量依据，并保留影响结论的场景与口径。单一样本的堆内存变化应限定到该样本，通用更新说明可概括为「降低长文渲染的内存开销」。
- 修改事实错误时，同步更新相关开发记录。完成情况区分文案整理与已完成需求溯源的条目。

## 复核条目是否独立

- 「用量与重试」拆为「Token 用量」和「自动重试」，各自说明变化。
- 「模型刷新预览」只写渠道中刷新模型的变化，智能体参数页放入智能体章节。
- 「目录搜索与符号搬家」拆为「目录搜索」和「符号链接搬家工具」，分别说明各自的操作。
- 「历史版本说明」只写版本浏览与搜索，通知分页另列「通知中心」。

这些例子用于检查信息是否同属一个任务，正常的关联说明可以保留，按语义判断逗号、分号和「与」的使用。

## 需求背景如何进入条目

历史聊天《研究消息合并组配置》记录了原始困扰：两条预设消息只有局部差异，公共正文却要同步维护两份。当前能力见[交互设计](../../../tools/agent-manager/docs/Plan/preset-message-composition-ui-design.md)与[设计及接入记录](../../../tools/agent-manager/docs/Plan/preset-message-composition-draft.md)。

可写成：

> - **组合消息**：将相似提示词的公共正文和差异部分拆成片段，公共规则只需维护一份；人设、文风等局部差异可通过片段版本切换。

条目同时保留功能名称、原有困扰和本次收益，读者可以扫读，也能理解用途。
