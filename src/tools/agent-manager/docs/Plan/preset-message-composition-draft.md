# 消息内部组合：设计与接入

> 更新：2026-10-24
> 状态：已接入业务；交互以[当前设计](./preset-message-composition-ui-design.md)为准
> 归属：Agent Manager；关联桌面与移动端聊天上下文流水线

## 0. 当前功能定位

单条消息的正文由有序内容块组成：正文条目与单选组可以任意排列，条目列表通过左侧勾选框承担多选；一条消息可同时包含多个独立选择维度。每个块可命名和启停，组内备选可命名和排序。核心使用场景包括身份、表达风格、附加规则与输出格式的独立搭配。

组合的作用域是宿主消息：外层继续管理角色、注入、匹配和附件；内部结构只生成这一条消息的正文。相邻同角色消息保持各自边界，后续会话级角色合并仍由原有配置控制。先拼装正文，再执行现有宏处理。

列表卡片默认折叠，显示块数与当前完整正文摘要；展开后操作内部选择。折叠状态只在组件内维护，选择与持久化结构保持原样。编辑工作区提供正文和单选组两种创建入口，连接方式在整个组合层统一配置。编辑备选与选入当前组合是独立操作。

正文结构使用 v1。单选组使用 selectedOptionId；所有条目通过 enabled 控制是否参与拼接，取消勾选保留正文与单选状态。条目按 parts 数组顺序输出，统一通过 composition.separator 连接。

以下调研记录保留最初的重复正文案例。公共前后文提取是组合能力的转换入口之一。

## 1. 最初配置与案例

本次只读检查了主人指定的 Agent 配置。该配置有 21 条预设消息、2 个消息组。其中 `vcp配置` 为单选组，包含以下两个变体：

| 消息        | 正文长度 | 差异内容       | 当前选择 |
| ----------- | -------: | -------------- | -------- |
| `1VCP系统1` | 359 字符 | `{{AIOgugu}}`  | 已选     |
| `2VCP系统2` | 360 字符 | `{{AIOgugu2}}` | 未选     |

两条消息的角色、注入策略与模型/渠道匹配配置相同。把正文拆成「公共前文 + 完整宏调用 + 公共后文」后，分别选入两个宏，均能逐字符还原对应原文。公共前文长 56 字符，公共后文长 292 字符，公共文本只需保留一份。

**建议增加一种占据主列表位置的“消息合并组”，由它承载完整消息配置，内部用有序文本片段和单选片段组织正文。** 现有消息组继续承担多条完整消息的分类与选择。

界面可使用“合并组”，底层将其建模为一条带结构化正文的预设消息。这样可以复用现有角色、匹配条件、注入位置、附件、拖拽和消息来源机制。

另一组 `防输入拦截` 同时包含 assistant 与 user 消息，并分别使用不同的注入顺序。它适合继续使用现有普通消息组，保持各自角色和注入配置。两类组可以在同一个 Agent 中并存。

调研时保留原 Agent 配置；后续已接入共享编译、编辑与聊天注入。

## 3. 使用方式

以当前配置为例，主列表中显示一个合并组：

```text
VCP 系统                         [启用] [编辑] [复制] [删除]
角色：system  注入：历史消息之后  顺序：120  匹配：原有渠道条件

  1. <<<[ROLE_DIVIDE_USER]>>> …    [启用] [编辑] [拖动]
  2. {{AIOgugu}}       [‹ 1 / 2 ›] [编辑] [拖动]
       {{AIOgugu}}
  3. AIO 与 VCP 的生态关系 …       [启用] [编辑] [拖动]

连接方式：原样
```

- 外层统一配置角色、模型/渠道匹配、注入策略、附件与整体开关。
- 普通片段提供正文、开关和排序，列表通过正文预览识别片段。
- 单选片段占据一个拼接位置，包含若干备选正文，选中的选项填入该位置。
- 日常像消息分支一样使用左右箭头切换，中间显示“当前位置 / 总数”，正文预览同步更新；备选按顺序编号。正文与公共片段通过既有编辑弹窗维护。
- 同一个合并组可以包含多个独立单选片段，例如分别选择人格、语言风格与输出格式。
- 单选片段允许清空选择；片段开关关闭时保留原来的选择，重新启用即可恢复。
- 单选选项沿用其所属片段的位置。要调整某个备选整体的注入位置，在外层配置。

结构维持「合并组 → 普通片段 / 单选片段 → 选项」这一固定层级。每条备选正文可以包含多个段落，适合把一套较长的差异规则作为一个选项维护。

现有普通消息组还可以包含合并消息，例如在“工作模式”单选组中切换两套完整配置；合并消息内部再选择局部变体。两层选择的作用范围明确分开。

## 4. 建议数据契约

在 `ChatMessageNode` 上增加预设专用可选字段 `presetComposition`，消息 `type` 继续保持普通预设消息的 `message` 语义。片段使用专用类型，避免继承聊天节点的角色、注入、树关系和生命周期字段。

```ts
interface PresetComposition {
  version: 1;
  separator: string; // 默认 ""；界面提供原样、换行、空行
  parts: PresetPart[];
}

interface PresetPartBase {
  id: string;
  name?: string;
  enabled?: boolean; // 默认 true
}

type PresetPart =
  | (PresetPartBase & {
      kind: "text";
      content: string;
    })
  | (PresetPartBase & {
      kind: "choice";
      selectedOptionId: string | null; // null 表示留空
      options: Array<{
        id: string;
        name?: string;
        content: string;
      }>;
    });
```

### 4.1 单一数据来源

- 普通消息由 `content` 保存正文；合并消息由 `presetComposition` 保存正文结构。
- 合并消息的持久化 `content` 固定为空字符串，满足现有节点字段要求。求值时生成带完整 `content` 的临时副本，保留宿主 ID。
- 合并结果只作为运行时产物；界面与配置工具编辑原始片段。
- 条目使用 `enabled` 记录参与状态，单选组使用 `selectedOptionId` 保存当前备选；备选保存稳定 ID、可选名称和正文。界面编号由数组顺序派生，调整顺序后仍通过 ID 保持原来的选中对象。
- `parts` 数组顺序就是拼接顺序，减少额外排序字段带来的同步工作。
- 片段 ID 在合并消息内唯一；选项 ID 在所在单选片段内唯一。复制片段或选项时生成新 ID，并同步选择引用。

### 4.2 拼接规则

按 `parts` 顺序取出启用片段的有效正文，再用 `separator` 连接。正文条目取自身正文，单选组取当前备选的正文；取消勾选的条目和清空选择的单选组跳过。启用片段中的空串、空白和换行按原样参与连接。

当前案例使用 `separator: ""`，拆分时把原有换行留在前后文中。两个变体保存完整宏调用 `{{AIOgugu}}` 与 `{{AIOgugu2}}`，避免把差异数字单独拆成片段后依赖跨片段拼接宏名称。

所有有效片段拼接完成后，再统一交给现有宏处理器。这样相邻片段中的模板、局部变量和文本边界按最终正文解释。

`chat_history`、`user_profile` 等系统锚点继续放在主列表，作为合并组外层注入策略的目标。合并组内部各项都是正文片段。

## 5. 发送、预览和编辑的接入方式

### 5.1 共享求值

建议新建小型纯 TypeScript 包 `packages/agent-preset-core/`，提供片段类型、结构校验、合并正文与来源映射。桌面和移动端共用；UI、文件持久化、宏解释和 IPC 继续由各端负责。

入口可设计为：

```ts
compilePresetComposition(composition): {
  content: string;
  contributingParts: Array<{
    partId: string;
    optionId?: string;
  }>;
};
```

编译过程只读输入。结构错误返回可定位到片段或选项的诊断，供保存和导入界面展示；运行时发现无效结构时中止当前发送并报告配置问题。失效的 `selectedOptionId` 需要用户重新选择，避免配置损坏后悄悄采用另一个变体。

组与成员的开关、旧式单选约束由统一的预设归一化入口处理，避免只在 UI 点击回调中维持约束。旧式单选数据出现多条启用时，编辑/导入入口应提示处理；发送时应防止同时注入多个成员。

### 5.2 上下文顺序

桌面端建议按以下顺序接入：

1. 根据外层消息开关、现有普通组开关和当前实际模型/渠道决定有效宿主。
2. 对有效宿主编译结构化正文；普通消息保持原行为。保留完整预设列表的顺序与系统锚点语义。
3. 使用有效正文检查工具宏保底注入，再展开宏。
4. 沿用现有深度/锚点注入、附件解析与上下文组装。

移动端在当前 `injection-assembler` 的正文非空筛选之前编译宿主正文，再交给后续 `macros-renderer`。如果先按持久化的空 `content` 过滤，合并消息会被直接丢弃。

合并消息在预设组装层提供一条逻辑消息；后续角色格式化与协议处理继续遵循现有行为。

### 5.3 来源与 token

- `sourceId` 保持宿主消息 ID，`sourceIndex` 保持宿主在主列表的位置。
- 运行时附带参与片段与选项的来源映射，支持上下文预览显示当前选用内容。
- 上下文预览中的“编辑来源”打开合并编辑器；展开后的整段文本使用只读预览。
- `updatePresetMessage()` 等纯正文写入入口遇到合并消息时，提示改用结构化编辑；明确“转为普通消息”后才把当前模板结果写入 `content` 并移除结构。
- token 估算消费同一份编译正文，按合并消息计量；切换选项、修改片段、开关和排序都要使对应缓存失效。
- 附件继续存放在外层消息，沿用宿主的附件解析与估算能力。

## 6. 编辑器与配置工具

主列表增加“新建合并组”。合并消息复用普通消息卡片，内部各片段显示正文的截断预览，单选片段保留左右切换与当前位置。聊天参数侧栏的 `AgentPresetEditor compact` 作为日常切换主要入口，点击箭头直接保存。点击编辑按钮或片段预览进入既有编辑弹窗；片段预览同时定位相应正文。完整列表与侧栏共用选择写入和持久化契约。

编辑器采用双栏工作台，详细流程见[消息合并组交互设计](./preset-message-composition-ui-design.md)：

- 顶部：名称、整体开关，以及外层角色、匹配和注入设置入口。
- 左侧：按序号与正文预览呈现片段，支持新增普通片段、新增单选片段、拖动、复制与删除。
- 右侧：当前片段正文，复用现有代码编辑器、宏选择和资产宏插入能力；单选片段的编辑对象与当前使用项分别操作。
- 下方：字符数、编译错误与连接方式设置。合并正文统一通过右上角“文本预览 / 渲染预览”查看，沿用既有宏预览流程。

现有 [`PresetMessageEditor.vue`](../../components/editors/PresetMessageEditor.vue) 同时包含正文编辑、角色、匹配、注入和附件。实施时可抽出共用正文编辑区域供片段使用，外层配置仍保留原有控件。

配置工具同步提供片段增删、移动、选项选择与正文修改入口。顶层 `add/delete/move_preset_message` 仍操作整条宿主消息；查找替换需要覆盖所有选项的原始正文，修改结果返回宿主、片段与选项定位，方便主人确认影响范围。

## 7. 转换与格式兼容

### 7.1 主动转换当前配置

提供“将消息组转换为合并组”或“从选中消息创建合并组”：

1. 比较原消息的角色、注入、模型匹配与附件。配置相同的成员可共用外层设置；存在冲突时展示差异供主人调整。
2. 以完整宏和文本边界为单位建议公共前后文与变体，允许编辑拆分位置。
3. 预览每个选项对应的完整模板，确认后替换原消息，继承原选择与整体开关。
4. 当前案例的两个成员连续排列，可以把宿主放在第一个成员的位置。跨越其他消息或系统锚点的成员，需要明确确认最终位置。
5. 整个旧组完成转换时同步移除旧组定义和成员引用。只转换部分成员时，保留其余组成员，并明确宿主的组归属。

既有普通组继续保留当前结构。关闭组的转换还要读取已有 `lastEnabledState`，还原之前的选择，随后以新结构保存。

### 7.2 导入导出

- 原有 Agent 和预设继续读取；合并组作为可选结构随 Agent 分享。
- 预设独立导出带合并结构时升级格式版本，保留所有片段、备选与当前选择。
- 导入时校验结构版本、ID、选择引用与正文类型，并将现有宏格式转换应用到全部片段和选项。
- Agent 的格式版本需要与已有 Recall 等迁移共存，实施时统一协调版本值；功能结构另由 `presetComposition.version` 标识。
- 旧版客户端可能忽略结构字段并把空 `content` 当作普通消息。分享时标明最低支持版本，并提供“导出当前选择为普通消息”的显式兼容选项。
- 兼容导出先编译当前选择的模板，再写入普通消息正文；宏留待目标运行环境展开。完整结构导出仍作为可继续编辑的分享格式。
- 移动端需要同步支持读取、求值和编辑，再将合并组列为两端通用能力。当前索引签名保留未知字段的能力只覆盖数据保留，发送前的正文筛选仍需适配。

## 8. 建议实施顺序

1. **数据与求值**：确定结构契约、实现共享编译和校验、接入两端发送流程，统一组开关与选择约束的执行边界。
2. **编辑与转换**：接入主列表宿主卡片、合并编辑器、紧凑模式选择，以及当前配置的显式转换预览。
3. **联动收尾**：接入预设和 Agent 导入导出、宏转换、token 估算、上下文来源编辑与配置工具。

验证围绕四类实际回归：两个变体逐字符还原且每次只注入当前选择；关闭/重开保留选择并跳过停用片段的宏；角色、锚点和附件沿用外层配置；导出再导入保留所有选项与顺序。编译逻辑优先用纯函数单测，两端编辑和实际发送按项目现有真实运行态流程走查。

**建议按“一个外层消息 + 多个正文片段 + 局部单选”实施。** 当前这对消息可以先拆成三个片段，公共正文只维护一份；以后新增局部差异时，添加新的单选片段即可。
