## 研究结论与实现

### 1. 审批与默认范围

- 分布式入口原先直接调用 registry 方法，已补上安全策略、死区拒绝、人工审批、批准后复检、取消及超时处理。
- 审批使用现有本机审批 Store，强制人工确认，服务器/请求/批次子项使用独立标识。实际入口位于聊天工具的审批栏。
- 新安装使用系统 API 解析桌面、文档和下载目录，默认白名单；不可用目录保持关闭。已有持久化配置通过合并保留，恢复默认也使用系统实际目录。
- 审批栏原提示将所有外部请求描述成远程执行，现统一提示请求来源及操作目标，兼容 VCP 请求本机文件操作的场景。

### 2. 文本追加与行范围

- 通用 append_file_force 的其他调用方继续沿用原扩展名限制；Agent 调用传入安全配置，在原生层重新检查路径，支持 Markdown 等 UTF-8 文本追加。
- read_file 增加可选 startLine/endLine：1-based、包含两端，支持文本及文档提取结果。返回 data.lineRange，保留原换行符，越界返回空内容；媒体读取使用独立的参数错误提示。
- 行范围缩小返回上下文；原文件仍接受大小限制和对应格式解析。

### 3. 大小限制与修改队列

- 大小按单文件原始字节计量，文本写入按 UTF-8 编码。读取、写入、追加、Diff、复制在原生层复检；追加检查最终大小，目录复制逐个检查源文件，超限时在覆盖目标前停止。
- 保留原文件写入采用排他创建；原有通用 IPC 调用契约保持兼容。
- 修改操作统一预留真实路径；同文件别名和祖先/后代路径互斥，独立文件可并发。源与目标一次预留，失败后释放，排队期间取消的请求停止修改。
- 作用范围为同一前端运行态中的文件工具调用；外部进程的同时修改继续受逐次磁盘检查与系统文件操作语义约束。
