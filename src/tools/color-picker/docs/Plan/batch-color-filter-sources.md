# 批量色彩筛选来源

## 目标

批量图片分析在不增加重复解码或额外缩放的前提下，为同一张图片保存三种互补的代表色，并让用户切换它们作为色系、亮度筛选和归档分组的依据。

- **平均色**：完整缩略图的 alpha 加权平均色；适合按整体画面调性整理，且保持现有行为。
- **主色**：5-bit 量化后出现次数最多的颜色；跳过透明和近白像素，适合有留白、卡片边框或大面积背景的素材。
- **鲜艳色**：量化色按出现比例、饱和度和中等明度综合评分得到的代表色；适合按画面主体或醒目色筛选照片、插画和设计素材。

不纳入 K-Means、裁剪平均等候选：它们对当前批量筛选没有足够独立的用户价值，或会与三种已选代表色重叠。

## 数据流

```text
原图解码一次 → 128 px 缩略图一次 → RGBA 像素
  ├─ averageColor + luminance
  └─ 单次 5-bit 量化桶扫描 → dominantColor + vibrantColor

前端切换“平均色 / 主色 / 鲜艳色”
  → 对已返回的颜色字段重新分类
  → 更新色系、亮度、筛选、分组、导出和归档
```

切换仅重算小量的 HSL / 亮度分类，不重新调用 Tauri、读取文件、解码或缩放。SVG 由 `resvg` 渲染到同一尺寸的缩略图后，也会计算三种代表色；渲染缓存使用预乘 alpha，量化前会还原为直通 RGB，避免抗锯齿边缘把主色和鲜艳色压暗。

## 交互边界

- 默认是 **平均色**，与旧版批量分析和归档分类保持兼容。
- 工具栏提供“色彩依据”分段切换，并通过提示说明三种方法的适用场景。
- 图片卡片显示当前筛选依据的色块和亮度，避免界面显示值与分组结果不一致。
- 不暴露缩略图尺寸、量化位数、采样间隔或算法权重等调参项；基准显示解码是主要成本，且这些低层参数不会改善大多数用户的筛选工作流。

## 性能与兼容性

三种结果共享生产现有的 `image::open → thumbnail(128) → RGBA` 流程。新增量化扫描只在至多 128×128 的缩略图上运行；量化桶按 Rayon worker 的线程本地缓冲复用，避免每张图片反复分配直方图。不引入新 Cargo 依赖，也不改变线程池、格式分流或缩放策略。结果字段在 IPC 中以 `averageColor`、`dominantColor`、`vibrantColor` 传递；缺少新字段的旧结果在前端自动回退到平均色。
