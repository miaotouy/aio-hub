> 状态：实施中（核心流程与高优先级前端能力已落地，待真实 Tauri WebView 验收）
> 归属工具：`color-picker`
> 计划位置：`src/tools/color-picker/docs/Plan/`

> 实施进度（2026-09-04）：已完成桌面端批量模式切换、目录/多文件扫描、递归深度与输入去重、轻量级透明像素加权采样、主色系/亮度分类、筛选与分组浏览、复制/符号链接归档、冲突重命名、源文件丢失标记、CSV/JSON 报告导出、4 路前端分析队列、预计剩余时间、失败项单项/批量重试、目标目录预检、图片查看器预览、归档结果详情对话框和归档后打开目标目录，以及对应 Tauri 命令和前端规则测试。结果区已接入 `@tanstack/vue-virtual` 的分组分片虚拟滚动，扫描事件级进度和 Rust 专项单元测试已补齐。当前剩余工作是使用真实 Tauri WebView 对本地/网络路径、符号链接、复制归档、预览、取消和重试等场景做人工验收。

## 1. 目标

在现有“图片色彩分析”工具中增加“批量整理”模式，同时保留现有单图取色、调色板分析、手动取色和历史记录能力。

批量模式用于从目录或文件集合中快速筛选图片的配色方向和明暗风格，并按照分析结果将图片复制或创建符号链接到用户指定目录下的分组目录中。

本计划首版只覆盖：

- 主色系分类
- 亮度分级
- 分组浏览与筛选
- 复制到分组目录
- 创建符号链接到分组目录
- JSON/CSV 分析报告导出

Windows `.lnk` 快捷方式暂不纳入本期实现。当前桌面壁纸目录扫描也不支持 `.lnk`，本计划不修改壁纸轮播相关逻辑。

## 2. 产品形态

### 2.1 模式切换

在 `color-picker` 工具中增加模式切换：

- **单图分析**：保持现有功能和交互不变。
- **批量整理**：进入目录扫描、图片分析、筛选、分组和归档流程。

批量结果只保存在当前会话中，不写入现有颜色历史记录，也不将全部图片导入资产库。这样可以避免批量处理大量素材时产生长期存储和历史清理压力。

### 2.2 输入方式

批量模式支持：

- 选择一个目录。
- 选择多个图片文件。
- 拖拽多个图片文件或目录路径。
- 多次添加输入并自动去重。

目录扫描支持递归层级设置：

- 仅当前目录
- 递归 1 层
- 递归 2 层
- 递归 3 层
- 无限递归

默认使用递归 3 层。扫描不跟随符号链接目录，避免重复扫描和路径逃逸。

#### 2.2.1 网络路径支持（高优先级）

支持 Windows UNC 路径（如 `\\server\share\photos`）和已挂载的网络驱动器（如 `Z:\photos`）：

- 后端需要正确处理 UNC 路径的规范化和存在性检查。
- 网络路径访问失败时，明确提示"网络路径不可访问"而非通用"文件不存在"。
- 扫描网络路径时可能较慢，需要在进度指示中说明正在访问网络位置。
- 符号链接可以指向网络路径，但复制操作会将网络文件下载到本地目标目录。

如果网络路径在扫描后、归档前断开，源文件变更检测会捕获此情况并标记为"源文件已丢失"。

首版支持的图片扩展名：

```text
jpg / jpeg / png / gif / webp / bmp / svg / ico / tiff / avif
```

动图默认分析首帧；透明像素不参与平均色和亮度计算。

## 3. 分类与筛选规则

### 3.1 分析方式

批量分析使用独立的轻量级图像特征提取逻辑，不要求对每张图片执行现有单图模式中的全部三种算法。

处理流程：

1. 将图片缩放到不超过 `128 × 128` 的采样画布。
2. 忽略透明度接近 0 的像素，并进行透明度加权采样。
3. 计算平均颜色，用于主色系判定和色板预览。
4. 计算感知加权亮度，用于亮度等级判定。
5. 保存源路径、文件名、平均色、亮度值和分类结果。

分析任务使用后台队列，默认并发 4 张图片，避免批量处理阻塞界面。用户取消后保留已完成结果。

#### 3.1.1 分析进度指示（高优先级）

批量分析过程中，界面需要实时显示：

- 总体进度条（百分比）。
- 已完成 / 总数量（如 `23 / 150`）。
- 预计剩余时间（基于已完成图片的平均耗时）。
- 当前正在处理的文件名（显示最近 4 个并发任务）。

进度信息布局示例：

```text
正在分析图片...  [████████░░] 54%

已完成：81 / 150 张
预计剩余：约 12 秒

当前处理：
• photo_001.jpg
• screenshot_2026.png
• cover_design.webp
• banner.jpg
```

后端扫描和前端分析分别报告进度：

- **扫描进度**：已扫描目录数、已发现图片数。
- **分析进度**：已解码图片数、已完成分析数。

用户可以随时取消，已完成的结果保留并可继续操作。

### 3.2 主色系

首版预设色系：

```text
红、橙、黄、绿、青、蓝、紫、粉、棕、灰
```

默认规则：

- 低饱和度图片归入“灰”。
- 非灰色图片按照平均色的 HSL 色相归类。
- 低明度的橙色系可归入“棕”，以便更符合素材整理习惯。
- 色相跨越 `0°/360°` 时需要正确归入红色系。

色系边界集中定义为可测试的常量，后续可以在不改变结果数据结构的情况下扩展为可配置分类方案。

### 3.3 亮度等级

默认使用 5 档：

```text
极暗、偏暗、中等、偏亮、明亮
```

亮度值归一化到 `0..1`，默认分界点为：

```text
0.20 / 0.40 / 0.60 / 0.80
```

批量设置允许用户调整四个分界点。调整分界点只重新计算分组，不重新读取和解码图片。

### 3.4 筛选逻辑

- 不同维度之间使用 **AND**。
- 同一维度内使用 **OR**。

例如选择”蓝、紫”和”偏暗、中等”时，结果必须同时满足：

```text
色系属于蓝或紫
且亮度属于偏暗或中等
```

筛选状态不自动清除图片选择状态。界面提供”全选当前筛选结果”操作，导出时只处理被选中的图片。

### 3.5 大量图片的虚拟滚动（高优先级）

批量结果区统一使用虚拟滚动优化；当图片数量超过 500 张时可显著降低 DOM 数量，小数据集也保持同一套渲染路径：

- 只渲染可视区域内的图片缩略图。
- 滚动时动态加载和卸载 DOM 节点。
- 使用项目已安装的 `@tanstack/vue-virtual`。

参考项目中已有实现（`SessionsSidebar.vue`、`RecallEntryList.vue`）：

```ts
import { useVirtualizer } from "@tanstack/vue-virtual";

const containerRef = ref<HTMLElement>();

const virtualizer = useVirtualizer({
  count: filteredImages.value.length,
  getScrollElement: () => containerRef.value,
  estimateSize: () => 120, // 每个图片项高度（像素）
  overscan: 5, // 上下各缓冲 5 项
});
```

虚拟滚动的阈值配置：

```ts
{
  threshold: 500,        // 500 张以上收益最明显，当前实现统一启用
  estimateSize: 120,     // 每个结果分片的预估高度（像素）
  overscan: 5,           // 上下各缓冲 5 项
}
```

分组展开/折叠状态需要与虚拟滚动兼容，避免折叠后高度计算错误导致滚动跳跃。每个分组独立使用虚拟滚动实例，或使用扁平化的虚拟列表并计算分组边界。

## 4. 结果展示

批量结果默认以分组卡片展示，也支持切换为紧凑列表。

每个分组使用嵌套维度展示：

```text
色系 / 亮度
```

例如：

```text
蓝/
├─ 偏暗/
└─ 明亮/
```

只创建和显示实际有图片的分组。

### 分组卡片

每个分组卡片展示：

- 分组名称。
- 图片数量。
- 分组代表色。
- 分组全选/取消选择。
- 可展开或折叠的图片缩略图网格。

### 图片项

每张图片展示：

- 缩略图。
- 文件名。
- 源路径提示。
- 平均色小色块。
- 亮度标签。
- 选中状态。
- 分析失败时的错误信息。

分析失败的图片单独显示在失败区域，默认不选中，也不会参与归档。

#### 4.1 图片预览与放大（中优先级）

使用项目全局图片查看器 `useImageViewer()`：

```ts
import { useImageViewer } from "@/composables/useImageViewer";

const { show: showImageViewer } = useImageViewer();

const handleImageClick = (image: BatchImageItem, index: number) => {
  // 获取当前筛选结果的所有图片路径
  const allImages = filteredImages.value.map((img) => img.sourcePath);
  // 显示图片查看器，定位到点击的图片
  showImageViewer(allImages, index);
};
```

全局图片查看器（基于 `viewerjs`）已支持：

- 显示原图（自动处理本地路径转换为 Blob URL）。
- 提供快速切换到上一张/下一张的按钮。
- 支持键盘左右箭头切换。
- 支持 Esc 键关闭预览。
- 支持缩放、旋转、翻转、全屏等操作。

图片的详细元数据（完整路径、文件大小、尺寸信息、平均色、色系、亮度等级）在批量结果界面的卡片或侧边栏中显示，无需在查看器中叠加，保持查看器界面简洁。

用户可以在查看器中快速浏览图片，关闭后回到批量结果界面修改选中状态。

#### 4.2 分析失败图片的重试（中优先级）

对于分析失败的图片，提供重试机制：

- 失败区域显示"重试全部失败项"按钮。
- 每个失败图片项显示"重试"按钮。
- 重试时使用相同的分析参数。
- 重试成功后移入正常分组。
- 重试仍失败时保留原错误信息。

常见失败原因：

- 文件损坏或格式不支持。
- 临时文件锁定或权限问题。
- 网络路径暂时不可用。

错误信息需要明确区分失败类型，便于用户判断是否值得重试。

## 5. 文件归档

### 5.1 操作类型

批量归档提供两个互斥选项：

- **复制文件**：保留源文件，并在目标目录创建副本。
- **创建符号链接**：保留源文件，在目标目录创建指向源文件的符号链接。

首版不提供移动源文件，不删除或改写用户原始素材。

Windows `.lnk` 快捷方式属于后续能力，不与符号链接混用，也不在本期接口中保留占位行为。

### 5.2 输出目录结构

用户选择目标根目录后，输出结构为：

```text
目标目录/
└─ 色系/
   └─ 亮度/
      └─ 图片文件
```

示例：

```text
素材整理/
├─ 蓝/
│  ├─ 偏暗/
│  │  └─ cover.png
│  └─ 明亮/
│     └─ landscape.jpg
└─ 灰/
   └─ 中等/
      └─ icon.png
```

文件在亮度目录下扁平输出，不保留源目录层级。

### 5.3 符号链接权限检测（高优先级）

Windows 系统创建符号链接需要满足以下条件之一：

- 管理员权限。
- Windows 10 1703 及以上版本，且启用了开发者模式。

在用户选择"创建符号链接"模式后，执行归档前，后端需要进行权限预检：

1. 在目标目录创建一个临时符号链接测试。
2. 如果成功，删除测试符号链接并继续。
3. 如果失败，返回权限不足错误码和详细提示。

前端收到权限不足错误后，弹出对话框说明：

```text
创建符号链接需要管理员权限或开发者模式

请选择以下操作：
• 以管理员身份重启应用（提供重启按钮）
• 启用开发者模式（提供系统设置跳转链接）
• 改用复制文件模式（提供切换按钮）
• 取消本次归档
```

提供 Windows 设置跳转路径：

```text
ms-settings:developers
```

用户可以在设置界面关闭对话框后手动调整，也可以直接切换为复制模式继续。

归档过程中，如果个别符号链接创建失败，保留逐项错误，不自动降级为复制，避免用户误以为所有文件都是符号链接。

### 5.4 符号链接类型选择（中优先级）

符号链接分为绝对路径和相对路径：

- **绝对路径符号链接**：指向源文件的完整路径（如 `E:\Photos\image.png`）。
- **相对路径符号链接**：相对于符号链接位置的路径（如 `..\..\Photos\image.png`）。

默认使用**绝对路径**，因为：

- 用户移动目标目录时符号链接仍然有效。
- 实现简单，不需要计算相对路径。

如果未来用户需要同时移动源目录和目标目录并保持符号链接有效，可以在批量设置中增加"使用相对路径"选项。首版不提供此选项，保持简单。

### 5.5 目标目录空间检测（高优先级）

在执行复制操作前，后端需要：

1. 统计所有待复制图片的文件总大小。
2. 查询目标目录所在磁盘的可用空间。
3. 如果可用空间小于文件总大小 + 100MB 安全余量，返回空间不足错误。

前端收到错误后提示：

```text
目标磁盘空间不足

需要空间：X.XX GB
可用空间：Y.YY GB
请清理磁盘或选择其他目标目录。
```

符号链接模式跳过此检查，因为符号链接本身占用空间极小（通常 < 1KB）。

### 5.6 源文件变更检测（高优先级）

从分析完成到执行归档之间，源文件可能被删除、移动或重命名。

归档操作执行时，后端对每个文件进行存在性检查：

- **文件存在**：继续复制或创建符号链接。
- **文件不存在**：记录为失败项，错误类型为 `SourceNotFound`。

前端在结果中单独显示"源文件已丢失"类别：

```text
归档结果：
✓ 成功：45 张
⚠ 源文件已丢失：3 张
✗ 其他错误：2 张
```

用户可以展开查看具体丢失文件的路径。

### 5.7 冲突与失败处理

- 同名文件不覆盖已有文件。
- 冲突时自动追加 ` (1)`、` (2)` 等序号。
- 复制失败和符号链接创建失败都保留逐项错误。
- 符号链接创建失败时不自动降级为复制。
- 后端负责目标目录创建、输出路径拼接和安全校验。
- 结果中返回成功数、自动重命名数、失败数、输出路径和错误明细。

### 5.8 归档完成后操作（中优先级）

归档操作完成后，结果对话框提供以下选项：

- **在文件管理器中打开目标目录**：调用系统默认文件管理器并定位到目标根目录。
- **查看详细报告**：展开成功/失败明细列表。
- **导出归档日志**：将归档结果保存为 JSON/CSV 文件。
- **关闭并返回**：返回批量整理界面，保留当前会话。

使用 Tauri 的 `shell` API 打开目录：

```ts
import { open } from "@tauri-apps/plugin-shell";
await open(targetDirectory);
```

Windows 平台也可以使用 `explorer.exe /select,<路径>` 高亮显示目标目录，但首版使用简单的打开目录即可。

## 6. 建议的代码结构

### 6.1 前端

在 `src/tools/color-picker` 下新增批量能力相关文件，建议拆分为：

- 批量类型定义：图片条目、分组、过滤器、扫描状态和归档结果。
- `useColorBatchAnalyzer`：图片读取、采样、平均色、亮度和分组计算。
- 批量结果组件：分组卡片、列表视图、筛选栏和选择状态。
- 批量设置组件：输入来源、递归层级、亮度分界点和操作类型。

`ColorPicker.vue` 负责模式切换和流程编排，单图模式尽量保持现有组件和状态逻辑。

#### 6.1.1 状态隔离与分批处理（高优先级）

批量模式和单图模式需要状态隔离：

- 使用独立的 Pinia store 或 ref 存储批量会话数据。
- 切换模式时不清除另一模式的状态，允许用户往返切换。
- 批量模式退出时提示用户是否保留当前会话。

图片分析使用分批处理避免阻塞主线程：

```ts
// composables/useColorBatchAnalyzer.ts
const analyzeBatch = async (images: string[], batchSize = 4) => {
  for (let i = 0; i < images.length; i += batchSize) {
    const batch = images.slice(i, i + batchSize);

    // 并行分析一批图片
    await Promise.all(
      batch.map(async (path) => {
        const result = await analyzeImage(path);
        results.value.push(result);
      })
    );

    // 让出主线程，避免长时间阻塞 UI
    await new Promise((resolve) => requestAnimationFrame(resolve));

    // 更新进度
    progressCount.value = Math.min(i + batchSize, images.length);
  }
};
```

**首版不使用 Web Worker** 的原因：

1. 项目中无 Web Worker 使用先例，引入增加复杂度。
2. 轻量级图片分析（128×128 采样 + 平均色计算）单张耗时 < 10ms。
3. 分批处理 + `requestAnimationFrame` 已足够保持 UI 响应。
4. Tauri 应用中，后端 Rust 多线程性能更优。

**后续优化路径**：

- 如果前端处理 1000 张图片耗时 > 5 秒，将分析逻辑移到 Rust 后端（新增 `color_picker_analyze_images` 命令）。
- Web Worker 作为最后备选方案，仅当后端方案仍不足时考虑。

需要同步更新 `color-picker.registry.ts` 的工具描述和版本信息。

### 6.2 Tauri 后端

```ts
color_picker_cancel_scan({

  testDirectory,

color_picker_check_disk_space({
  targetDirectory,
  requiredBytes,
}) -> { available: number, sufficient: boolean }

color_picker_organize_images({
  items,
  targetDirectory,
  mode: "copy" | "symlink",
  checkSourceExists: boolean,

```

返回结构示例：

```ts
interface BatchOrganizeResult {
  successCount: number;
  renamedCount: number;
  sourceNotFoundCount: number;
  failedCount: number;
  details: Array<{
    sourcePath: string;
    targetPath?: string;

```

Rust 返回结构统一使用：

```rust
#[serde(rename_all = "camelCase")]
```

扫描和归档过程通过带任务 ID 的 Tauri 事件报告进度，避免多个批量任务之间串收事件。

后端需要：

- 对扫描路径去重。
- 不跟随符号链接目录。
- 校验图片扩展名和普通文件类型。
- 防止输出路径逃逸目标根目录。
- 在 Windows 使用文件符号链接能力，在其他平台使用对应平台的符号链接 API。
- 将冲突命名和实际文件系统操作放在后端执行。
- 正确处理 UNC 路径的规范化（Windows `\\?\UNC\server\share` 格式）。
- 符号链接权限预检测使用临时文件测试，成功后立即删除。
- 磁盘空间查询使用平台 API（Windows `GetDiskFreeSpaceExW`，Unix `statvfs`）。
- 源文件存在性检查在归档时逐个执行，失败项标记为 `source_not_found`。


#### 7.1 CSV 编码选项（中优先级）

CSV 导出时提供编码选择，避免中文路径在不同软件中乱码：

- **UTF-8（推荐）**：现代软件默认支持，兼容性最好。
- **UTF-8 with BOM**：Excel 可以正确识别为 UTF-8（不加 BOM 时 Excel 可能用 ANSI 解析）。
- **GBK**：兼容老版本 Excel 和国内表格软件。

默认使用 **UTF-8 with BOM**，平衡 Excel 兼容性和国际化需求。

导出对话框中显示编码选项：

```text
导出格式：CSV
编码：[UTF-8 with BOM ▼]
```

后端负责按照指定编码写入文件，前端不做二次转换。

报告通过现有保存对话框和文件写入能力导出，不新增长期数据库结构。

## 11. UI 交互与视觉设计方案

为了将“批量整理”模式完美融入现有 UI，且不破坏单图分析的纯粹体验，本功能采用**“渐进式工作流”的双栏毛玻璃卡片布局**。

### 11.1 模式切换与整体布局

#### 11.1.1 模式切换入口

在顶部操作栏（`header-bar`）的左侧标题旁，引入一个优雅的 `el-segmented` 切换器：

- **单图分析**（默认）：保持现有双栏布局不变。
- **批量整理**：主内容区切换为批量整理的专属工作流。

#### 11.1.2 批量整理的三阶段状态机

批量整理视图在同一个容器内，根据当前会话状态，在以下三个阶段之间流转：

1. **配置阶段 (Setup View)**：收集输入源和参数。
2. **分析阶段 (Progress View)**：展示多线程分析进度。
3. **结果与归档阶段 (Result & Archive View)**：进行筛选、预览、调整并执行归档。

---

### 11.2 阶段一：配置与输入界面 (Setup View)

当用户切换到“批量整理”且尚未开始分析时，主内容区呈现一个对称的配置界面：

- **左侧：输入源卡片 (`InfoCard`)**
  - **拖拽区域**：使用 `DropZone` 组件，支持拖入文件夹或多张图片。
  - **列表展示**：下方用轻量级列表展示已添加的路径，右侧带删除按钮。支持多次添加并自动去重。
- **右侧：设置与启动卡片 (`InfoCard`)**
  - **递归深度**：`el-segmented` 或 `el-select`。
  - **亮度分界点**：提供一个可视化的滑块（`el-slider` 带 4 个滑块，或者 4 个并排的输入框），允许微调 `0.2 / 0.4 / 0.6 / 0.8` 的分界线。
  - **归档模式预设**：让用户提前选择“复制”或“符号链接”，以便在分析前就明确意图。
  - **底部大按钮**：**“开始分析 (N 张图片)”**，当 N > 0 时激活，点击进入阶段二。

---

### 11.3 阶段二：分析进度界面 (Progress View)

点击开始分析后，界面进入全屏遮罩或居中卡片状态，展示多线程后台任务的进度，避免用户产生“卡死”的焦虑：

- **进度条**：使用 `el-progress`，配合动态百分比。
- **状态文本**：显示“预计剩余时间”（基于已完成图片的平均耗时，动态平滑计算）。
- **并发任务槽**：下方并排或垂直排列 4 个正在处理的文件名，如果是网络路径（UNC），文件名旁带有一个小小的 `[网络]` 标签，提示用户可能存在网络延迟。
- **取消按钮**：点击后中止队列，但**保留已分析完成的数据**，直接跳转到阶段三。

---

### 11.4 阶段三：结果与归档界面 (Result & Archive View)

分析完成后，进入核心的“筛选与归档”双栏界面。这里是设计师进行素材整理的主战场：

#### 11.4.1 左侧：结果展示与筛选区 (`InfoCard`)

- **顶部筛选栏**：
  - **色系多选**：一排彩色的标签按钮（`el-checkbox-button`），背景色对应其色系（如红、蓝、绿），灰色系使用中性灰。
  - **亮度多选**：一排亮度等级按钮。
  - **快捷操作**：提供“全选当前筛选结果”和“取消全选”按钮。
- **图片网格区（支持虚拟滚动）**：
  - 采用扁平化的虚拟列表（`@tanstack/vue-virtual`），将分组标题和图片项混合扁平化，或者每个分组独立虚拟化。
  - **分组标题栏**：
    - 格式如 `蓝色 / 偏暗 (12张)`。
    - 左侧带有一个小色块（代表该分组的平均色）和一个亮度指示图标。
    - 右侧带有“组内全选/取消全选”复选框，以及折叠/展开箭头。
  - **图片卡片 (`ImageItem`)**：
    - 尺寸：`100px × 100px` 的紧凑网格。
    - 悬浮效果：鼠标悬浮时，卡片上方浮现：
      1. 左上角：多选复选框（点击可切换选中状态）。
      2. 右上角：平均色小圆点和亮度数值（如 `L: 0.35`）。
      3. 底部：半透明遮罩显示文件名。
    - 点击交互：点击图片任意区域（除复选框外），触发 `useImageViewer()` 弹出全屏大图预览，支持左右键切换。
- **失败与异常区域**：
  - 在列表最下方，如果存在分析失败的图片，展示一个“分析失败 (N张)”的分组。
  - 失败项卡片呈灰色半透明，中心显示一个警告图标。悬浮时显示具体错误（如 `格式不支持` 或 `网络超时`），并提供一个“重试”小按钮。
  - 顶部提供“重试全部失败项”按钮。

#### 11.4.2 右侧：归档控制面板 (`InfoCard`)

- **目标目录选择**：
  - 一个输入框配合“选择目录”按钮。支持手动粘贴 Windows UNC 路径。
  - 输入框下方有动态提示：“网络路径”或“本地磁盘”。
- **归档模式切换**：
  - `el-radio-group` 切换“复制文件”与“创建符号链接”。
- **动态预检看板**：
  - **磁盘空间**：当选择“复制”时，实时计算选中图片的总大小，并与目标磁盘可用空间对比。如果空间不足，文字变红并显示警告。
  - **链接权限**：当选择“符号链接”时，后台自动进行临时文件写入测试。如果无权限，显示黄色警告，并提供一个“查看引导”链接（点击弹出开发者模式/管理员重启引导）。
- **执行按钮**：
  - 巨大的 **“开始归档 (已选 M 张)”** 按钮。

---

### 11.5 归档结果对话框 (Archive Result Dialog)

归档完成后，弹出一个精致的模态对话框，展示归档战报：

- **视觉反馈**：使用大图标和语义化颜色（绿色成功、黄色冲突、红色失败）。
- **快捷操作**：
  - **“在文件管理器中打开”**：一键调用 Tauri Shell API 打开目标目录，让设计师立刻看到整理成果。
  - **“导出归档日志”**：提供下拉菜单，支持导出 JSON 或 CSV（默认 UTF-8 with BOM，完美解决 Excel 乱码）。

---

### 11.6 移动端极简主义适配 (Mobile Constraints)

根据项目的 `mobile-protocols.md` 规范，移动端屏幕极其珍贵，且不支持符号链接和本地归档：

- **移动端不提供“批量整理”模式**。该功能作为桌面端专属的“生产力工具”存在。
- 桌面端 UI 保持高密度、多维度的卡片展示，不进行过度留白，确保设计师能在一屏内浏览尽可能多的素材。
