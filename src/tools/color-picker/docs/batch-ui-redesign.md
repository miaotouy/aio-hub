# 批量色彩整理工具 UI 重构说明

## 重构时间
2026-09-05

## 问题分析

原有设计采用了**强制三阶段向导流程**（配置输入 → 分析进度 → 筛选归档），这种设计存在以下问题：

1. **固定步骤流程不适合此场景**
   - 批量分析不是一次性完成的向导任务，而是需要反复调整的工作流
   - 分析阶段占据整个屏幕，用户无法边分析边查看结果
   - 配置和结果无法同时可见，调整参数需要返回上一步

2. **与现有模块风格不一致**
   - 资产管理器采用侧边栏 + 工具栏 + 内容区的自由布局
   - Agent 资产管理器同样采用左侧边栏分组 + 主内容区的结构
   - 强制向导流程与项目整体交互风格不符

3. **空间利用不合理**
   - 分析进度占据整个视口，但只需要小块区域显示状态
   - 结果筛选和归档操作被割裂在不同阶段，无法联动

## 解决方案：侧边栏 + 主内容区布局

### 核心设计理念

参考资产管理器的布局模式，将批量整理改为**自由操作**而非强制流程：

```
┌─────────────────────────────────────────────────────────┐
│ [左侧边栏]        [主内容区]              [右侧面板]     │
│ 输入&配置          工具栏 + 结果网格         归档控制    │
└─────────────────────────────────────────────────────────┘
```

### 布局结构

**左侧边栏（280px）**：
- 添加图片（拖放区 + 文件/目录选择）
- 候选图片统计
- 分析设置（递归深度、亮度阈值、归档模式）
- 开始分析按钮
- **分析进度**（在侧边栏内显示，不占据主区域）

**主内容区（flex: 1）**：
- 工具栏：
  - 色系筛选下拉框
  - 亮度筛选下拉框
  - 统计标签（筛选/总数/已选）
  - 批量操作（全选当前、清空选择）
  - 导出报告（CSV/JSON）
  - 重试失败按钮
- 结果网格：
  - 虚拟滚动分组展示
  - 按色系/亮度分组
  - 每组显示颜色指示器、标题、数量、全选框
  - 图片卡片显示颜色预览、文件名、亮度值

**右侧面板（320px）**：
- 已选数量大号显示
- 目标目录选择
- 归档方式切换
- 预检结果（磁盘空间/符号链接权限）
- 开始归档按钮
- 归档结果统计（成功/重命名/失败/丢失）

### 组件拆分

为提高代码可维护性，将单体组件拆分为：

1. **BatchInputSidebar.vue** - 左侧输入配置栏
   - 添加图片、候选列表、分析设置
   - 分析按钮和进度显示
   - 280px 固定宽度

2. **BatchResultToolbar.vue** - 主内容区工具栏
   - 筛选器（色系、亮度）
   - 统计标签
   - 批量操作按钮
   - 导出和重试按钮

3. **BatchResultGrid.vue** - 结果网格
   - 虚拟滚动列表
   - 分组展示
   - 图片卡片交互

4. **BatchArchivePanel.vue** - 右侧归档面板
   - 归档配置
   - 预检状态显示
   - 归档结果统计

5. **BatchColorOrganizer.vue** - 主容器
   - 组合上述组件
   - 状态管理和业务逻辑

## 关键改进点

### 1. 非线性工作流

- **不再是向导**，而是自由操作的工作台
- 可以边分析边查看结果（已完成的立即显示）
- 配置始终可见，随时可调整参数重新分析
- 分析是后台任务，不阻塞界面

### 2. 空间利用优化

- 分析进度在侧边栏显示，只占用必要空间
- 主内容区专注于结果浏览和筛选
- 归档控制独立面板，与结果区联动

### 3. 交互一致性

- 与资产管理器、Agent 资产管理器保持一致的布局风格
- 侧边栏 + 工具栏 + 内容区的标准三栏结构
- 符合用户对文件管理类工具的操作预期

### 4. 实时反馈

- 分析进度实时更新（完成数、预计剩余时间）
- 已完成的图片立即出现在结果网格
- 预检结果实时显示（磁盘空间、权限检查）

### 5. 虚拟滚动优化

- 使用 `@tanstack/vue-virtual` 优化大量图片渲染
- 按分组分片虚拟化
- 自动测量行高，适应不同内容

## 技术实现要点

### 状态管理

```typescript
// 数据状态：候选、分析项、筛选条件
const candidates = ref<BatchImageCandidate[]>([]);
const items = ref<BatchImageItem[]>([]);
const filter = ref<BatchFilterState>({ colorFamilies: [], brightnessLevels: [] });

// 分析状态：后台运行，不阻塞UI
const analyzing = ref(false);
const completed = ref(0);
const etaSeconds = ref<number | null>(null);

// 归档状态：预检、执行、结果
const preflight = ref({ loading: false, error: "", ... });
const organizing = ref(false);
const archiveResult = ref<ArchiveResult | null>(null);
```

### 分析流程

- 点击"开始分析"后，`analyzing` 变为 true
- 进度在左侧边栏显示，不占据主区域
- 并发 4 个 worker 处理图片
- 每完成一张，更新 `completed` 和 ETA
- 已完成的图片立即进入 `items` 并显示在网格中
- 用户可随时取消分析

### 预检机制

- 监听 `selectedItems`、`targetDirectory`、`archiveMode` 变化
- 自动调用预检 API（磁盘空间检查/符号链接权限检查）
- 结果影响"开始归档"按钮的可用性
- 实时显示检查状态（loading/success/error）

## 响应式适配

### 桌面端（> 1200px）
- 三栏完整显示：左侧边栏 280px + 主内容 flex + 右侧面板 320px

### 平板端（768px - 1200px）
- 垂直堆叠：侧边栏在上，主内容在中，归档面板在下

### 移动端（< 768px）
- 暂不支持，批量整理是桌面专属功能

## 与原设计的对比

| 维度 | 原设计（三阶段向导） | 新设计（侧边栏布局） |
|------|---------------------|---------------------|
| 工作流 | 强制线性流程 | 自由操作 |
| 分析进度 | 全屏显示 | 侧边栏小块区域 |
| 配置可见性 | 只在第一阶段可见 | 始终可见 |
| 结果查看 | 必须等分析完成 | 边分析边查看 |
| 空间利用 | 阶段切换浪费空间 | 三栏高效利用 |
| 风格一致性 | 独立向导风格 | 与资产管理器一致 |
| 操作灵活性 | 低（必须按步骤） | 高（随时调整） |

## 总结

此次重构将批量色彩整理工具从**强制向导流程**改为**自由操作工作台**，参考资产管理器的成熟布局模式，提供了更灵活、高效的用户体验。同时通过组件化拆分，提高了代码的可维护性和可测试性。

新设计更符合桌面端文件管理工具的操作习惯，与项目整体交互风格保持一致。
