# 动态消息注入锚点待办

> 记录日期：2026-10-29
> 状态：待实施
> 范围：桌面端与移动端的预设注入、锚点配置，以及关联的酒馆预设导入兼容。

## 需求

预设消息需要支持吸附到最后一条指定角色消息的之前或之后，例如在最后一条用户消息之前插入指令，在最后一条 AI 消息之后插入提醒。

首批补齐以下三个动态目标，沿用现有的“之前 / 之后”和顺序权重配置：

| 动态目标 | 相对位置 |
| --- | --- |
| 最后一条用户消息（`user`） | 之前、之后 |
| 最后一条 AI 消息（`assistant`） | 之前、之后 |
| 最后一条消息 | 之前、之后 |

固定深度依赖消息条数；续写、重新生成和工具调用会改变尾部角色分布，因此需要独立的按角色定位能力。

## 当前实现与缺口

- [锚点注册表](../../composables/ui/useAnchorRegistry.ts)的内置锚点只有 `user_profile` 与 `chat_history`。
- [注入配置编辑器](../../../agent-manager/components/editors/InjectionConfig.vue)已有目标、前后位置和顺序权重，可复用其交互结构。
- [桌面端组装器](../../core/context-processors/injection-assembler.ts)围绕预设占位符组装锚点注入，历史消息作为整段插入，尚无按历史消息角色查找动态目标的逻辑。
- [移动端组装器](../../../../../mobile/src/tools/llm-chat/core/pipeline/processors/injection-assembler.ts)同样缺少动态目标解析；移动端另有独立的类型与预设编辑入口，需要同步。
- [预设编辑器](../../../agent-manager/components/assets/AgentPresetEditor.vue)会为系统锚点自动补占位卡。新增动态锚点时需要区分定位类别，防止生成可拖动的“最后用户消息”占位卡。
- [历史加载器](../../core/context-processors/session-loader.ts)已将预览中的待发送输入作为 `session_history` 用户消息加入，可作为预览与实际发送对齐的接入点。

## 关联待办：酒馆预设注入兼容

核查入口：[sillyTavernParser.ts](../../services/sillyTavernParser.ts) 的 `SillyTavernPrompt` 与 `convertInjectionStrategy()`，以及[酒馆兼容说明](../architecture/sillytavern-compatibility.md)。

2026-10-29 核查发现：

1. 当前转换优先判断 `injection_depth > 0`，会绕过位置类型；深度字段需要结合位置语义解释。
2. 当前将 `injection_position = 1` 解释为历史之前。核对酒馆 release 分支 `public/scripts/PromptManager.js`，其定义为 `RELATIVE = 0`、`ABSOLUTE = 1`，其中 `1` 表示 in-chat 注入。现有映射与之有出入。
3. 因上述分支，`injection_position = 1` 且 `injection_depth = 0` 的预设会被放到历史之前，尾部注入语义丢失。
4. 当前转换将顺序统一设为 `100`，类型与转换均未读取 `injection_order`。
5. 兼容文档仍记录当前旧映射，实现修正时需同步更新。

待办：

- [ ] 按预设导入格式核对位置与深度语义，修正 `injection_position` 和 `injection_depth` 的联合转换，保留深度 `0`。
- [ ] 读取并保留 `injection_order`，缺省时沿用默认值。
- [ ] 对已有的 `2`、`4` 位置分支核查格式来源，再确定兼容处理，避免直接套用其他配置格式的编号。
