# Chat 输入区上方功能面板插槽计划

- 状态：六组面板已接入 / 待主人界面验收
- 最近更新：2026-10-16
- 公共化：面板容器与布局已迁至 `src/components/common/input-panel/`，控制器迁至 `src/composables/useInputPanel.ts`，Chat 与媒体生成共同使用；下文原组件名保留实施记录。
- 影响范围：桌面 Chat 输入区、分离输入窗口；复用现有工具栏布局与业务设置
- 当前阶段：输入设置、宏变量、会话、工具设置、Knowledge、画布已统一接入单插槽；代码检查与相关测试已通过，真实界面验收由主人进行

## 1. 目标与布局

在 Chat 输入区上方增加统一功能面板插槽。适合持续操作的气泡内容改造成符合插槽契约的面板，通过正常布局展示，输入文字与发送入口始终可见。

同一位置承载一个当前面板。打开另一项功能时直接替换内容；容器统一提供标题、折叠与关闭控件。

建议从上到下排列：

```text
聊天记录
────────────────────────────────────
Knowledge · 已引用 2 个库             折叠 / 关闭
  搜索、引用方式、资料库列表
────────────────────────────────────
已引用资料、附件
────────────────────────────────────
输入文字

工具栏、状态、发送 / 停止
```

折叠后仅保留当前面板的标题行；关闭后插槽收起并释放空间。容器使用项目主题与轻量分隔，宽度跟随输入工作区。输入框聚焦与面板展开可以同时保持。

## 2. 实施前盘点

| 内容 | 当前承载方式 | 建议承载方式 | 完成操作后的行为 |
| --- | --- | --- | --- |
| 宏变量 | 工具栏共享气泡，内容为 `MacroSelector` | 插槽内插入面板 | 插入后关闭，回到编辑器并保留插入位置 |
| 会话列表 | 工具栏共享气泡，内容为 `MiniSessionList` | 插槽内切换面板 | 选中后关闭；维持现有会话草稿隔离 |
| 工具调用设置 | 工具栏共享气泡，内容为 `MiniToolCallingSettings` | 插槽内设置面板 | 修改即时生效；高级设置沿用原入口 |
| Knowledge 引用 | `KnowledgeReferenceControl` 自有气泡 | 插槽内引用面板 | 多选期间保持展开；引用结果沿用现有 chips |
| 输入设置 | `ToolbarSettingsPopover` 自有气泡 | 插槽内设置面板 | 修改即时生效；保留现有存储及同步通道 |
| 画布管理 | `ToolbarStatusCapsules` 内的独立气泡 | 插槽内画布面板 | 保留绑定、解绑、新建、打开操作及当前状态 |
| 更多操作、快捷操作集合菜单 | 工具栏短时菜单 | 保留短菜单 | 面板类菜单项关闭菜单后替换插槽内容 |
| 附件操作、转写批量操作 | 附件区短时菜单 | 保留短菜单 | 执行动作后结束；承载位置和高度另行走查 |
| 临时模型、补全模型 | `openModelSelectDialog` 对话框 | 沿用现有对话框 | 选择结果继续显示为原状态胶囊 |
| 工具栏自定义、快捷操作管理、上下文分析、Agent 高级设置 | 独立管理入口 | 沿用现有管理界面 | 维持现有业务流程 |
| 流式输出、补全、翻译、压缩、草稿剪切/粘贴等 | 开关或直接动作 | 沿用直接动作 | 保持工具栏与更多菜单的统一执行入口 |

短菜单打开方向优先朝编辑区外侧，并检查空间不足时的翻转。Tooltip 维持短提示，只在悬停或聚焦时出现。

### 实施前确认的结构问题

1. `MessageInputToolbar.vue` 根据多个布尔值计算单一 `openPanel`，共用气泡与虚拟锚点；Knowledge 和输入设置另有气泡壳。
2. 画布的展开状态在 `ToolbarStatusCapsules.vue` 中独立维护，通过事件写回菜单状态，与工具栏功能面板分属两条路径。
3. `messageInputStore.ts` 的 `anyMenuOpen` 汇总气泡、菜单和管理对话框，用于分离窗口尺寸调整。当前任意菜单打开会把窗口扩到至少 650 的逻辑高度。
4. `MessageInput.vue` 已把附件和引用放在编辑器上方；`useMessageInputResize.ts` 根据额外内容高度计算编辑器最大高度。增加插槽后需要统一高度分配。
5. 工具栏已有自定义、排序、窄窗口收纳和跨窗口同步；新交互继续使用这些既有入口。

## 3. 插槽容器标准

### 3.1 容器职责

新增 `MessageInputPanelHost.vue`，位于编辑器上方，统一承担：

- 标题行：标题、可选图标及业务摘要，默认展开/折叠与关闭按钮。
- 内容布局：`MessageInputPanelLayout.vue` 提供 `controls`（顶部常驻控件）、默认内容（滚动区）和 `footer`（底部常驻操作）三个插槽。Host 同时暴露这些插槽与 `header-actions`；动态面板在业务组件内使用同一布局，保留自身状态与事件。
- 布局：全宽展示、统一边框和间距、可用高度限制及内容滚动区域。
- 交互：折叠、关闭、Escape、焦点返回及可访问性关联。
- 尺寸：向输入区提供当前占用高度，折叠与关闭后同步释放空间。

面板内容复用这一外壳，把空间用于自身业务操作。高级设置等业务入口可放在可选标题操作区或内容中。

### 3.2 功能组件接入契约

- 面板描述提供稳定 ID、标题及可选图标/摘要，关联具体内容组件；沿用当前组件映射方式即可。
- 内容组件渲染业务内容，复用现有服务、store 与业务事件。
- 列表、设置区遵守容器提供的宽度和高度预算。默认由容器滚动；虚拟会话列表与宏选择器使用 `scroll: "content"` 接管内部滚动，容器提供确定高度。工具与 Knowledge 使用 `scroll: "layout"`，由业务组件接入公共三段布局，按内容自适应高度并只滚动列表。
- 操作完成后可请求关闭及返回编辑器焦点，如宏插入、会话选择。
- 搜索和加载限定在当前面板生命周期内；替换后卸载旧内容，清理监听与待处理任务。异步结果按面板实例和业务上下文校验，避免旧请求影响新内容。
- 当前面板折叠时保留其局部编辑状态；切换或关闭后释放该实例。重新打开从当前业务状态初始化。

业务设置、Knowledge 引用、画布绑定等已生效的数据继续保存在原业务层，随面板替换正常保留。

## 4. 单插槽交互规则

### 4.1 状态与替换

窗口内面板状态采用单一当前 ID、折叠状态和焦点返回目标，统一经过打开、替换、折叠、关闭入口维护。

| 当前状态 | 用户操作 | 结果 |
| --- | --- | --- |
| 空插槽 | 点功能 A | 挂载 A 并展开 |
| A 展开或折叠 | 点功能 B | 卸载 A，挂载 B 并展开 |
| A 展开 | 再点 A | 按输入设置折叠或关闭；默认折叠 |
| A 展开 | 点折叠 | A 收起为标题行 |
| A 折叠 | 再点 A / 点展开 | A 恢复展开 |
| A 展开或折叠 | 点关闭 | 卸载 A，清空插槽并释放空间 |
| A 展开 | 点编辑器 | 继续输入，A 保持当前状态 |

- 打开新功能时同步更新标题、按钮状态、内容及焦点返回目标。
- 工具栏按钮与更多菜单调用同一入口。窄窗口收纳仅影响触发入口位置。
- 面板 UI 状态作为窗口内临时状态；业务设置继续沿原通道持久化及跨窗口同步。
- 会话与 Agent 切换时，关闭当前会话相关面板；全局输入设置保持。资料库权限、引用、工具列表和画布绑定跟随新上下文。

### 4.2 键盘与焦点

- 功能按钮表达当前面板的展开状态，并关联本地面板 ID。
- 用户从按钮打开面板后，按用途聚焦搜索框或首个操作；宏插入及会话选择完成后回到编辑器。
- 面板内 Escape 关闭当前面板并把焦点还给触发入口；触发按钮已被收纳时，回到更多入口。
- 折叠时若焦点位于内容区，移到标题展开控件。编辑器内 Escape 尊重编辑器原有行为。
- 替换、折叠、关闭及配置修改保留输入草稿和编辑器选区；异步加载完成只更新内容，焦点由当前用户操作决定。

### 4.3 高度与分离窗口

- 插槽采用正常文档流，长列表在预算内滚动；编辑器与发送入口保持可操作。
- 根据 Chat 工作区实际高度预算，为编辑器、工具栏及聊天记录保留空间；标题、附件、引用与工具栏高度纳入总量计算。
- 用户锁定的编辑器高度与插槽高度分别管理。空间不足时按布局预算限高，保留用户设定用于空间恢复后的布局。
- 分离窗口的内联面板按实际内容扩缩，并受屏幕工作区边界约束；短菜单和独立对话框分别处理可见性。
- 尺寸更新采用最终布局测量，合并快速连续变化；替换、折叠和关闭后的窗口尺寸能够收敛。

## 5. 实现结构与顺序

### 5.1 承载层与内容拆分

- 在 `MessageInput.vue` 的编辑器上方接入统一插槽容器。

- `MacroSelector`、`MiniSessionList`、`MiniToolCallingSettings`、`MiniCanvasControl` 复用已有独立内容组件，调整固定高度和窄宽度样式。
- Knowledge 提取独立内容组件，保留权限、加载/错误态、搜索与研究方式、选择及引用行为；核查其他调用后再决定兼容外壳。
- 输入设置提取独立内容组件，保留所有设置写入、自定义工具栏入口和原同步通道。

主要涉及 `components/message-input/` 下的输入容器、工具栏、业务面板及状态胶囊，以及 `stores/messageInputStore.ts`、`composables/input/useMessageInputResize.ts`。这些路径均相对 `src/tools/llm-chat/`，实施前继续读取直接调用方及分离窗口容器。

### 5.2 实施顺序

1. **插槽标准与首批迁移**：建立公共容器及单面板控制状态，接入宏变量、会话列表、工具设置；同步处理编辑器高度和焦点交接。
2. **其余持续面板**：拆分 Knowledge、输入设置的内容层，接入画布；保持现有保存、引用与高级入口。
3. **分离窗口与交互收口**：拆开内联面板和短菜单的尺寸处理，走查替换、折叠、关闭、窄窗口、输入法及两种编辑器。
4. **文档同步**：实现完成后更新 Chat 架构的输入区章节及本计划状态。
