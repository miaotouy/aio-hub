# Chat 输入工具栏自定义收纳调研

> 状态：已实施，验证完成
> 最近更新：2026-10-12
> 范围：桌面端 Chat 主窗口与分离输入窗口

## 1. 建议结论

采用「常驻操作 + 更多菜单 + 独立状态区」：每个系统操作可选择常驻或收纳，常驻项支持排序。默认布局保留少量聊天入口，用户也可恢复完整布局或建立自己的操作组合。

建议新用户默认常驻「附件、临时模型、Knowledge」，右侧保留发送与生成中的停止按钮；「更多」始终可见。Knowledge 的默认位置属于产品建议，可在界面走查时调整。

```text
常规聊天
[附件] [临时模型] [Knowledge] [更多]          [必要状态] [发送]

偏好写作的用户
[附件] [宏] [智能补全] [翻译] [更多]           [必要状态] [发送]

偏好工具工作流的用户
[附件] [临时模型] [工具调用] [上下文分析] [更多]  [必要状态] [发送]
```

以上为布局示意；系统操作使用现有图标，完整名称放在 tooltip 和菜单中。自定义快捷操作继续使用文字按钮。

## 2. 当前实现与问题

### 2.1 三种内容已经分离

| 区域 | 当前内容 | 当前控制能力 |
| --- | --- | --- |
| 底部系统工具栏 | 流式输出、宏、附件、Knowledge、切换会话、临时模型、更多、工具调用设置、工具栏设置、展开/收起 | 基本按模板固定排列；展开入口受窗口类型影响 |
| 更多菜单 | 智能补全、补全模型、翻译、压缩上下文、路径转附件、清理占位符、上下文分析、剪切/粘贴草稿、解除高度锁定、快捷操作管理 | 固定菜单；翻译按功能开关显示，多项有运行态禁用条件 |
| 快捷操作栏 | 全局、Agent、User Profile 引用的快捷操作组 | 支持启用项与按组分行，当前启用项平铺 |
| 右侧状态与发送区 | 临时模型、补全模型、画布、Token/上下文统计、发送、停止 | 状态按条件出现，Token 展示已有偏好开关 |

底部系统图标与上方文字快捷操作分属独立区域。本次自定义布局聚焦底部系统工具栏；文字快捷操作沿用关联配置、单项可见开关和按组分行偏好。

### 2.2 直接相关实现

- `components/message-input/MessageInputToolbar.vue`：布局、主窗口/分离窗口分支、发送/停止、快捷操作有效范围聚合。
- `components/message-input/toolbar/ToolbarMoreMenu.vue`：更多菜单与各操作禁用条件。
- `components/message-input/toolbar/ToolbarSettingsPopover.vue`：输入行为与展示偏好设置，目前弹层宽度为 240px。
- `components/message-input/toolbar/QuickActionsBar.vue`：启用的文字快捷操作平铺。
- `components/message-input/toolbar/ToolbarStatusCapsules.vue`：模型、画布、统计与相关状态操作。
- `components/message-input/KnowledgeReferenceControl.vue`：Knowledge 选择器及其自身弹层状态。
- `stores/messageInputStore.ts`：现有操作处理、多个弹层的开关状态；`chat-input-settings` 通过 `useStorage` 存储四个布尔偏好。
- `composables/settings/useChatSettings.ts`：`chat-settings.json` 的 ConfigManager 持久化与默认值合并。
- `composables/chat/useLlmChatSync.ts`：已经同步 ChatSettings；已有 `update-chat-settings` 主窗口动作入口。

当前系统工具区和底栏都有 `flex-wrap: wrap`。按钮较多或状态胶囊较长时会换行，输入区高度与操作位置随之变化。

## 4. 自定义交互

### 4.1 配置入口与编辑器

「更多」底部固定展示「自定义工具栏…」；工具区空白处右键可提供同一入口。原有「工具栏设置」可收纳到更多菜单，保留现有输入行为配置。

自定义面板使用 BaseDialog，提供系统操作编辑区，顶部给出实际布局预览。底部提供「简洁布局」「完整布局」「恢复默认」「取消」「保存」。

- 系统操作：左右两区「常驻」「更多菜单」。常驻项可拖动排序，也提供上移、下移，兼顾键盘操作。
- 收纳项：点击「常驻」即可加入；常驻项可点击「收纳」。在面板中完成管理，避免每行菜单塞进额外按钮造成误触。
- 简洁与完整布局为快捷填充操作，之后可以继续逐项修改；保存时写入最终位置与顺序。
- 面板内变更只更新局部草稿与预览；保存后生效，取消保留原布局。关闭前的行为与项目现有编辑型对话框一致。
- 搜索框用于筛选系统操作。

### 4.2 更多菜单

更多菜单按「聊天与资料」「输入处理」「会话与显示」分组，底部放「输入设置…」「管理快捷操作…」「自定义工具栏…」。空组连同分隔线一并省略。

- 可配置操作只在一个位置出现：常驻区或更多菜单。窄窗口下临时溢出的常驻项加入菜单顶部「常用操作」。
- 每个收纳项显示图标、完整名称和必要的当前状态；执行条件和原操作保持一致。
- 流式输出作为开关项，显示当前勾选状态。布局配置只改变入口位置，实际开关继续来自 ChatSettings。
- 宏、Knowledge、切换会话、工具调用等操作先关闭更多菜单，再打开各自面板。菜单里的入口与常驻入口共用面板和处理函数。
- 「输入设置」与「自定义工具栏」是管理入口，更多菜单中固定可达；用户可另将输入设置固定到工具栏。

### 4.3 独立快捷操作栏

快捷操作栏继续展示全局、Agent、User Profile 关联的快捷操作组，沿用模板内容和处理函数。每个操作的“操作区可见”（`isEnabled !== false`）决定文字按钮是否显示，“按组分行”偏好控制排列。

显式关联的操作组沿用重构前的显示规则，组级 `isEnabled` 值保持原有语义。快捷操作管理入口保留在更多菜单中，编辑器继续负责内容与单项可见性。

### 4.4 状态与宽度

- 发送与生成中的停止保持直接可达；更多入口始终可见。
- 临时模型、补全模型、已绑定画布及待处理变化属于影响当前操作的状态，沿用现有条件与清除/管理入口。模型名称可截断，tooltip 显示完整内容。
- Knowledge 已选资料继续使用现有引用 chips 告知用户；配置收纳只移动选择器入口。
- 收进菜单的工具调用入口在菜单中展示启用/接管状态；更多按钮可提供低干扰活动提示，详细状态在展开后呈现。工具审批提示沿用独立审批条。
- Token/上下文信息沿用既有展示偏好；受限宽度下优先压缩统计展示，为发送、停止和有效覆盖状态预留空间。
- 自适应收纳按用户排序从末尾开始，宽度恢复时还原。临时收纳只影响当前窗口渲染，保存的常驻顺序保持稳定。
- 全部常驻在足够宽时全部展示；确实放不下时进入更多菜单，避免工具栏无限换行。

## 5. 默认值与升级策略

建议新用户使用简洁布局：附件、临时模型、Knowledge 常驻，系统高级操作进入菜单，关联的快捷操作继续在上方文字按钮栏显示。

已有用户升级时保留现有系统入口顺序与快捷操作平铺方式，首次进入自定义面板后可一键切到简洁布局。此方案兼顾简洁默认和已有使用习惯；是否统一切换老用户的默认布局，属于发布前的产品决策。

允许系统常驻列表为空，此时仅保留更多入口和发送区。后续新增操作默认进入更多菜单，由用户决定是否固定。

## 6. 实现建议

### 6.1 统一操作描述与渲染

新增轻量操作描述表和布局 composable，放在 llm-chat 模块内；沿用现有项目 registry 风格与组件。

每个系统操作使用稳定 ID，集中描述名称、图标、菜单分组、操作类型（执行/开关/打开面板）及可用条件。运行状态从现有 store/props/context 派生。

常驻按钮与菜单项读取同一描述和处理入口。首批将现有底栏及更多菜单中的业务操作纳入；输入设置、快捷操作管理、自定义编辑器属于固定管理入口。避免为了移动入口复制两套补全、压缩或权限判断。

宏、会话和工具调用复用共享弹层宿主；Knowledge 与输入设置通过虚拟触发模式复用原组件。各面板共用打开状态协调与稳定锚点，Knowledge 的打开能力可由外部调用。收纳入口打开面板时以更多按钮或独立面板为稳定定位参考，菜单销毁后仍可继续使用。

弹层可见性接入 `anyMenuOpen`，关闭、展开、窗口拖动和 focus-return 延续现有输入区约定。分离窗口中继续使用现有主窗口动作路由处理高级设置和快捷操作管理。

### 6.2 配置结构

布局属于用户的桌面 Chat 偏好，建议放入 `ChatSettings.uiPreferences.inputToolbar`，复用配置管理和跨窗口同步。现有四个 `chat-input-settings` 布尔偏好维持原路径，实施范围集中在新布局字段。

```typescript
interface InputToolbarLayout {
  version: 1;
  // 持久化值只包含稳定操作 ID，名称/图标/运行状态从描述表读取
  pinnedActionIds: string[];
}
```

- `createDefault` 为全新配置提供简洁布局；`mergeConfig` 在发现旧配置缺失布局字段时保留原入口顺序和快捷操作平铺。
- 对新嵌套结构做显式合并与规范化：区分缺失字段和合法空列表，去重 ID，校验字段类型。未知 ID 跳过渲染并保留配置，方便版本回退后再升级。
- 主窗口保存新布局；分离窗口通过 `update-input-toolbar-layout` 动作请求更新，随后消费设置同步。读取 Tauri 持久化配置时遵循应用路径封装。
- 保存后生效，保存失败显示可行动错误并保留编辑草稿，用户可重试。一次确认一次保存即可；后续若加入即时拖动保存，再通过 ConfigManager 的 `saveDebounced` 处理。
- 旧布局配置中的 `quickActions` 展示偏好在规范化时清理，系统常驻 ID 顺序完整保留。快捷操作继续由独立操作栏显示。

### 6.3 实际实现入口

- `MessageInputToolbar.vue`、`ToolbarMoreMenu.vue`、`KnowledgeReferenceControl.vue`：共享操作入口及派生布局；`QuickActionsBar.vue` 直接接收关联操作组，沿用单项可见性与按组分行规则。
- toolbar 目录新增 `ToolbarCustomizeDialog.vue`、`ToolbarActionButton.vue`、`inputToolbarActions.ts`，共享弹层由输入工具栏协调；配置对话框挂载在 `LlmChat.vue`，输入区分离后主窗口仍保留配置入口。
- `types/input-toolbar.ts`、`config/inputToolbar.ts` 提供布局类型、预设、兼容解析和常驻/菜单分区；`useActiveQuickActionSets.ts` 统一有效操作范围。
- `useChatSettings.ts` 以 `saveInputToolbarLayout` 专用入口先持久化再发布布局，保存失败时当前布局保持原值；`useLlmChatSync.ts` 增加打开编辑器和保存布局的动作，沿用设置同步。
- `ToolbarSettingsPopover.vue` 继续承担输入行为设置，增加进入布局编辑器的入口或支持从更多菜单打开。

## 7. 建议实施顺序与验证

1. 建立统一操作描述、配置解析和兼容默认值；先覆盖系统按钮在常驻/菜单之间移动、排序及原操作行为。
2. 接入系统操作自定义面板和更多菜单分组。
3. 完成窄窗口溢出、弹层焦点交接与分离窗口体验走查。

前端验证使用当前脚本 `bun run build:tsc` 与 `bun run build:vite`。纯布局可用明确 mock 的浏览器场景辅助观察；分离窗口、文件对话框和主窗口动作路由在真实 Tauri 环境走查。

测试聚焦三类公开契约：有效常驻/菜单分区与排序；旧配置及合法空布局的解析；同一操作移动前后的执行/禁用规则及快捷操作有效范围。优先复用已有测试；新增用例应能定位真实回归，避免对组件内部拆分和展示文案做机械断言。

界面走查重点为：菜单中的选择器能继续操作；发送/停止始终可达；窄窗口恢复后顺序稳定；主窗口和分离窗口共享已保存布局。

## 8. 实施记录

- 新配置采用简洁布局，旧配置缺失新字段时保留原系统入口顺序和快捷操作平铺。
- 常驻系统操作可拖动排序、逐项收纳/固定；快捷操作栏保持独立。
- 更多菜单始终保留输入设置、快捷操作管理和布局编辑入口；宽度不足产生的临时收纳只影响当前窗口。
- 配置编辑器在主窗口打开，分离输入窗通过动作请求进入；保存结果沿现有 ChatSettings 状态通道同步。
- 已通过 3 个文件、11 项单元/组件回归，以及类型检查和 Vite 生产构建。
- 真实 Tauri 窗口已验证取消不写入、保存布局、宏/会话/Knowledge 选择器、Escape 关闭、受限工作区溢出收纳、分离输入窗请求主窗口编辑、保存后同步与重新附着。配置面板和悬浮输入窗已完成截图走查。

- 分离输入窗初始化尺寸已与设置加载分离；上游设置提前就绪时仍按渲染后的内容调整高度，避免工具栏被窗口裁切。
