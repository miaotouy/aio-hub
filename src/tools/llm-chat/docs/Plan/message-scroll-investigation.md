## 3. 当前滚动路径

- `LlmChat.vue` 将 `store.currentActivePathWithPresets` 交给消息区域。`MessageList.vue` 的滚动回调负责跟随状态、当前消息索引和阅读区刷新；这里没有按上翻动作发起历史分页请求。滚动时看到的历史“加载”主要涉及已有消息正文的延迟解析、挂载和显示恢复。
- `.message-slot` 保留消息行壳；`useMessageHeights.ts` 用实测缓存或估高维护 `contain-intrinsic-size`，通过共享阅读区控制 `content-visibility`。
- 底部跟随开启时，列表关闭浏览器锚定，由 `ResizeObserver → followBottom()` 和消息变化 watcher 驱动到底部。
- 上翻后暂停跟随，列表启用浏览器锚定，屏外消息的高度变化由浏览器补偿。
- 页面恢复、搜索和显式消息导航暂时保留消息相对锚点；后续滚动输入交还阅读位置控制权。

## 4. 已修复：代码块内部滚动误恢复底部跟随

### 原生复现

环境：隔离 Tauri/WebView2，1280×768，DPR 1.5，消息视口高 556 CSS px；60 条初始历史，后续追加诊断消息。

1. 最后一条消息显示可内部滚动的代码块，代码区共 250 行。
2. 暂停底部跟随，将外层列表停在距底部约 60px 的位置；代码查看器内部滚动位置为 0。
3. 鼠标移入代码查看器，使用真实鼠标滚轮向下滚动 100px。
4. 在底部追加一个普通完成态消息节点。

| 时点         | 外层 scrollTop | 代码区 scrollTop | 外层 overflow-anchor |
| ------------ | -------------: | ---------------: | -------------------- |
| 内部滚轮前   |      49635.332 |                0 | auto                 |
| 内部滚轮后   |      49635.332 |              100 | none                 |
| 新节点到达后 |      51351.332 |                — | none                 |

内部滚轮只移动了代码区，外层位置保持不变，但外层跟随状态已经恢复。新增节点后外层移动 **1716px** 并对齐列表底部。

同样的近底部停留状态，跳过代码区滚轮步骤直接追加消息，外层 `scrollTop` 保持 `50345.332`，`overflow-anchor` 保持 `auto`。这组对照表明，本次拉动来自滚轮触发的跟随状态变化。

### 原因

修复前，`useMessageScrollAnchor.ts` 的 `onWheel()` 接收列表内冒泡的所有滚轮事件。收到正向 `deltaY` 且 `isNearBottom` 为真时，立即设置 `shouldStickToBottom = true`。此时没有判断事件是否由内部滚动容器消费，也没有等待外层列表实际向下移动。

`MessageList.vue` 中后续消息长度变化和内容尺寸变化继续沿用该跟随状态，分别经 `scrollToBottom(true)` 和 `followBottom()` 拉到底部。原有测试覆盖普通上翻、回到底部和浏览器补偿；本轮扩展嵌套滚轮、事件取消与边界滚动链的行为契约。

### 实施与验证

- 沿滚轮事件路径检查内部可垂直滚动容器；内部仍可消费滚轮时，保留外层跟随状态并清除待恢复意图。
- 已被内部查看器取消默认行为的滚轮、缩放滚轮同样清除待恢复意图，避免后续布局补偿误恢复跟随。
- 在内部边界按 `overscroll-behavior-y` 处理滚动链：允许原生链传递时交给外层，`contain` / `none` 保持内部归属。
- 外层向下滚轮先记录意图，等外层实际向下移动到触底阈值内后恢复跟随。外层已触底时再次下滚可直接恢复；“到底部”按钮沿用原有显式操作。
- 单测新增契约覆盖内部上翻与下滚、已取消的事件、近底部实际滚动、边界滚动链和已触底恢复；本文件共 22 项用例通过。

修复后在隔离 WebView2 重放同类代码区场景：外层 `scrollTop` 在内部下滚 100px 前后与新增消息后均为 **37657.332px**，`overflow-anchor` 保持 `auto`，外层位移 **0px**。

另用原生嵌套滚动容器验证边界链传递：内部触底后继续下滚，外层实际移动约 49.336px 并触底，随后新增节点仍正确跟随到底部。代码查看器自身对边界滚轮的处理继续遵循其事件取消行为。

## 5. 导航器交互确认

调查观察到 `MessageNavigator.vue` 的透明热区命中滚轮；主人确认，鼠标进入该区域后导航器会显式出现，因此这属于可见导航区域的交互归属。本轮保留导航器和热区的现有实现，后续修复范围聚焦内部查看器与外层消息列表的跟随状态。
