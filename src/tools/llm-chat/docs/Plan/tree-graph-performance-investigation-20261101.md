# Chat 节点树模式性能复查（2026-11-01）

## 结论

本轮在合并上游 `dev` 后复查桌面端 `force-graph` 视图。**主问题是更新粒度：单节点正文、思考或状态变化，进入了覆盖所有节点、边与拓扑派生的 `updateChart`。优化目标应先收敛受影响集合，让局部变化沿局部路径完成。**

此前测得的三项开销属于这条全量链路的放大因素：

1. **Vue Flow 1.48.2 的节点标准化存在平方级空查找**：没有 `parentNode` 的普通节点，也会逐个扫描整批节点查找父节点。1000 节点的一次 `setNodes()` 中位耗时约 61.5ms；临时副本加判空后约 5.1ms。
2. **无附件节点的引用复用实际失效**：普通空数组兜底值与 Vue 深层代理后的数组比较，始终不相等。500 个无附件节点即使完全没有数据变化，刷新一次仍会更换 500 份 `data`；临时冻结该常量后更换数为 0。
3. **D3 计算数据进入 Vue 深层代理**：500 节点物理布局的一次 tick 中位耗时约 25.0ms；仅在临时副本中把模拟实例和 D3 节点、边数组改为 `shallowRef`，约为 2.1ms。

思考流按动画帧写回完整推理文本，又把全图路径反复唤起。首要工作是将节点展示更新与拓扑、路径、布局更新拆开；上述局部提速用于补充初次加载和确有需要的布局更新。按节点的展示更新、尺寸差量传递和 D3 深浅响应式边界已经落地；下一阶段处理结构变化中的布局影响集合与真实窗口复测。

本报告更新了 [2026-06-15 调查](./tree-graph-performance-investigation.md) 的部分判断。旧报告中的“阶段二完成”和“瓶颈不在 Vue Flow 或 D3 本身”需要结合本次实测重新理解。

## 1. 数据更新路径与高频触发

当前路径：

```text
正文批量 flush / 思考 requestAnimationFrame flush
  → session.nodes 的 content / metadata.reasoningContent
  → getGraphSessionWatchSource：全体节点排序、逐字段投影、附件签名
  → updateChart：拓扑指纹、深度、活动路径、全体节点与边派生
  → nodes.value / edges.value 更换数组
  → Vue Flow prop watch → setNodes / setEdges
  → 组件更新、尺寸同步、绘制
```

关键入口：

- `composables/chat/useChatResponseHandler.ts:113–157`：正文批量写回间隔为开启增量保存时 `max(250, incrementalSaveInterval)`，关闭时为 2000ms。
- 同文件 `215–226、280–295`：思考缓冲通过 `requestAnimationFrame` 合并，再写入完整 `metadata.reasoningContent`。它的频率取决于分块到达与动画帧调度，最高可接近逐帧；工具正文也有立即 flush 路径。
- `components/conversation-tree-graph/flow/FlowTreeGraph.vue:938–993`：watch 源读取全文及完整思考文本，对所有节点排序并投影。
- `flow/composables/useFlowTreeGraph.ts:372–618`：每次重新派生全图，最后提交新的节点、边数组。

### watch 与图数据转换实测

单位 ms；watch 与 `updateChart` 列为中位数，最后一列为“修改一次推理文本，等待 watch 回调与图数据更新”的 p95。

| -----: | -------: | ------------: | ---------------: | ---------------: |
|    100 |     0.15 |          1.01 |             1.28 |             3.70 |
|    500 |     0.82 |          6.00 |             7.84 |            11.63 |
|   1000 |     1.70 |         12.52 |            15.75 |            23.20 |

## 2. 无附件兜底数组使引用复用失效

位置：`flow/composables/useFlowTreeGraph.ts:49、95、149`。

```ts
const EMPTY_ATTACHMENTS: readonly any[] = [];
// ...
a.attachments === b.attachments;
// ...
const nodes = ref<any[]>([]);
```

`readonly` 是 TypeScript 类型限制；运行时该常量仍是普通可代理数组。节点写入深层 `ref` 后，旧 `data.attachments` 读出来是代理；下一次构造 `nextData`，兜底值又是原数组，严格引用比较失败。

独立复现：创建图，执行两次 `updateChart()`，中间保持会话数据完全相同。

| 100 个节点的附件字段           | 更换的 `data` 数 | 更换的 node 数 |
| ------------------------------ | ---------------: | -------------: |
| 省略 `attachments`             |              100 |            100 |
| 每个节点显式 `attachments: []` |                0 |              0 |
| 每个节点显式提供附件           |                0 |              0 |

另一次 500 节点对照中，仅在临时副本中将常量改为 `Object.freeze([])`，更换 `data` 的数量由 500 降为 0。正常节点创建入口 `composables/session/useNodeManager.ts:112` 直接采用 `config.attachments`，允许其为 `undefined`，因此这条路径具有实际可达性。

建议优先修复该常量的运行时身份边界，保持附件本身的响应式更新。直接把整个图节点数组改为浅响应式会同时影响坐标同步，需要另行设计。

## 3. Vue Flow 节点标准化存在 N² 空扫描

锁定版本及位置：`@vue-flow/core@1.48.2`，安装产物 `dist/vue-flow-core.mjs:4737–4767` 的 `createGraphNodes`。

第二轮遍历对每个节点执行：

```ts
const parentNode =
  findNode(node.parentNode) || nextNodes.find((n) => n.id === node.parentNode);
```

聊天图生成的节点包含 `id / type / position / data`，没有 Vue Flow 分组用的 `parentNode`。聊天的父子关系通过边表达。此时 `findNode(undefined)` 返回空，后面的 `find` 遍历全数组，N 个节点累计 N² 次比较。

使用真实 `useVueFlow()` store，在内存组件内测量 `setNodes([...nodes])`。临时对照只在父节点查找表达式前加 `node.parentNode` 判断，保留后续 `isParent` 处理。

| 节点数 | 当前比较次数 | 当前 p50 / p95（ms） | 判空副本 p50 / p95（ms） |
| -----: | -----------: | -------------------: | -----------------------: |
|    100 |       10,000 |          1.22 / 4.06 |              0.71 / 0.84 |
|    500 |      250,000 |        15.63 / 17.07 |              2.58 / 4.02 |
|   1000 |    1,000,000 |        61.49 / 65.83 |              5.15 / 9.31 |

判空副本中的上述比较次数均为 0。实测包含真实 store 的标准化，界面挂载与绘制仍在测量范围之外。

触发关系同样明确：安装产物的 prop watch 位于 `5780–5870` 附近，数组更新会进入 `setNodes / setEdges`。当前 `updateChart` 即使复用了全部元素，依然更换两份数组。因此修复附件引用后，全量提交的额外成本还会存在。

实施建议：

- 查验候选依赖版本是否已修正此表达式，确认后再决定升级；本轮没有核查远端版本。
- 若暂时维持锁定版本，使用包管理器维护的定点补丁。原型仅证明性能收益，正式补丁需保留分组父节点语义。
- 展示结果无变化时保持数组身份；只更新一个节点时，评估按节点提交的已有接口。节点更新与拓扑变化分开处理。

`only-render-visible-elements` 控制渲染规模，覆盖不到 `setNodes` 的这轮标准化，单独打开它仍会保留当前的 N² 路径。

## 4. D3 模拟数据的深层代理成本

位置：`flow/composables/useGraphD3Simulation.ts:113–115、252、378–391`。

模拟实例、`d3Nodes`、`d3Links` 均使用 `ref`。节点数组被交给 `sim.nodes(d3Nodes.value)` 后，D3 在每个 tick 内对坐标、速度、固定点与链接端点的大量访问会经过深层代理。

临时副本仅将该文件导入的 `ref` 替换为 `shallowRef`，保留输入图节点的响应式及坐标写回。以下为三叉树同一组数据的一次同步 `sim.tick()`，单位 ms，未计入坐标写回回调。

| -----: | ------- | -------------: | -------------------: |
|    100 | tree    |    1.26 / 2.50 |          0.20 / 0.46 |
|    100 | physics |    4.30 / 8.73 |          0.43 / 1.43 |
|    500 | tree    |    5.58 / 7.44 |          0.85 / 2.68 |
|    500 | physics |  24.97 / 28.65 |          2.13 / 3.83 |
|   1000 | tree    |  11.18 / 14.26 |          1.63 / 3.66 |
|   1000 | physics |  54.17 / 61.54 |          5.03 / 7.24 |

单独坐标写回中位耗时约为：500 节点当前 0.65–0.75ms，浅引用副本 0.50–0.52ms；1000 节点当前 1.35–1.55ms，副本 0.95–0.99ms。正式界面还会承担这些坐标变动带来的下游工作。

适合的边界是“D3 保有普通计算对象，Vue 接收明确的展示提交”。正式实施需同时处理：

- 保留单节点和子树拖动对 `fx / fy` 的写入及回弹行为。
- 调试态使用独立帧快照或修订信号。当前 `debugLinkPaths` 常直接从 `link.source / target` 对象读取坐标；改为浅引用后，仅复制 `d3Nodes` 数组不足以保证该 computed 每帧失效。
- 延续现有页面暂停、恢复与尺寸变化规则；静态布局保留一次性应用坐标的行为。

这部分收益来自响应式边界调整，原型没有更换力模型、降低 tick 数量或改变冷却参数。

## 6. 调查主线修正：让单节点变化沿局部路径完成

### 6.1 根因所在

当前的三个环节分别丢失了变更范围：

1. `getGraphSessionWatchSource` 把所有节点字段合成一个源，回调只知道“源变了”，没有变化的节点 ID 与字段类别。
2. `updateChart` 对内容更新同样计算拓扑指纹、深度图、活动路径、压缩映射以及全部展示数据；`isStructureChanged` 仅在末尾决定是否重新启动布局。
3. 节点与边最终总以新数组提交，局部内容变化也进入 Vue Flow 的全量标准化路径。

因此，修复引用比较、加节流或让全量函数更快，都无法单独解决更新粒度。图中有 N 个节点时，一次普通内容变化的展示计算应只取决于该节点的消息长度与自身派生字段；同一批 K 个脏节点的工作量应随 K 增长。

### 6.2 先明确各类变化的影响集合

| 变化                                   | 展示更新范围                                       | 拓扑与布局处理                       |
| -------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| 正文、思考、生成状态、错误、token 信息 | 当前节点；展示投影相同时跳过提交                   | 保持拓扑与坐标；真实尺寸变化另行通知 |
| 附件或角色、模型等展示元数据           | 当前节点；共享配置变动可按引用该配置的节点集合更新 | 尺寸改变时提交该节点的尺寸差量       |
| 切换活动分支                           | 新旧路径差异节点与边，加上新旧叶节点               | 沿父链计算路径，保持拓扑与已有坐标   |
| 普通节点启用、禁用                     | 当前节点的样式                                     | 压缩节点的启用状态需走下方压缩规则   |
| 压缩展开、折叠、成员变化               | 压缩代表、成员节点及受映射影响的边                 | 更新相关压缩映射，再判断布局需求     |
| 增删、嫁接、移动子树                   | 增删节点、相关边与深度改变的子树                   | 更新结构索引；按实际布局模型重新求解 |
| 会话切换、首次加载、历史整体恢复       | 新快照的节点与边                                   | 允许一次完整对账与布局初始化         |
| 主题全局变化、显式重置布局             | 主题影响全部展示；重置影响全部坐标                 | 保留明确的全局入口                   |

“只更新一个节点”的目标针对展示数据传播。节点实际增高时，碰撞和层高约束可能要求布局调整；力模拟也可能影响其他节点坐标，这些属于有效的跨节点依赖，应单独记录触发原因。单纯增加不可见的文本尾部且尺寸不变时，应停留在局部路径。

### 6.3 推荐的数据与订阅边界

**拓扑索引保持常驻，内容流使用按节点订阅。**

- 保存 `flowNodeById / parentById / childrenById / incidentEdgeIds` 等结构索引；增删与父关系变化时维护，普通正文更新直接复用。
- 成员监听只跟踪节点 ID 集合及容器替换；每节点监听自身的展示字段，父关系与压缩字段走单独分类。每次正文变化都运行 `Object.values(nodes).map(...)` 的全图投影会继续保留 O(N) 扫描，哪怕最后只提交一个节点也达不到目标。
- 节点订阅将 ID 放入脏集合，同一批次去重；只派生脏节点的展示投影。先比较摘要、状态和附件展示信息，再决定提交。
- 正文与思考的缓存分别维护。思考尾部增长且摘要保持原值时，局部比较完成即可；正文剥离思考标签仍遵循已有规则，不能简单对原文先截断。
- 现有流式处理和节点管理中存在直接属性写入，历史恢复还会整体替换 `session.nodes`（`useSessionNodeHistory.ts`）。按节点订阅可覆盖这些响应式写入；优先从图展示层建立边界，避免要求所有写入口同时改为专用事件或修订号。
- 删除节点时释放对应订阅；会话或快照替换时统一对账并清理旧队列。异步提交绑定会话身份，防止旧会话的脏节点在切换后写入新图。缓存页面暂停期间也暂停这些订阅的派生，恢复后补齐展示快照。

### 6.4 定点提交接口已经存在

锁定版 Vue Flow 的 `updateNodeData(id, data, { replace: true })` 通过节点索引查找目标，再更新其 `data`；它的函数体没有调用 `setNodes`。位置为安装产物 `dist/vue-flow-core.mjs:6656–6662`。普通内容更新可沿该接口提交，节点和边数组保留原身份。

组件适配时应使用当前图实例的同一份 Vue Flow store，并同步图展示层的节点缓存，保证下一次结构对账不会把旧 `data` 覆盖回去。仅给数组加等值判断仍会保留上游全量派生；仅改成 `updateNodeData`，却继续为所有节点构造新数据，也只完成了一半。

尺寸传播采用相同边界：组件直接消费 Vue Flow 的尺寸变更批次，只把实际变化的节点交给 D3；D3 通过节点索引更新目标，不再逐次扫描全部模拟节点。尺寸数值变化后仍按布局模式决定是否刷新碰撞约束或静态层高。

### 6.5 局部链路原型：验证工作量随脏节点数变化

新增临时原型 `.tmp/graph-perf-probe/incremental-probe.ts`，初始化仍使用当前图转换函数，更新时使用：

```text
目标节点字段变化
  → 该节点订阅
  → dirtyNodeIds 合并
  → 该节点展示派生与等值比较
  → updateNodeData(id)
```

使用真实 Vue 订阅与 Vue Flow store，分别创建 100、500、1000 节点。三种规模下，下表计数一致：

| 操作                           | 节点订阅回调 | 派生节点数 | 定点展示提交 | setNodes / setEdges | 改变 data 的节点数 |
| ------------------------------ | -----------: | ---------: | -----------: | ------------------- | -----------------: |
| 一个节点的可见正文改变         |            1 |          1 |            1 | 0 / 0               |                  1 |
| 思考尾部追加、展示摘要保持原值 |            1 |          1 |            0 | 0 / 0               |                  0 |

### 6.6 正式链路已经落地

`FlowTreeGraph.vue` 现在只监听会话身份、活动叶、节点 ID、父关系及压缩结构。每个节点独立监听正文、思考、状态、错误、token、模型信息与附件展示字段；变化先进入 `dirtyNodeIds`，同一批次只派生一次。

- 展示派生集中到 `createNodeData`，结构更新保存活动路径、深度与压缩上下文，局部更新复用同一套规则。
- 真正变化的 data 通过当前 Vue Flow store 的 `updateNodeData(id, data, { replace: true })` 定点提交，同时同步图层的节点缓存。
- 结构未变化时不替换节点、边数组；边样式没有差异时也不提交边数组。
- 活动叶改为独立监听；分支切换时只计算新旧活动路径的差集，仅派生差异节点，并通过 `findEdge` 更新与差异节点相邻的边，节点和边数组保持原身份。
- 压缩展开与折叠只更新摘要节点的 `isExpanded`，并替换映射发生变化的成员连接边；未受影响的节点、边保持原引用，节点数组不重新提交。
- 无附件节点的空数组改为冻结常量，未变化节点继续复用原 data。
- Vue Flow 尺寸变更通过 `onNodesChange` 按 ID 收取，D3 模拟实例、节点和边数组改为 `shallowRef`。

相关行为回归覆盖了单节点更新隔离、同批写入合并、思考摘要不变时跳过提交、活动分支的节点与邻边差量、压缩展开的连接边重建以及未变化节点 data 复用。类型检查、相关单测、Oxlint 与 Vite 生产构建通过；真实 Tauri 窗口中的交互和 FPS 对比仍待验收。
