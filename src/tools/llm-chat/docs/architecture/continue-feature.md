# LLM Chat 续写与补全功能说明文档

本文档描述了 LLM Chat 工具中的“续写 (Continue)”与“输入补全 (Input Completion)”功能的架构与使用方式。

## 1. 功能概述

该功能旨在解决长文本生成中断、内容增量补充以及写作辅助等场景。它包含两个核心维度：

1.  **消息续写**: 在对话历史中的任意消息节点基础上继续生成。
2.  **输入补全**: 在输入框撰写过程中，请求 AI 协助完成后续文本。

## 2. 消息续写 (Message Continuation)

### 2.1 交互入口

- **位置**: 消息操作栏 (`MessageMenubar.vue`) -> 更多菜单 (`MoreHorizontal`)，可通过“自定义工具栏”固定到常驻区。
- **选项**:
  - **续写消息**: 使用当前智能体或临时指定的模型从该节点继续生成。
  - **选择模型续写**: 弹出模型选择器，指定特定模型进行续写。

### 2.2 用户配置

在「聊天设置 → 续写设置」中调整，自动保存并应用于后续发起的助手正文续写。

| 设置              | 默认值       | 作用                                                                                       |
| ----------------- | ------------ | ------------------------------------------------------------------------------------------ |
| 续写方式          | 自动选择     | 优先使用物理模型支持的原生前缀续写；可改为始终使用提示词，以兼容不同网关或调整接续效果。   |
| DeepSeek 思考模式 | 跟随模型     | 可为本次 DeepSeek 续写指定开启或关闭，覆盖模型扩展参数中的思考开关。其他模型沿用自身参数。 |
| 续写提示词        | 内置接续指令 | 自定义提示词模式的续写要求。系统始终在指令末尾附上精确原文锚点，清空后使用默认指令。       |
| 末尾定位长度      | 1200         | 锚点长度，范围 100–16000 个 UTF-16 代码单元；完整原文仍通过正常上下文发送。                |
| 去除开头重复内容  | 开启         | 统一处理流式与最终正文的开头重复；关闭后将返回正文逐字追加。                               |

设置在请求开始时形成快照，生成过程中修改设置应用于下一次续写。续写模型继续通过消息操作或输入栏的模型选择入口指定。DeepSeek Beta 使用渠道现有配置。

### 2.3 实现原理

1. **分支创建**：调用 `nodeManager.createContinuationBranch`。
   - Assistant 续写创建兄弟节点，初始正文复制自原节点，原分支保持原样；`continuationPrefix` 保存接力前的全文。
   - User 续写创建空白 Assistant 子节点，按原有对话上下文接话。
2. **请求定位**：`useChatHandler` 设置 `isContinuation: true`，执行器按上下文消息的来源 ID 标记实际 Assistant 节点。尾部世界书或其他注入保持原顺序。
3. **物理模型适配**：`useLlmRequest` 在渠道选定物理模型后调用 `prepareContinuationMessages`，结合本次续写方式与该模型的 `prefixCompletion` 能力选择请求形式。
   - 原生前缀续写要求标记节点处于消息列表末尾。DeepSeek 渠道缺省采用原生模式，显式能力配置优先；Beta 偏好默认开启，继续由现有端点路由处理。
   - 通用续写保留上下文和完整原文，追加一条 User 指令，以原文末尾配置长度（默认 1,200 个 UTF-16 代码单元）作为精确锚点，要求从最后一个字符之后补完句子、代码或其他未闭合结构，仅输出新增正文。
   - Responses 协议采用通用续写。若原文后还有上下文注入，同样采用锚点指令定位接缝。
4. **跨模型接力**：续写输入以已有正文为依据，当前节点的旧思考记录在请求准备时清理。思考开关默认沿用本次模型参数，可通过续写设置覆盖本次 DeepSeek 开关，并通过顶层 `thinking` 字段发送；模型的工具回放与其他历史消息沿用既有策略。
5. **接缝合并**：执行器将本次去重策略固定到节点元数据。`ContinuationTextFilter` 统一处理流式正文与最终响应。完整原文重输出、原文末尾至多 4,096 个代码单元内长度至少 16 且含至少 8 个文字或数字的精确重叠只保留一份；短尾词、空白和代码符号保留原样。仅匹配返回开头，后续正文按原样追加。候选接缝尚未确定时暂存开头，完成或中断时统一收尾，确保显示、保存和跨窗口增量一致。

## 3. 输入框补全 (Input Completion)

### 3.1 交互入口

- **位置**: 输入框工具栏 (`MessageInputToolbar.vue`) -> 更多工具 (`MoreHorizontal`)。
- **功能**:
  - **智能补全**: 触发 AI 对当前输入框内容的补全。
  - **指定补全模型**: 允许用户为补全功能设置一个独立的模型（不同于当前对话智能体），设置后会在工具栏显示星形图标 (`Sparkles`) 标识。

### 3.2 实现原理

1.  **独立请求**: `useChatHandler.completeInput` 发起一个不创建 Chat Node 的临时 LLM 请求。
2.  **上下文构建**:
    - `system`: 引导模型作为写作助手，仅输出补全部分，不要重复输入。
    - `user`: 传递当前输入框的文本内容。
3.  **结果回填**: 获取响应后，将文本直接追加到 `inputManager` 绑定的变量中。

## 4. 技术细节

### 4.1 协议定义 (`src/llm-apis/common.ts`)

```typescript
export interface LlmMessage {
  role: "system" | "user" | "assistant";
  content: string | LlmMessageContent[];
  /**
   * 是否作为续写前缀 (DeepSeek / Claude Prefill)
   * 如果为 true，该消息必须是列表中的最后一条，且 role 通常为 assistant
   */
  prefix?: boolean;
}
```

### 4.2 状态管理 (`src/tools/llm-chat/stores/llmChatStore.ts`)

- `continueGeneration(nodeId, options)`: 封装了续写逻辑的调用与生成状态管理。
- `completeInput(content, options)`: 封装了补全逻辑并将结果写回输入管理器。

## 5. 注意事项

- **Token 统计**: 续写的前缀内容在计费时被视为 `prompt_tokens`。系统在预估时已将其包含在内。
- **模型兼容性**: 并非所有模型都完美支持 `prefix` 模式。在不支持的模型上，系统会回退到基于 Prompt 引导的“模拟续写”模式。
