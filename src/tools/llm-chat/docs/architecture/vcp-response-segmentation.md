# VCP 上游响应分段

VCP 文本渠道的流式 Chat Completions 请求，可以在一次 HTTP 响应内执行多次模型生成和工具调用。聊天执行器将这些阶段实时写入同一分支的消息节点：

```text
用户 → assistant 回复／工具请求 → tool 结果或摘要 → assistant 后续回复
```

## 启用与事件链路

- 聊天设置 → 通用设置提供「VCP 消息拆分」开关（`uiPreferences.splitVcpResponses`），默认关闭；旧配置通过默认值合并补齐。
- 开关开启时，沿用 `resolveChannelToolHandling()` 的渠道识别结果，仅对上游消费 `vcp-text` 的流式聊天请求启用。关闭时沿用单节点回复与原有文本／推理回调。
- 每次请求开始时读取开关，修改后从下一次请求生效；已有消息节点保留原样。
- 启用拆分时，`useSingleNodeExecutor` 注册 `onResponseChunk`，并请求 `stream_options.include_usage`。OpenAI Chat 适配器将该观察回调映射为 llm-core 的 `captureResponseChunks`；这个内部选项留在解码侧。
- llm-core 按需提供 `response-chunk` 事件，包含响应 ID、正文、独立推理、完成原因和用量。普通文本／推理事件与最终 `completed` 契约保持原样。
- 未提供这些事件的适配器沿用原有单节点处理，包括经过 Responses、Anthropic、Gemini 协议桥的请求。

## 分段规则

`core/tool-calling/vcp-stream-segmenter.ts` 消费已解码的完整 SSE 数据：

1. 上游 `finish_reason` 标记一次模型生成结束；紧随其后的 usage 归到该 assistant 段。
2. VCP 服务端生成的 `chatcmpl-vcp-batch-*` 整批结果，以及历史 `chatcmpl-vcp-<数字>`／`chatcmpl-vcp-summary-*` chunk 进入 tool 段；角色围栏与 separator 控制阶段切换。上游未提供完成原因时，工具 chunk 也能建立阶段边界。
3. 工具区后的模型正文／独立推理创建新的 assistant 段。重复使用响应 ID 的上游也按阶段拆分。
4. `chatcmpl-VCP-final-*` 是请求的最终完成信息，最终 `[DONE]` 仍由通用 decoder 处理。
5. 模型正文中的标记示例保留在原段；角色围栏只根据服务端 chunk 来源识别。VCP 注入的 reasoning 闭合标签保留在前一个 assistant 段。

## 节点与请求生命周期

- 首段复用原 assistant 节点，后续段通过节点管理器追加为其后代。当前活动叶子仍是上一段时，随分段推进；已选中的排队叶子或其它分支保持选中。
- 后续段插入到排队消息之前：合并模式移动带排队标记的 user 子树，链式模式移动包含排队 assistant 占位节点的 user 子树。整条排队链保持顺序，分支选择记忆同步更新；生成标记转移到新段后，排队节点的祖先路径仍包含当前请求，直到请求结束才恢复调度。
- 加载或导入历史会话时，`metadata.vcpResponse.kind === "tool"` 的节点恢复为工具角色；正文中的角色围栏示例保持原消息身份。
- 每段在 `metadata.vcpResponse` 中记录原请求 ID、段类型和可用的上游完成信息；每个 assistant 节点分别保存 usage 和生成计时。首段沿用 HTTP 请求起点，后续段以服务端工具结束／分隔 chunk 的到达时间作为可观测起点，旧服务端回退到最后一条工具内容 chunk；首字时间记录各段第一条正文或推理，结束时间优先采用该段完成标记。
- 生成速度、首字延迟和总耗时显示在消息底部，与 Token 统计并列；各项按可用数据独立展示，性能指标开关与 Token 统计开关独立生效。
- 仅保存各段正文，最终合并响应用于请求返回；会话树中的历史按各节点各回传一次。
- VCP tool 卡片从节点原文提取批次与旧结果框，将工具名称、状态和纯文本返回值合并到卡片自身的头部与结果区；多工具结果平铺排列，统一使用外层折叠。普通正文和未完成批次按纯文本展示，折叠预览提取返回内容或摘要；工具结果 chunk 收到后同步写入节点，确保首帧展示已有内容；assistant 正文继续通过 StreamSource 渲染，节点正文按持久化间隔写入。
- VCP tool 节点在上下文管道中转换为 user 文本，以匹配 VCP 的工具结果注入方式。
- 所有新增节点共用原请求的 AbortController。阶段切换刷新流缓冲；失败时保留已收到内容，错误归到活动段；请求结束后统一清理生成状态。
- 上游未给出有效 usage 时，沿用已有本地 token 估算。后续轮次估算纳入先前可见回复与工具结果；服务端隐藏的上下文处理可能导致估算与真实账单存在差异。

## 可见结果边界

关闭 VCP 详细结果展示时，tool 节点保存服务端发来的摘要；详细结果块出现时一并保存。现有协议的摘要与展示文本可能省略工具返回字段，节点内容以实际收到的数据为准。

### 带时间戳的返回批次

`chatcmpl-vcp-batch-*` 正文按原样逐段累积，保留 `VCP_TOOL_BATCH_START/END` 和外层角色围栏。工具返回中引用的角色标记同样保留，流式正文可以在任意标记位置拆包。富文本渲染侧统一完成精确时间戳边界匹配和正文隔离，整个批次展示为工具返回容器，截断批次显示未完成状态。

旧摘要 chunk 沿用工具状态提取；新批次正文在执行与持久化层保持隔离；展示侧可将完整旧结果框与摘要投影为结果卡片和去重摘要，结果值保持纯文本，工具状态元数据沿用收到的正文。协议细节见 [工具返回批次](../../../tool-calling/ARCHITECTURE.md#426-服务端工具返回批次)。
