# 聊天 DOM 驻留归因与下一轮方向

> 日期：2026-10-27
>
> 范围：真实 Tauri 性能构建，离线本地真实会话回放；本轮完成归因与脚手架补充，生产挂载策略保持原样。

## 1. 语料可读性复核

旧提取器显式按 UTF-8 读写文件，但对正文逐词生成随机汉字。最小中文输入经 UTF-8 写入、严格解码、读取后完全一致；经过旧替换器后则变成难以阅读的汉字串。这是替换策略的效果。

本轮新增 `readable` 模式：保留普通中文、数字、代码标识符和扩展协议标记，定向处理常见凭据、联系方式与本机路径。工具参数中的敏感字段值另外直接替换。外部资源、HTML 活动内容、身份与附件处理沿用已有边界。`masked` 保留用于复查旧结构压力；历史语料和结果保持原样，新提取默认 `readable`，运行时显式通过 `--corpus` 选择。

**可读模式属于本机私有测试语料。** 自动处理覆盖常见敏感模式，正文可能仍有姓名、私人语境和其他未识别信息；上传、提交或分享前需要人工审阅。测量日志和报告只输出结构统计，正文保留在 Git 忽略的本地目录。

可读语料的 8 组源会话结构统计与旧版一致。两种模式改变了渲染输入，测量结果分开解释。

### 网名与特定指代抽查补充

按短片段抽查可读语料后，另存 `corpus-readable-entities-20261027.json`；本地替换表为 `entity-replacements.local.json`，均位于 Git 忽略的 `.tmp/app-memory/`。43 条等 UTF-16 长度规则中有 40 条命中，累计替换 602 处，涉及 111 个文本字段；覆盖已识别的群聊网名、账号变体、角色及设定指代。单字网名按发言标签或 @ 提及替换，普通句子保持原样。

8 组样本的回放结构统计保持一致，382 个非空正文、推理和译文字段的静态 AST 类型序列一致，UTF-8 严格解码往返通过。规则只覆盖人工识别的词项，正文仍限本机使用。下文测量保留原可读文件；后续优化对照统一指定新文件，静态解析复核与真实窗口测量分别记录。可复用提取参数见 [内存测试文档](../../../../../docs/Plan/app-memory-workload-matrix.md#定向指代替换)。

### 扩展语法受损的具体证据

`long-answer` 的聊天消息区从旧模式约 40,644 DOM 节点变为可读模式的 12,927 节点。对最长正文单独使用当前 `CustomParser` 静态解析：

| 模式     | 输入字符 | 顶层块 | VCP 工具节点 | VCP 角色节点 |
| -------- | -------: | -----: | -----------: | -----------: |
| masked   |  316,760 |     64 |            0 |            0 |
| readable |  316,539 |     27 |           16 |            2 |

旧模式破坏了扩展语法标记和字段识别，工具内容回退到普通文本 / 代码等路径。这个样本说明字符长度与 Markdown 标点相近仍不足以保证真实渲染工作量。解析对照仅覆盖最长正文；真实聊天还包含宏、资产与 renderer 的预处理。以实际运行态统计作为后续选样依据。

## 2. DOM 探针口径

`bun run perf:memory` 增加可选 `--dom-census`：在指定阶段的测量检查点完成后，另存 `*-dom.json`，记录 document、聊天工作区与消息区的节点 / 标签 / 子树规模，以及按索引排列的消息复杂度。记录数量和角色类别，省略正文、消息 ID、文件路径与标题。

- 对每个类别只累计最外层匹配子树，嵌套列表内部沿同一类别去重；不同类别之间可重叠，禁止直接相加作总数。
- 通过 WeakRef 记住消息区，返回首页后继续观察 KeepAlive 子树，避免探针自身强引用维持整个页面。
- 常规 `document.querySelector` 看不到 KeepAlive 的脱离文档子树；CDP 全局 DOM 计数则还包括缓存树、其他 document 和未回收节点，二者分别报告。
- 生产构建未暴露 Vue 组件元数据，本轮组件计数为不可用；DOM 数量不能换算成准确的组件实例数。
- census 会扫描 DOM 并产生临时对象，本轮用于结构诊断。检查点在扫描前采集，但扫描可能影响后续 GC 与运行状态；数据与关闭探针的正式性能时序分开看。

另增 `--empty-switch-probe`：在原有末轮 GC 之后回到聊天、切换空会话、静置并再做一次页面 GC，作为终端诊断阶段。正常往返阶段保持原有含义。

## 3. 可读语料真实窗口结果

三类样本、特效关闭、各一个独立进程和一次往返。预热 4 秒，测量 / 冷却 8 秒，滚动 12 秒。3 个案例全部完成，23 个检查点有效，图表 / 图片错误计数为 0。聊天中没有发起真实模型或工具请求。

| 样本        | 消息槽位 | 消息区节点 | 富文本子树节点 | 最大消息节点 | 返回首页 GC 堆 MiB | 全局 DOM |
| ----------- | -------: | ---------: | -------------: | -----------: | -----------------: | -------: |
| branches    |       51 |     74,212 |         67,754 |        8,349 |              223.5 |  109,011 |
| rich-text   |        4 |     17,065 |         16,598 |       14,637 |               76.8 |   27,753 |
| long-answer |        8 |     12,927 |         11,908 |        7,449 |               83.2 |   25,588 |

槽位包含工具等特殊行，和普通聊天消息 testid 计数分别解释。`branches` 返回首页后弱引用仍能读到 74,191 个消息区节点，`rich-text` 为 17,063，`long-answer` 为 12,896。这与主布局对聊天页启用 KeepAlive 的实现一致。

### branches 的内容分布

| 子树       |          根数量 | 节点数 | 相对消息区 |
| ---------- | --------------: | -----: | ---------: |
| 列表       | 276，最外层 224 | 22,134 |      29.8% |
| 表格       |              58 | 10,216 |      13.8% |
| 图表       |              18 |  8,428 |      11.4% |
| 代码块整体 |              67 |  7,472 |      10.1% |
| 代码块头部 |              67 |  4,020 |       5.4% |

代码块头部属于代码块整体，其他类别也可能互相嵌套。这份会话的剩余主成本已超出代码编辑器范围。列表 / 表格与图表共同构成需要治理的内容规模。

选样标签也需复核：当前 `rich-text` 的“400 处表格结构匹配”为文本启发式统计，实际只渲染 2 个表格，最大的一条用户消息独占约 85.8% 的消息区节点。后续富文本密集选样应以实际 AST / DOM 特征复核，单条超长消息和多消息累计分别处理。

## 4. 切空会话的终端诊断

追加一个 `branches` 独立进程案例，预热 / 测量同上，滚动 8 秒；10 个检查点有效，图表 / 图片错误为 0。

| 阶段          | 页面堆 MiB | CDP 全局 DOM | Private 尾值 MiB |
| ------------- | ---------: | -----------: | ---------------: |
| 返回首页并 GC |      223.3 |      109,011 |            950.3 |
| 切空会话并 GC |       70.7 |       13,977 |            634.7 |

页面堆减少约 152.6 MiB，全局 DOM 减少 95,034。说明大量驻留与当前复杂会话绑定的展示对象及其关联状态有关；当前测量尚未将 AST、VNode、组件、菜单与会话缓存的堆占比单独拆开。本轮未采堆快照，也未测长期累计增长。

### document 中还留着菜单与浮层

返回首页并 GC 时，document 本身有 33,702 个节点，其中 `.el-popper` 最外层子树合计 **25,742** 个节点，约 76.4%。菜单和工具提示属于这批浮层的子集：

- 110 个 dropdown-menu 根，12,407 节点。
- 73 个 tooltip 根，10,145 节点。
- 切空会话后 popper 子树降为 8,610 节点，仍有首页和聊天其他控件。

此轮只浏览正文 / 推理，未打开消息操作菜单。源码中 `MessageMenubar.vue` 的更多操作 Popover、`MessageToolbarAction.vue` 的翻译 Dropdown 分别为每条消息创建；本机 Element Plus 的 Popover / Dropdown 默认 `persistent: true`。这些入口是下一步缩减关闭态菜单子树的具体排查对象；上述总量尚未按每种控件归属精确拆分。

## 5. 下一轮落点

1. **优先验证消息操作菜单的按需挂载。** 聚焦 `MessageMenubar.vue`、`MessageToolbarAction.vue` 的浮层内容，验证未打开、打开、关闭、重新打开、键盘焦点、翻译操作和分支操作；保留完整工作区和现有按钮。先用相同可读 `branches` 采前后 popper、全局 DOM 与 GC 堆，再决定是否推广。
2. **再评估非活跃页静态渲染树卸载。** 保留会话数据、滚动位置和消息高度，离开页面后回收静态展示；进行中的发送、翻译、编辑与弹窗需明确保护。重新激活时恢复内容与滚动锚点，避免整体取消 KeepAlive 引入其他工具回归。
3. **活动页历史消息按视口治理。** 多消息优先在 `.message-slot` 保留外壳和高度，回收内层展示；保留当前交互、流式行和截图模式。现有导航依赖 `.chat-message` 与 `[data-message-id]` 的 DOM 定位，需要同步接入挂载后定位。单条巨型消息随后评估顶层块挂载，先用当前 `rich-text` 的单行密集输入验证。
4. **选样和协议保真继续修正。** 以 AST / 实际挂载结果补充表格、列表、VCP、图表形态；逐词掩码模式只做旧结果复查。原图尺寸、HTML 活动内容与媒体保真仍沿用原限制。

本轮修改测试脚手架和文档，继续使用上一轮的性能二进制。脚本类型检查通过；相关 5 个测试文件共 16 个用例通过，新增断言保护中文 / VCP 在 UTF-8 落盘后的保真、定向敏感字段处理，以及 DOM 嵌套类别去重和脱离文档缓存统计。
