>

## 目标与现状

当前 V2 使用 `CustomParser` 生成 AST，并通过流式处理器与 AST Patch 更新界面。已有测试覆盖 VCP、附件占位符和局部 AST 更新；交互测试台提供模拟流式输入。规范用例、可复现的解析对比与性能采样需要补齐。

按以下顺序推进，每一项完成后在本文回写入口、结果和后续发现。

## 已确认的产品约定（2026-10-25）

- **段落内单次回车产生可见换行**。主人明确偏好输入时的换行在显示时保留，后续兼容性修补应保护这一行为。空白行继续表达段落分隔。
- 同输入库对照使用相同换行策略，例如 `markdown-it` 的 `breaks: true`。官方默认输出差异与项目行为契约分别统计；修复优先级按内容正确性和实际影响安排。
- **文本末尾回车是否显示尾部空白行**仍待单独确认，当前行为保留；段内可见换行与末尾空白行分开讨论。
- 首轮 20/652 是严格静态 AST 比较的历史结果，包含预期的产品行为差异。后续报告需要显示产品配置与差异分类；该历史比例用于定位，质量评估结合具体问题。

## 第一项实施记录

### 运行入口

在仓库根目录运行：

```powershell
bun run rich-text:commonmark
bun run rich-text:check
bun run test:run -- scripts/rich-text/commonmark.test.ts
```

报告默认写入 `.tmp/rich-text-commonmark/report.md` 与 `.tmp/rich-text-commonmark/report.json`。可通过 `--out-dir <路径>`、`--timeout-ms <毫秒>` 调整输出目录与单例超时，默认 2000 ms。日常运行使用已入库的用例，离线可重复执行。

实现位于 `scripts/rich-text/`，复用现有 jsdom 依赖。官方 HTML 使用惰性 DOM 片段转换为语义树；实际 AST 直接映射，避免浏览器自动修复实际树而掩盖嵌套差异。解析在独立 Worker 中串行执行，每条输入有超时保护，超时后重建 Worker 并继续。启动失败或比较器内部异常使命令失败；规范差异、解析异常与超时计入报告。

脚本使用独立 TypeScript 配置，根 `tsconfig.node.json` 排除该目录，由 `rich-text:check` 连同被引用的解析代码进行检查。

首轮已定位的代表性差异：

- **换行策略**：普通段内换行转换为可见换行已确认为产品约定。Example 650–652 额外涉及文本末尾的 `hard_break`，末尾空白行单独待确认。
- **代码块末尾 LF**：Example 119 的实际代码内容缺少官方预期保留的末尾换行。此项保留为严格文本差异，后续确认 AST 内容契约。
- **列表语义**：Example 301 暴露紧凑列表的段落包装差异；当前 `parseList` 也尚未将有序列表的起始数字写入 AST。
- **引用式链接**：Example 192 的引用定义与链接用法和官方预期存在结构差异。
- **数学扩展交界**：Example 12、18、19、143 产生 `katex_inline` / `katex_block` 节点，计入适配器待支持，JSON 中保留原始 AST；后续结合反斜杠转义和代码围栏规则分析。

## 差异复核：已确认的修复候选（2026-10-25）

本次用最小输入直接调用当前 `CustomParser.parse()`，并以已安装的 `markdown-it("commonmark", { breaks: true })` 对照，排除了单次回车策略造成的主干差异。同时阅读对应解析代码与节点组件确认写入/展示链路。复现脚本位于忽略目录 `.tmp/rich-text-commonmark/triage.ts`、`triage-extra.ts`，下方记录可独立复现的输入与结果。本轮完成调查与记录，修复任务仍待实施。

### 优先修：代码内容与围栏边界

- [ ] **围栏长度错误导致后文错归属**。输入如下，预期是一个包含内部三个反引号的 `md` 代码块，随后为正文 `after`：

`````text
````md
```
inside
```
````
after
`````

实际产生多个错误分块：首个代码块内容为 `` `md ``，`inside` 成为正文，最后的代码块包含四个反引号和 `after` 且被标记为未闭合。起止围栏需记录字符种类与长度，结束围栏应匹配对应规则。定位：`parser/Tokenizer.ts` 的 `RE_CODE_FENCE_OPEN` 及结束围栏扫描。

- [ ] **语言标记混入代码正文**。输入：

````text
```c++
int n = 1;
```
````

实际语言为 `c`，代码正文前多出一行 `++`。这会改变用户查看、复制的代码内容。语言/信息字符串应与正文分离。当前开头正则仅接受 `\w*`。

- [ ] **波浪线围栏缺少支持**。`~~~js` 包裹的代码当前成为普通段落。与长度规则一起补齐，避免代码进入普通 Markdown/公式解析。

### 优先修：列表结构与编号

- [ ] **列表项内的续段脱离列表**。输入：

```markdown
- first

  continuation

- second
```

预期 `continuation` 属于第一个列表项；实际成为根级段落，并将后续列表拆成另一个根节点。`parser/block/parseList.ts` 遇双换行直接结束当前项，尚未结合后续缩进判断列表项续段。该问题影响列表归属，与紧凑列表的段落间距策略分开处理。

- [ ] **有序列表起始数字丢失**。`3. third` 换行接 `4. fourth`，实际 AST 只有 `ordered: true`，缺少起始数字。另一个独立缺口是 `components/nodes/ListNode.vue` 虽声明 `start`，模板尚未绑定 `<ol start>`。修复需同时贯通 token → AST → 实际列表元素。

### 随后补齐：链接与字符内容

- [ ] **引用式链接缺少解析**。输入 `[foo]: /url "title"`，空行后 `[foo]`，实际将定义与引用都显示为普通文本；预期定义被消费，引用产生链接。定位：块级定义收集与内联引用解析目前缺少对应路径；后续还需处理前向引用和流式定义补全。
- [ ] **正文字符实体原样显示**。输入 `&amp; &#35; &#x4e2d;`，实际文本内容仍为这三个编码串，预期可见内容为 `& # 中`。`TextNode.vue` 输出 Vue 文本节点，后续渲染也会保留这些编码。补齐普通 Markdown 文本的命名/数字实体解码，代码内容继续按字面值保留；解码结果仍通过文本节点输出，防止 `<` 等字符被重新解释为 HTML。现有 `decodeHtmlEntities` 主要用于 HTML 内容且只覆盖少数命名实体，需先确认复用边界。

### 暂缓或继续核实

- 四空格缩进代码当前成为普通段落，属于后续兼容性补齐项，优先级排在围栏截断、内容污染与列表归属之后。
- 紧凑列表的 `<p>` 包装、代码块末尾 LF、无标题链接的 `title: ""` 与属性省略，先结合组件展示与 AST/导出契约区分显示策略、比较器噪声和实际缺陷。
- 普通反斜杠转义、`***both***`、含反引号的双反引号行内代码、带标题链接、URL 中平衡括号与基本嵌套列表，在本次最小复现中主干语义正常；其余规范用例仍逐例判断。
