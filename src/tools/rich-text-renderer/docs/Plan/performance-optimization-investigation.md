### 现有机制与剩余边界

- `RichTextRenderer.vue` 使用 V2 处理器与单树 AST Patch；AST 为浅引用，更新按 rAF 合帧。分词 Worker 之外的解析、diff、patch 和 Vue commit 仍在主线程。
- `MessageList.vue` 对消息整行使用 `content-visibility: auto`，共享实际滚动视口的阅读范围；完成且已获得自身尺寸的屏外富文本会释放显示树，沿用实测高度、AST 和视图快照。尚无有效测量和持有自有状态的内容继续挂载。
- renderer 内部块级 `content-visibility` CSS 保持注释状态。更细的长消息挂载需要高度缓存和滚动锚点。
- 原有代码块逻辑提前 600px 初始化 CodeMirror，完成后一直保留。单个 4,000 行代码块只有一个编辑器；1,248 个短代码块的全篇滚动则会让编辑器从 5 个增长到 1,248 个，回到顶部仍保留。主线程 GC 堆约 112 → 142 MiB，卸载后约 48.7 MiB。
- 短代码块外围约 37 个元素、6 个按钮。固定围栏样本约有 10.1 万 DOM 和 1.5 万监听器；CodeMirror 之外的工具栏和组件数量同样需要处理。

### 当前轮实施边界

代码查看器离开 600px 预加载区后等待 2 秒，再将完成态编辑器回退到轻量源码；保留当前高度和标量 UI 状态。获得焦点或参与文本选区的编辑器保持可用，进行中的输出继续更新。KeepAlive 停用时释放编辑器，重新激活或滚回时由当前内容重建；延迟语言加载只作用于发起请求的那一代视图。显示 CodeMirror 时卸载隐藏的 `PreCodeNode`，减少重复全文和行号 DOM。

## 6. 后续路线与复现入口

### 计算管线

稳定区扫描仍需块级源码锚点、尾块回看和全局引用上下文。此前直接拼接稳定前缀的原型遇到尾部换行归属随输入变化的问题。保留单树 AST diff，避免拆容器导致长列表或引用视觉断裂。解析背压先量化预处理、边界扫描和 patch 调度，再决定频率；聚合文本应减少重复读取和中间数组，留意大列表上的缓存额外成本。图片列表的全 AST 扫描可另评估 patch 驱动。

### 重型节点

Mermaid 关注 pending 阶段频率、最后成功 SVG 与 stable 终渲染；HTML 关注 stable 后挂载、CDN 本地化缓存和沙箱生命周期；KaTeX 关注内容 / displayMode 缓存，当前固定采样的 149 个组件在流式中无重复更新。长代码流的 append-only 插入与编辑器回收分别对照。节点级异步就绪需与 AST 完成分开计时。

### 正式入口

- 规范、固定语料和细节记录：[markdown-conformance-and-performance.md](markdown-conformance-and-performance.md)。
- 计算计时 / CPU：`bun run rich-text:bench`、`bun run rich-text:profile`。
- 真实组件时延 / 内存：`bun run rich-text:performance:tauri`、`bun run rich-text:memory:tauri`；固定代码全篇滚动加 `--scroll --filter '^code:'`。
- 完整聊天和外观配置：`bun run perf:memory`，参数与采样定义见 [应用内存矩阵](../../../../../docs/Plan/app-memory-workload-matrix.md)。
- 回收定位：`bun run rich-text:heap:compare`，组件弱引用、Worker 和原生进程分别核查。
