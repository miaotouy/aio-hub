# 天气工具接入调查与候选方案

> 状态：候选，接口调查完成，产品实现待启动。
>
> 最近修订：2026-10-27（北京时间）

## 1. 首期范围

桌面端增加独立“天气”工具，路由 `/weather`，使用 UAPI 作为首个数据源。交付常用城市、当前天气、多日预报、按需加载的逐小时趋势，以及可选 UAPI Key 设置。

保留轻量转换函数，页面读取工具自己的展示数据。多供应商差异留作附录参考；后续接入第二家时再扩展当前模型。

首页摘要、分钟降水、生活指数、移动端、Agent 方法和自动刷新安排在后续阶段。首期通过手动刷新与本地缓存控制调用量。

- [常见问题：额度、鉴权、扣费与错误](https://uapis.cn/docs/api-reference/faq)
- [积分与资源包](https://uapis.cn/pricing)

- [使用条款与来源标注](https://uapis.cn/docs/getting-started/privacy-policy)

天气文档标题宣称完全免费，参数区标记高级参数为 Pro，价格页显示 2 积分/次。本次高级参数均可免 Key 调用，实际请求会消耗积分。产品说明使用“支持免 Key 查询”，同时展示额度耗尽时的可行动提示。

客户端从用户本机直连 UAPI，页面注明“数据来源：UAPI”。

### 2.2 已执行的请求

2026-10-27 使用 curl 直接执行 7 次天气请求，未携带 Authorization、API Key 或持久化 Cookie。

| 场景                                                    | 结果                                                                                 |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 北京基础查询                                            | HTTP 200，返回天气、图标代码、温度、湿度、风向风力和发布时间描述                     |
| 上海 `adcode=310000`，五项扩展开关全开                  | HTTP 200，7 天预报、24 条小时预报、120 条两分钟间隔降水数据、18 项生活指数及扩展字段 |
| 主人提供的北京完整示例，含空 `adcode` 与全部 false 开关 | HTTP 200，与基础返回结构一致                                                         |
| Tokyo，扩展字段与日预报、英文                           | HTTP 200，3 天预报；缺少 `adcode` 和部分国内扩展字段                                 |
| 明显无效的城市名称                                      | HTTP 400，`code=INVALID_PARAMETER`，附可读错误消息                                   |
| 城市与行政编码都省略                                    | HTTP 200，按请求出口 IP 定位；此次返回广东惠州惠城区                                 |
| 北京日预报，附 `Origin: http://tauri.localhost`         | HTTP 200，7 天预报，返回匹配 Origin 的 CORS 允许头                                   |

IP 定位结果只说明此次请求出口被识别为该地区，用户实际位置可由手动城市选择修正。CORS 记录供浏览器场景参考，桌面接入沿用 Tauri HTTP 插件。

### 2.3 额度与扣费

2026-10-27 查阅官方 FAQ 后补齐：

- 游客每月 1500 积分，按网络出口 IP 计算，同一局域网或共用出口的用户可能共享额度；每月 1 日 0 点重置。登录用户按账号计量，每月免费额度为 3500 积分。
- 天气标价 2 积分/次。实测未命中缓存扣 2，命中缓存扣 1，并返回 `UAPI-Credits-Pricing: cache-hit-half-price`；以 `UAPI-Credits-Charged` 为实际扣费依据。
- 无效城市实测扣费 0，仍消耗请求频率额度。实测响应头包含 IP 每日请求数、瞬时速率与积分额度等多项策略，运行时读取限流头。
- 游客月额度耗尽通常为 HTTP 429、`VISITOR_MONTHLY_QUOTA_EXHAUSTED`；短时限流也可返回 429，需结合业务错误码区分。
- 账号额度及余额不足通常为 HTTP 402、`INSUFFICIENT_CREDITS`。账户可设置资源包和余额扣费；填入 Key 后按账户设置结算。
- 按每次 2 积分计算，1500 积分约支持 750 次天气查询。首期采用手动刷新和 30 分钟缓存。

## 3. 页面与交互设计

### 3.1 整体工作区布局与响应式策略

遵循桌面端软件交互准则，打开工具即展示**完整工作区框架**（左侧常用城市栏 + 右侧顶部工具栏 + 右侧主内容看板 + 底部来源与状态栏），不采用“先输入才出现界面”的引导式空页面。

```text
+----------------------------------------------------------------------------------------+
|  Weather.vue (主工作区，双栏弹性布局)                                                  |
|  +----------------------+  +--------------------------------------------------------+  |
|  | CitySidebar (240px)  |  | WeatherToolbar (搜索输入 / IP定位 / 时间 / 刷新 / 设置)|  |
|  | ------------------   |  +--------------------------------------------------------+  |
|  | 常用城市      [+收藏]|  | 状态告警条 (仅在有缓存但刷新失败/限流时内联展示)       |  |
|  |                      |  +--------------------------------------------------------+  |
|  | :: 北京       24°C   |  | CurrentWeatherCard (实时天气主卡)                      |  |
|  | :: 上海       21°C   |  | +-----------------------+ +-----------------------+    |  |
|  | :: 东京       18°C   |  | | 北京市            [★] | | 湿度 45% | 东北风 2级 |    |  |
|  |                      |  | | 24°C  多云 (↑26° ↓15°)| | 体感 23° | 空气 优    |    |  |
|  | [热门城市快捷入口]   |  | +-----------------------+ +-----------------------+    |  |
|  |                      |  +--------------------------------------------------------+  |
|  |                      |  | HourlyTrendPanel (按需展开 24 小时趋势，横向卡片+折线) |  |
|  |                      |  +--------------------------------------------------------+  |
|  |                      |  | DailyForecastCard (多日预报列表 + 归一化温差区间条)    |  |
|  |                      |  +--------------------------------------------------------+  |
|  |                      |  | 页脚：数据来源 UAPI · 本地获取时间与发布时间说明       |  |
|  +----------------------+  +--------------------------------------------------------+  |
+----------------------------------------------------------------------------------------+
```

- **断点依据**：以天气工具工作区的可用容器宽度为准，使用容器查询适配主窗口侧栏和独立窗口。
- **宽屏模式（工作区宽度 `>= 860px`）**：左侧固定 `240px` 常用城市侧栏，右侧自适应主看板；实时天气主卡内部采用左右双区排布（左侧核心温况，右侧 2×2 指标网格）。
- **窄幅模式（工作区宽度 `< 860px`）**：左侧城市栏自动收拢为工具栏中的紧凑城市下拉选择器（保留切换与收藏能力），实时天气主卡内部切换为上下堆叠。工具栏允许分行：城市切换、查询输入与查询按钮优先排列，IP 定位、刷新、时间与设置在空间不足时换至下一行；输入框允许收缩，避免整个工作区产生横向滚动。

### 3.2 核心区域交互细节

#### 1. 左侧常用城市面板 (`CitySidebar.vue`)

- **头部区**：标题“常用城市”、数量 Badge，以及“收藏当前城市”快捷按钮（当右侧正在查看的城市尚未加入列表时高亮可用）。
- **列表项与语义装饰**：
  - 遵循容器语义装饰规范：普通项使用 `1px` 结构边框与 `var(--card-bg)`；选中项采用固定宽度的 `border-left: 2px solid var(--el-color-primary)`（默认 `2px solid transparent`，切换时只改颜色避免重排）配合 `rgba(var(--el-color-primary-rgb), calc(var(--card-opacity) * 0.12))` 浅色背景。
  - 每项展示：左侧专用拖拽柄（`.city-grip`）、城市显示名、可选地区副标签（与城市名相同时省略，行政编码放在 Tooltip）；若本地缓存中存在该城市未过期的天气数据，右侧顺带显示缓存温度快照（如 `24°`）；鼠标悬停时显示移除按钮（`X`）。
- **拖拽排序**：复用 `VueDraggableNext`，配置 `handle=".city-grip"`、`:force-fallback="true"`、`:fallback-on-body="true"` 与 `:animation="150"`；拖拽柄设置 `cursor: grab; touch-action: none; user-select: none;`，兼容 Tauri WebView2。
- **空列表态**：当常用城市为空时，展示轻量级内联说明“暂无常用城市，查询后可点击星标保存”，并在下方提供预设热门城市芯片（`北京`、`上海`、`广州`、`深圳`、`杭州`、`成都`），点击即可直接触发查询。

#### 2. 顶部查询与控制工具栏 (`WeatherToolbar.vue`)

- **查询输入组**：
  - 单行搜索框（支持输入中英文城市名称或 6 位 `adcode` 行政编码，带一键清空）。手动查询只从本次输入生成目标参数：去除首尾空白后，纯 6 位数字按 `adcode` 提交，其余非空内容按 `city` 提交。空输入提示填写城市或使用 IP 定位按钮。点击常用城市或刷新当前城市时复用该城市保存的位置参数，有行政编码时优先使用编码。
  - 显式“查询”主按钮（支持点击或单行输入框回车触发）。
  - “IP 定位”按钮（配 `LocateFixed` 图标，Tooltip 明确提示：“按当前网络出口 IP 自动判断所在地区，开启代理时可能定位至代理出口”）。
- **状态与全局操作组**：
  - **时间与缓存胶囊**：展示 `更新于 HH:mm`（本地获取时间），悬停 Tooltip 展示来源原始 `report_time` 描述；若当前结果命中本地 30 分钟缓存，展示轻量级 `缓存` 标签。
  - **刷新按钮**：配 `RefreshCw` 图标，点击强制跳过本地缓存重新请求；请求进行中图标旋转并禁用重复点击。
  - **设置按钮**：配 `Settings` 图标，并附带 `6px` 状态圆点（已配置 UAPI Key 时显示主色圆点代表“账号模式”，未配置时显示中性圆点代表“游客模式”）。

#### 3. 实时天气主卡 (`CurrentWeatherCard.vue`)

- **核心温况区（左）**：
  - 城市主标题 + 可选地区副标签（与城市名相同时省略，行政编码放在 Tooltip）+ 收藏星标切换按钮（`Star` 图标，已收藏时填充高亮，点击可快速加入或移出常用城市）。
  - 温度主读数（`48px`、字重 `700`、等宽数字 `font-variant-numeric: tabular-nums`）+ 动态映射的天气现象大图标 + 天气描述文本。
  - 当日高低温区间（提取自日预报首日数据，展示为 `最高 26° · 最低 15°`；若日预报缺失则自动隐藏该行）。
- **气象指标网格（右，2×2 自适应 Grid）**：
  - 每个指标格采用 `1px` 边框、图标 + 指标名 + 数值的紧凑布局：
    1. **相对湿度**：`Droplets` 图标 + `humidity`（如 `45%`）。
    2. **风向风力**：`Wind` 图标 + `wind_direction` 与 `wind_power`（如 `东北风 · 2级`）。
    3. **体感温度**：`Thermometer` 图标 + `feels_like`（如 `23°C`；来源未返回时显示 `--`）。
    4. **空气质量**：`Leaf` 图标 + 来源返回的空气质量分类标签（仅当来源提供明确分类文案时展示对应文字与状态点；若如国际城市仅返回未知标准的裸数值 `aqi=2`，按数据规则直接隐藏该格或显示 `--`，不自行着色分级）。

#### 4. 按需逐小时趋势面板 (`HourlyTrendPanel.vue`)

- **按需加载机制**：
  - 面板头部常驻展示标题“24 小时趋势”与展开/收起切换按钮。
  - 展开时：若当前城市的 `hourly` 模块缓存距该模块成功获取未满 30 分钟，直接渲染；若尚未加载或已经过期，则由 Store 发起带 `hourly=true` 的请求，并在面板内部就近展示加载指示。存在旧小时数据时保留趋势并标注其获取时间，加载反馈保持局部展示。当前天气和日预报继续可见。
- **趋势可视化**：
  - 采用**横向滚动时间轴 + 内联 SVG 轻量温度折线**组合，按实际返回的数组长度渲染（无需引入重型 ECharts 实例）：
  - 上层为内联 SVG 绘制的平滑温度曲线与极值圆点（使用 `var(--el-color-primary)` 描边与透明渐变填充）；
  - 下层为对齐的横向小时列（每列展示：来源时间文本如 `14:00`、天气小图标、温度值 `24°`、天气短描述），支持鼠标滚轮或拖拽横向浏览。
- **局部失败态**：若按需加载小时数据失败，仅在该面板内展示错误原因与“重试”按钮；已有小时数据继续显示并保留原获取时间，主卡片数据保持完好。

#### 5. 多日预报面板 (`DailyForecastCard.vue`)

- **动态天数适配**：面板右上角标注实际返回天数（如国内城市显示 `未来 7 天`，东京等国际城市显示 `未来 3 天`），严格按返回数组长度渲染行项。
- **列表项与归一化温差条**：
  - 每行采用对齐结构：`日期与星期（今日/明日/周X）` | `天气图标 + 天气描述` | `最低温` | `可视化温度区间条` | `最高温`。
  - **温度区间条（Temperature Range Bar）**：仅使用有效温度数值计算当前多日预报的全局最低温 $T_{\min}$ 与全局最高温 $T_{\max}$，将端点齐全且顺序有效的当日 $[t_{\text{low}}, t_{\text{high}}]$ 映射为轨道内的相对偏移 `left%` 与宽度 `width%`。区间条采用随主题自适应的柔和冷暖色带，直观呈现整周冷暖起伏。
  - 全局温差为 0 时，在轨道中心显示温度点；全局温差大于 0、当日高低温相同时，在对应位置显示温度点。
  - 任一端点缺失或高低温倒置时，该行省略区间条，已有有效温度照常显示，缺失值显示 `--`；全局无有效温度时，各行均省略区间条。数值 0 按有效温度处理。

### 3.3 状态矩阵与错误降级体验

所有状态下均保持左栏与顶部工具栏可操作，严禁整页白屏或弹窗轰炸：

| 状态场景                   | 界面表现与可操作性                                                                                                                                                                                 |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. 首次未选城市空状态**  | 完整展示左栏、工具栏与右侧卡片容器骨架；主内容区展示内联引导卡，提供“按出口 IP 定位天气”主按钮及热门城市快捷按钮组（北京 / 上海 / 广州 / 深圳），一键点击即完成首次查询。                          |
| **2. 首次查询加载态**      | 目标城市尚无任何本地缓存时，右侧主卡与多日预报区域展示等高微光占位块（Skeleton），工具栏查询按钮处于 loading；切换城市或修改配置时若中止旧请求，立即切换至新请求状态。                             |
| **3. 含缓存的刷新/错误态** | 若目标城市已有上次成功的缓存数据，刷新期间保留现有天气卡片不闪烁；若请求失败，**继续完整展示上次成功天气与获取时间**，仅在工具栏下方插入一条非阻塞告警横幅，说明失败原因并提供“重试”或“设置”按钮。 |
| **4. 无缓存的首次失败态**  | 目标城市无可用缓存且请求失败时，右侧展示结构化错误卡，按错误码给出明确行动入口（见下表）。                                                                                                         |

**错误码与可行动反馈映射：**

- **参数错误（`400 INVALID_PARAMETER`）**：提示“未能识别该城市名称或行政编码，请检查拼写后重试”，附“聚焦搜索框”按钮。
- **凭据无效（`401 UNAUTHORIZED`）**：提示“UAPI Key 鉴权失败，已保留您填写的 Key，请检查是否正确”，附“打开设置修改”按钮。
- **游客月度额度耗尽（`429 VISITOR_MONTHLY_QUOTA_EXHAUSTED`）**：提示“当前网络出口的游客免 Key 月度额度（1500 积分）已耗尽”，附“配置个人 UAPI Key”与“了解额度规则”入口。
- **短时速率限制（`429` 其他限流码）**：读取并展示 `Retry-After` 建议等待秒数，提供倒计时结束后的“重试”按钮。
- **账户积分不足（`402 INSUFFICIENT_CREDITS`）**：提示“当前 UAPI 账号积分或资源包余额不足”，附“前往 UAPI 控制台”与“打开设置（可清除 Key 切回游客模式）”入口。

### 3.4 可选 UAPI Key 设置弹窗 (`WeatherSettingsDialog.vue`)

使用项目自主实现的 `BaseDialog` 组件（配置 `width="520px"`、`show-close-button`、`close-on-backdrop-click`，不传 `el-dialog` 专有属性）：

- **模式状态摘要卡**：顶部以带状态点的信息块展示当前所处模式：
  - 未配置 Key：**游客免 Key 模式**（共享出口 IP 免费额度 1500 积分/月，天气查询 2 积分/次，命中服务端缓存 1 积分/次）。
  - 已配置 Key：**账号凭证模式**（使用个人账号 3500 免费积分/月，超出后可能按账户设置消耗资源包或余额）。
- **凭据表单区**：
  - `uapiApiKey` 密码遮罩输入框（`type="password" show-password`），容器标记 `data-dev-sensitive` 以支持截图自动遮罩。
  - 操作按钮：保存、一键清除（切回游客模式）以及“打开 UAPI 控制台”链接按钮。
- **安全与边界说明**：
  - 仅在配置非空 Key 时向固定 UAPI HTTPS 地址发送 `Authorization: Bearer <key>`。
  - 普通偏好与天气缓存由 `createConfigManager` 保存；Key 使用现有 `createObfuscatedStore` 单独保存到天气目录，复用通用存储原语，避免挂到 LLM Profile。
  - 界面文案明确说明“凭据经混淆保存在本机应用目录”，不宣称系统钥匙串或硬件级强加密；Key 从日志、诊断导出及公共状态同步载荷中严格排除。
  - Key 的新增、变更和清除会使当前窗口进行中的旧凭据请求立即失效；已有可用天气缓存继续保留。尚未使用真实 Key 实测账户请求。

### 3.5 图标映射与主题视觉规范

- **工具图标**：注册文件使用 `markRaw` 包裹的天气图标组件（优先在 `@aiohub/tool-icons` 中按 24×24 线性规范新增 `WeatherIcon` 或使用 `CloudSun`）。
- **天气现象图标映射**：建立轻量级纯函数映射表，将 UAPI 返回的 `weather_icon` 代码与常见天气关键字归类映射到 `lucide-vue-next` 图标（如 `Sun`、`CloudSun`、`Cloud`、`CloudRain`、`CloudDrizzle`、`CloudLightning`、`Snowflake`、`CloudFog`、`Wind`），未知代码平滑回退至通用 `CloudSun` 图标，天气文字始终保留来源原文。
- **主题与毛玻璃适配**：
  - 所有卡片与面板统一使用 `background-color: var(--card-bg); backdrop-filter: blur(var(--ui-blur)); border: var(--border-width) solid var(--border-color);`。
  - 选中态、告警横幅与状态标签背景统一使用 `rgba(var(--el-color-*-rgb), calc(var(--card-opacity) * 0.12))`，严禁硬编码 Hex 颜色或直接使用 Element Plus 的 `--el-color-*-light-9` 实色变量。
- **数据来源标注**：工作区底部常驻轻量级说明栏，展示“数据来源：UAPI · 支持免 Key 查询”，符合接口来源标注规范。

Provider 保持无状态，缓存和请求合并只存在于 Store。当前无需另设 `weatherService.ts`。

Store 在每个 WebView 内各有实例，Pinia 单例的范围为当前窗口。独立窗口复用项目的 `useStateSyncEngine` / `WindowSyncBus` 同步常用城市和最新成功结果，按位置与各模块的获取时间合并，接收更新时避免再次请求或回写广播。Key 由各窗口从专用存储加载，在使用或修改凭据时更新；公共天气状态只携带天气与偏好。

首期仅合并当前窗口的相同进行中请求。跨窗口状态同步用于复用已完成结果，跨窗口进行中请求的全局合并留待真实使用需求。手动查询模式无需新增后台刷新协调器。

### 4.2 请求与缓存

- 默认请求 `extended=true&forecast=true&lang=zh`；小时面板展开时再增加 `hourly=true`。可将成功小时响应中的当前天气和日预报一并更新。
- 查询目标由本次操作确定：手动查询使用本次输入，常用城市切换与刷新使用目标城市保存的位置参数，IP 定位省略城市和行政编码。确定目标后，有行政编码时优先使用编码，其余空参数省略。国内常用城市可保存返回 `adcode`；国际城市允许仅保留名称及地区信息。
- 缓存按位置、语言和已加载模块保存，各模块记录自身成功获取时间。仅复用所需模块在 30 分钟有效期内的结果；响应只更新实际返回模块的数据与获取时间。持久化恢复和跨窗口同步沿用原模块时间；当前天气或日预报更新时，已有小时数据保留自身获取时间。刷新按钮显式重新请求。
- 普通常用城市配置与小体积天气缓存持久化；进行中的 Promise、AbortController、loading/error 只留在内存。
- 切换城市、切换凭据或退出页面时中止相关请求，提交结果前再核对请求标识；旧请求的响应和 finally 块均只更新自身状态。
- 首期错误保留状态码、业务错误码、可读消息及可用的 `Retry-After`，兼容 UAPI 的 `code/message` 与 `error/message` 返回。
- 参数错误提示修改城市；401 提示检查 Key；短时 429 展示可重试时间；月额度耗尽提示等待重置或配置 Key；402 提示检查账户额度。其余网络或服务错误保留缓存供手动重试。

### 4.3 首期数据与转换

`types.ts` 只定义当前组件实际使用的数据：

- 城市显示名、可选行政编码。
- 当前天气描述、来源图标代码、温度、体感温度、湿度、风向风力、可用空气质量标签。
- 日预报对象数组：日期、高低温、天气描述。
- 可选小时数组：来源时间文本、温度、天气描述。
- 本地获取时间、来源发布时间描述、已加载模块及各模块成功获取时间。

Provider 输出统一命名的展示字段，UAPI 原始字段与 DTO 留在 Provider 中。当前按 UAPI 已核实单位转换与展示；第二家接入后再添加单位换算及供应商识别字段。

保留直接影响本期展示正确性的规则：

1. 空值保持缺失，0 按有效值处理；数值接受有效小数，字符串数字经校验后使用。
2. 实测图标字段为 `weather_icon`；未知代码使用通用天气图标，描述保留原文。
3. `report_time` 可能为相对描述，直接展示来源文本；另显示本地获取时间。小时时间缺少时区时按来源文本展示。
4. 日预报高低温从日预报记录提取；小时与日数组按实际长度展示。
5. UAPI 国际裸 `aqi=2` 的标准尚未确认。优先展示来源返回的空气质量分类；只给裸数值时收起该指标，避免自行着色分级。
6. 日、小时数据使用可选数组；请求失败与加载反馈由相应 Store action 维护。首期无需通用模块状态包装器。

日志、错误处理、操作反馈、主题、持久化路径和图标沿用项目现有规范。新增工具采用动态页面导入，并在 `src/config/tools.ts` 设置合适顺序。
